`assertPhysicalProducerEvidence` receives `{config, terminal, admission, results, artifactAudit, inputManifest, observed}`. It performs no filesystem access, imports no domain owner, and opens no SQLite database. The eventual caller reads and hashes explicitly bound evidence files before invoking it, then retains the same-connection closed-end owner check inside the official helper.

The run-v2 configuration requires a `physicalProducer` object for real execution. Import-only configuration remains valid without it. Its `kind` is `first_base_clean_producer_v1`; required pins are producer Source commit, Source-manifest SHA-256 and file count, original-input path/SHA-256, runtime SHA-256, the exact four launcher-control hashes keyed by filename, the three published negative-proof hashes keyed by filename, and the published original-input manifest SHA-256. Missing fields never mean compatibility fallback. Producer Source and all file locations are supplied explicitly; no current workspace path is an authority or default.

The observed bundle holds independently calculated input/output/receipt hashes, before/after Source-manifest hashes and file count, runtime and copied-control hashes, published negative-proof hashes, original-manifest hash, and current input/output WAL lengths. An absent WAL is represented explicitly by null; an unknown/omitted WAL field is rejected.

`physicalProducer.files` supplies explicit `{path, sha256}` references for `admission`, `results`, `artifactAudit`, `inputManifest`, `sourceBeforeManifest`, `sourceAfterManifest`, `runtime` and `originalInput`; `controls` and `negativeEvidence` contain filename-keyed maps of the same references. These 15 sidecars plus the existing terminal and output references must have distinct absolute paths. Required filenames are exact; none are discovered or guessed beside the report. JSON is hashed and decoded from the same bytes. Binary/control/reference files are hashed without opening SQLite. Manifest parsing rejects duplicate paths. The selected terminal is read first, and a pending or publication-only receipt is rejected before any physical artifact access. The complete bundle then passes the pure semantic validator before helper import or execution.

Success requires exact boolean/number types: gatePassed true; childExitCode zero; stopReason null; every source/runtime/control/input/negative-evidence unchanged flag true; matching admitted Source and every pinned/observed hash; two total and two passed tests, none failed/pending/skipped; both named assertions actually passed; actual worker receipts with Node 26.10.0 and 1120 MiB heap; no remaining worker; artifact audit exit zero; exact output path/hash and absent/empty WAL. The audited artifact must contain the requested physical end and one seal, and preserve the original table census/counts/logical hashes.

This bounded producer profile accepts only original input `a54678e3aae1c6df0d25683b65c2811cedfed98539ca604aa233563f9eee7caa` and the exact three published `first-base-negative-phase-31c29` references used by the frozen clean launcher. These are immutable fixture lineage restrictions, not filesystem defaults. The previous interrupted negative receipt remains a negative-phase proof, never a clean-success receipt. The watcher’s `committed-end-pending-final-proof` receipt/backup cannot satisfy successful terminal admission.

The successful terminal/admission/results/audit bundle must be the raw authenticated producer evidence. A sanitized publication projection is a separate review artifact and cannot replace it, even if it carries success-like fields and its own matching file hash. All four raw JSON objects reject top-level `kind`, `schema`, `publicationProjection` and `originalRawReceiptSha256` identities; the frozen launcher, Vitest 2 and SQLite audit raw formats have none of these fields. The check does not inspect nested Vitest metadata or SQLite Source values. The published input manifest and the three explicitly hash-pinned negative-phase publication files remain allowed only in their separate supporting-proof roles; the previous interruption is never treated as a complete producer pass.

Pure tests use JSON-only synthetic receipt objects, including relocated paths. They never construct a physical end or claim an artifact gate pass. The initial RED extraction preserves healthy hash behavior so semantic rejection cases fail specifically because the existing admission checks only matching bytes.
