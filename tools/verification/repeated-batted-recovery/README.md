# Held fresh closed-input continuation

This distinct test-control route restores prerequisites for the existing
repeated-batted task. It changes no production code or game behavior and leaves
the raw-producer pipeline entrypoint and byte-exact recovered contract intact.
Its only available origin is the published known-profile-ended snapshot.

The new explicit input manifest must pin that disk, its publication projection,
this current Source/control cut, registered profile and accepted original model
Sources. It declares the existing helpers' fixture policy, ten effort values and
baseline recipe, away-2 and the explicit TAKE input. No lost receipt is inherited.

The supervisor is held until separate source/control review, dependency binding
and coordinator runtime release. It requires an independently supplied config
hash and an explicit release flag. Phases run serially:

1. Focused compiler, without npm lifecycle/catalog execution
2. Raw immutable read-only schema, initial Match/World/pitch/end/seal, zero
   downstream work, exact active-ten Player/Person/model/primitive admission
3. Current-source Native persisted-end/history/field reauthentication
4. Existing official helper, with both real INSERT faults and close/reopen/retry
5. Existing original-ten-role helper, with all five fault obligations and frozen
   AFTER heads; its recovery regression stays on a separate copy
6. Existing next-actor helper, with both faults, new away-2 TAKE from the real
   current workload/frame and all-close/reopen/readback

`--phase compiler|raw|reauthenticate|official|role|next` runs exactly one complete
phase and releases its locks afterward. Every phase after compiler requires
`--preceding-terminal-sha256` from the independently captured preceding verified
checkpoint. That checkpoint pins its proof receipt; the consumer verifies the
receipt pin again before use. Checkpoints live in the declared private flow,
while each invocation gets a separate controls/log directory. No production
transaction is split. Other bounded gates may run between these whole phases.
Pinned checkpoint/proof JSON is hashed and parsed from one captured byte buffer.
The externally supplied terminal hash is retained through consumption, checked
after the phase, recorded in the phase receipt and rechecked at final chain
qualification. Internally produced checkpoint pins come from their written byte
buffers, and every checkpoint records/verifies its preceding terminal pin.
`--phase all` is an optional serial fresh-flow invocation. Full continuation
qualification requires every phase and closed output on the same Source,
configuration, input and dependency pins. A successful single invocation has
`invocationVerified:true`; it cannot alone establish freshContinuationVerified.

The exact reviewed process helper is copied unchanged, SHA-256
`17c73eb414b32f9f1616b5e4e58ac1077a0449dd5b6887c0291369b73ce9ca9f`.
Each Popen owns its generation ledger; its root identity is registered before
polling, every signal uses a freshly generation-checked pidfd, and all descendants
are reaped. New attempts preserve failed attempts; no automatic retry occurs.

Every phase has finite wall/RSS/reserve limits. The supervisor pins complete
Source and dependency snapshots, controller/config/input/control bytes, actual
Node version/heap and before/after closed input hash. Vite caches and logs stay
in the new private attempt directory. Only fully observed, exited, reaped,
unchanged phases allow progression. The final terminal denies historical raw
admission, original construction/seal rollback, elapsed world recovery, geometry
RED and whole-pipeline proof.

This is prepared source, not a tested launcher or a passing continuation. No
runtime, SQLite connection or shared lock has been started during preparation.
The current worktree still needs its reviewed dependency snapshot bound before
launch. Heavy Native phases use the existing 14,400-second ceiling; a resource
stop is an incomplete stage, not success or intended RED.

Fresh continuation success would produce new official/role/next receipts and a
new pinned TAKE artifact. The original repeated-batted preflight/copy helper
still hardcodes lost historical NEXT pins; use a separately reviewed test-input
adaptation before consuming this fresh lineage. Preserve its physics, model,
calibration, Source ownership, TAKE prefix and intended RED definitions.
