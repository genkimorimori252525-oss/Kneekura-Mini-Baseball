# Received umpire defender replan: pure Core API

`deriveReceivedUmpireDefenderReplan` is a deterministic, renderer-neutral decision adapter for an original defender with an adopted incumbent command. Inputs are internally rederived owner/dependency data. A Native caller must authenticate source identities and hashes, the current physical/observation cut, monotonic process progress, and the previous receipt. This pure API provides no persistence, physical execution or Native authentication proof.

The original received call, observation, incumbent command/motor, model and contextual plan form an immutable evidence capsule. Current observations can advance the process while candidate selection continues to use that original perception. The policy has explicit OUT/SAFE pursuit and hold priorities; a missing active branch remains pending. A missing owner may be bound once when genuinely available. Bound model, plan, policy and incumbent data cannot be replaced on the same cause.

Reception is compared with the predecessor's original information cut using exact elapsed time. Latest initial-decision observation hashes and issuance times are separate progress metadata. Equal exact moments need an authenticated sequence from the same sequence owner. Without that order the result remains pending. After exact eligibility is established, an exact comparison finds the first integer boundary at or after observation availability, then the existing replan, awareness and first-step kernels supply timing.

Existing local candidates remain competitors. The active call profile adds pursuit/hold priorities weighted once by received confidence and original communication trust, subject to the original confidence gate and observed-ball eligibility. The existing chooser decides. An unsupported winning intent retains its trace and leaves `intent_adapter_unavailable`; there is no fallback command. OUT and SAFE have no hard-coded motion interpretation.

A proposal is not a committed decision. `selectedAt` records only the exact owned cognition boundary. Missing semantics leaves source-specific due decision work. A later profile or a skipped exact commitment cannot backdate selection or restart its deadline. After a valid decision, every reached first-step cut retains `renewal_due` and the original adoption due tick. Native owns actual integer-start eligibility, continuous incumbent authority and lawful due-work admission; the pure receipt does not certify a later cut as physically executable. The incumbent command remains retained while renewal is pending. This adapter never adopts a body trajectory or certifies event consumption or PlayEnd.

The public policy Source validator and Native replan/renewal owners are separate integration work. This module validates its explicit internal policy data but does not accept external Source assertions as authority.
