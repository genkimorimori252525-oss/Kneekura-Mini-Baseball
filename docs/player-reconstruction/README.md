# 選手再現部 — Historical Player Reconstruction Department

> **創設:** 2026-10-16（ユーザー提案）
>
> **状態:** DOCUMENTATION / QA DEPARTMENT ESTABLISHED。OB能力固定・複数年の全盛期データからの再構成・突出年も届き得るが毎年保証されない、という**明示されたユーザー方針**を長期保存。詳しい推計係数・年代補正・Season Expressionは**DESIGN PROPOSAL / NOT IMPLEMENTED / NOT CALIBRATED**。
>
> **対象:** Kneekura Mini Baseball（将来のNatural Baseballも同じ正史Core）。実在OB・歴史的選手、将来は現役選手の時点別再現。これは新しい試合エンジンでも、キャリア開発コードの別実装でもない。

## 最優先の実装方針（後続修正）— OOTPは起動せず、Miniだけで王貞治

**ユーザーがOOTP起動を不要と明示。** [Mini独立王Pilot](OOTP-FIRST-OH-PILOT-PLAN.md)では、公開されたOOTP歴史DBを**研究資料**として使うが、OOTP本体・Editor・再計算を一切起動しない。`.odb`は主に史実記録を含み、OOTPゲーム内で後から生成される選手Ratingが本人別に既に入っているとは確認されていない。そこで史実の王と[1972–76同時期のリーグ相対基準](cases/sadaharu-oh-1972-1976-league-reference.json)を計算し、Mini独自の真の技能Sourceで再現する。[独立した計算器](../../tools/player-reconstruction/compute-oh-mini-benchmark.mjs)を用意済み。

**新しい全員分の査定やOOTP能力値の抽出を先に要求しない。** 王のNative実打席へつなぐことを優先し、成立したらユーザーが指定した人物のみ同じSeed方式を使う。既存のより進んだNativeブランチに接続して、別の公式試合エンジンを作らない。Miniゲーム本体の実装・試験は未完了。


## この部署の目的

「有名選手にSや金特を大量につける」のではなく、**本人の歴史的プレーを生み出せる因果的な能力・判断・身体技術を、出典と不確実性を持って復元する**。選手をペナントに投入しても、全盛期到達の可能性・通常年の水準・シーズン差・他選手との相対関係を損なわない。見た目の☆/0–100/G–Sは内部原因の要約にすぎない。

6. [史実データからの再現手順・QAゲート](METHOD-V1-PROPOSAL.md) — 年度別PA/AB集計、校正、4つの軽量チェック（毎人厳格な全項目監査は不要）。

- [NPB公式年度URL探索索引](sources/npb-official-season-index.json) — **171キー**：完了歴史年度168件、2026 as-of 2件、1945公式リーグなし1件。URLの大半はパターン推定で**アクセス未検証**。選手成績は含まない。
- [史実ソース台帳・権利/品質区分](sources/npb-evidence-source-registry.json) — **19件**。大量インポートや素材コピーが許されたという意味ではない。
- [参照マニフェスト構造検証ツール](../../tools/player-reconstruction/validate-npb-source-manifests.mjs) — ローカルで `node tools/player-reconstruction/validate-npb-source-manifests.mjs`。オフライン整合性チェックのみで史実の正確性や利用許諾は検証しない。
- [再現ケース用の型付JSON Schema](schemas/reconstruction-case.schema.json) — 正本技能Source・公式記録・公開Rating・Trait（青/金/赤/緑/青赤/Neutral）・QA証拠・利用権限を分離した**研究用**型提案。人物Save/Match Core正式契約ではない。

**重要:** 戦前〜現代の「公式一軍選手の存在・年次成績」は広く調査できるが、1936〜現代までの球種/球速/回転/打球速度/選球思考などの真値がすべて実測されているわけではない。各選手の非公開技能やTraitは証拠・推論・unknownを分離する。**二軍の全面再現は当面必須としない。**


### 最優先: 史実データを活用して再現を進める

**2026-10-16ユーザー修正:** 後楽園球場の1936年誤表記のような珍しい不整合のために、全球場/全年度・全ソースの機械的監査は不要。**既知のミスは一行注記して、必要な部分だけ補正し、そのまま先へ進む。** AIの労力は一軍史実環境・選手能力・ペナント再現へ投じる。選手一人ごとに大量のGate、複数サイト照合、全てのTraitの確認は課さない。基本のOB能力固定と、史実の最高成績が到達可能なことは維持。

## この部署が責任を持つもの

- **史実調査とEvidence**: 公式年度別データの出典・年・シーズン規則、未確認情報/不確実性の保持。
- **Prime Window**: 恣意的なベスト数年の摘み食いを避け、連続的な全盛期の観測窓を事前定義して記録する。
- **年またぎの基礎能力設定**: 実成績の単純コピーではなく、球道/スイング/選球/身体/守備など正史因果ソースを推定する。OBの基礎能力はペナント進行で変動させない。
- **成績の再現可能性**: 通常年の分布、悪い年の発生、史実に並ぶ好成績の到達可能性。最も良い記録を毎年強制せず、極端な年だけ合わせない。
- **適切な個性・Trait**: 強い引っ張り志向と引っ張り屋の技能は区別。広角打法は実技Evidenceなく自動付与しない。
- **検証**: 複数シード/複数年/リーグ条件で、生データの適合、ワンシーズンだけの過大評価、対戦条件の再現性、同一能力の固定を比較。
- **バージョン管理**: 選手テンプレ・歴史的時点・校正環境・データ版を記録。同じ人物に複数の時代プロファイルがあり得ても、ペナントの同一OBが毎年能力を書き換えることとは別。

## この部署が勝手に変更してはいけないもの

- Match Coreの投打/守備/判定物理を、OBの成績目標へ合わせて後から変更しない。
- 公開ミート/パワーの数字を直接Matchへ投入したり、HR/安打を結果抽選したりしない。
- 選手能力の「年ごと自動成長/加齢衰退」をOBの固定モードへ混入しない。
- 動的な所属リーグ相対Ratingと「OBカード能力値固定」の間にある表示仕様の未解決事項を黙って上書きしない（[PRINCIPLES](PRINCIPLES.md)）。
- 「カル・ローリーが歴史的に一発屋で確定した」等、キャリア判断を一つの突出年だけで確定しない。あくまで「単年突出ケース」の検証題材。
- 未承認のSeason Expression数式・数値係数をCANONICALに昇格させない。

## 引継ぎ・作業完了条件

選手ごとに**使用した主資料・年代・主要な設定・分かった誤りと補正内容**を簡潔に残せばよい。資料が揃わない細部は概算/不明のまま進め、実試合検証ができる段階で代表選手を確認する。未実施の検証をPASSと書かないが、資料不足だけで選手再現を止めない。
