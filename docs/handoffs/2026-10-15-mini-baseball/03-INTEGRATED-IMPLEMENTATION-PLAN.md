# 03. 全要求の統合実装計画：物理と野球規則を正史として一括検証

## 0. 製品の完成条件

TBDホーム対LADビジターを、承認済みPNG/B1画面のまま、正式Native Match Coreによって9回プレイできる。投球、打球、バウンド、転がり、9人守備、走者、捕球、送受球、判定、得点、選手成績、次打席、リプレイが**一つの因果的な正史イベント履歴**で説明できる。PCとAndroid/iPhoneスマホの単体オフライン実機で動作し、保存・再開しても一致する。Natural Baseballでは同じ世界を別の描画で観測できる。

ユーザーの根本方針は、野球のシチュエーションを個別のif文で列挙しないこと。野手は未来を読まずに見えている情報から合理的に判断する。物理の結果をルールで裁定し、画面はそれを観測する。実装は依存関係を踏まえてまとめ、一括検証。完了率やPASSを水増ししない。

## Phase 1：自由球から保持球までの真正ボール物理（最優先）

再利用：src/core/sim/ball の BallFlight、BaseballAerodynamics、BallSurfaceContact、BattedBallPostResponseFlight、BattedBallSettlingEvidence、BattedWorldContinuation、BattedWorldPiecewiseFieldThrow、BallContactResponseと既存の正史取得・持替え・放球source。

1. 投球・打球・送球は同一質量・半径・球面・スピン・空力モデル。実リリース→自由飛翔→地面やフェンスの実接触→反発・滑り・rolling・減速・停止→野手捕球→保持→持替え→放球まで連続させる。
2. 土、天然芝、人工芝、フェンスで反発・摩擦・スピン減衰が変わる。接地前の将来予測と実発生したイベントを区別。鉄球のような跳ねないゴロを禁止。
3. glove secure possession成立のtickから通常・俯瞰・投手・打者・走者・守備者すべての視点で白球を消す。保持表示が必要なら別マーカー。捕手のミットに入った球が浮く・上下に動くのは禁止。放球後は自由球として再び表示。
4. フェンス衝突だけでエンタイトル二塁打／ホームランを予約しない。実際の場外通過・deadball ruleがなければライブボール。壁跳ね返りをフライの正規直接捕球にしない。

**検証:** 速度・スピン・入射角・素材・カメラを変え、実球world・球場衝突・スピン・カメラ球位置・公式イベントを一致させる。保持球の表示0と再放球での表示復帰。初回大谷の既知seedは必須。

## Phase 2：バット・スイング・狙う芯・悪球打ち（最優先）

再利用：src/core/sim/contact/SwingKinematicsV1.ts、RigidBatBallContact.ts、src/core/sim/pitching/AerodynamicRigidBatSwingingPitchPhysicalResult.ts、正史身体、src/presentation/mini/BatDoubleCadence.ts、ユーザー提供木製バット画像。

1. グリップ・ノブ・バレル・芯・ヘッドを3D剛体として定義し、手元と腕の実姿勢へ接続。打者視点と捕手視点は同じバットの別投影。前方に離れて貼り付けた絵を削除。
2. 打者は基本的に球をバットの芯帯へ当てにいく。目安として全長のノブから65〜78%の位置を暫定候補とし、選手の実バット・弾性・慣性に合わせて校正。自然な小誤差で詰まりや先端接触が生まれるが、意図的に芯を外すルールは作らない。
3. 本人の認識・意思決定・悪球打ちによる軌道維持・身体能力と、実際の剛体衝突/exitVelocity/exitSpinを独立の正史として保管。自動的な打率や本塁打率のBuffは禁止。
4. 引っ張り・流し打ち・広角・後方ファウル・観客席ファウルを同じ物理接触から発生させる。ファウル角度の現実比較は Phase 9。
5. 真のフォロースルー終了後から走者身体の次動作。試合結果を先に決めたfake打者走行は禁止。

**検証:** 同一球道で体・バット・球の正史を再現、接触点と芯帯の分布、外角・無理な体勢・高/低spinの実打球をチェック。物理衝突tickの前後を表示補間で貫通させない。

## Phase 3：本人の投球と捕手主導／投手主導／協議型（最優先）

既存：BatteryPitchDecision、CommandPitchAdapter、AerodynamicPitchTrajectory、BaseballOrientation、BaseballSpinDecay、NativeAerodynamicSession／ReferenceFixture、09/23 battery設計。

1. キャッチャーの提案と投手の実際の採用／首振り／修正を、受理タイムスタンプ付きイベントとする。CATCHER_LED、PITCHER_LED、NEGOTIATEDは選手の性格・経験・信頼度に応じる。1種類の全員共通処理を完成と言わない。
2. ティカオの最高151km/h、高速スライダー、落差のあるフォーク、速いカーブ。制球97（NLB公開相対）は狙ったミット地点への実誤差が小さい人物像を表す。ナッパの配球理解6が低くてもティカオの制球の真値を毀損しない。コース選択と身体実行を別にする。
3. NLB絶対能力200〜250は確定の一括補正ではない。本人の真の身体能力・投球sourceから設定し、母集団による公開0〜100への射影を後で作る。旧ブラウザの40m/s・特定スピン値はREFERENCEで、本物のティカオの固定球種に昇格しない。
4. 監督指示は現在発行された1球の終了後に停止、次球から適用。既に飛んでいる球や打席の心理を後から改変しない。シードロック／新試合seed、正史リプレイを用いる。

**検証:** 3主導型×カウント×捕手知能×投手能力×次球境界を繰り返し、本人の球種とspinでミットの実位置と球道を照合。四球率は結果を書き換えて合わせず、目標選択と誤差の因果から校正。

## Phase 4：走者の自律認識と物理運動をつなぐ（最優先）

既存：RunnerDecision、RunnerLocomotionController、RunnerBaseTouch、ForceObligation、BatterRunnerWorldTimeline、RunnerKnownContextのSource/Host。

1. 「一塁走者がいる」と「打者走者が一塁へ走る」の役割を分け、8走者占有状態で各走者の強制進塁・帰塁・タッチアップを正本化。forceの情報が未受理ならfalseに変換せずpendingにする。
2. アウト数・捕球前後・二塁送球・一塁アウトによる強制解除・塁タッチ時刻から自律走塁する。走者アニメーションは実際の本人位置を投影する。早着セーフ／架空のベース到着を防ぐ。
3. 3アウトが正史で成立した瞬間に攻撃側全員の行動目標をベンチへ変更。個別の打者OUTでも直ちに打者のベンチ行動へ。UIの結果1秒ホールドと本人身体の移動開始は同時刻の別の処理。

**検証:** 0/1/2アウト、1B〜満塁、フライ/ゴロ/ファウル/四球/三振、各塁先着・タッグアップ・併殺強制解除・得点の条件で実タッチ履歴と描画位置一致。

## Phase 6：全視点を正史read-onlyへ完全接続（P1）

1. v23/v28のPNG原画を維持して、9回プレイ用の旧Browser結果エンジンを廃し、正式Coreのactual world/samples/eventsだけを描画する。旧v23試作エンジンは比較用アーカイブに保存。
2. ボールは自由球のみ可視、保持時は消える。距離に応じて光学的に拡大可能だが衝突半径・飛翔速度へ一切変更を与えない。投手視点は貼り付け円ではなく、透視投影と球面の正史姿勢・陰影・縫い目。回転はCore world spinと時刻、spin減衰、Source release orientation（不明なら表示位相の仮定）から描画。左上の別の回転モニターは禁止。
3. 俯瞰の投球/送球はv27/v28の視認性を保ち、**打球だけ**遠距離・高高度でさらに小さくする。同サイズのフライ球では遠近が分からないため、連続した球径の変化と背景の奥行き手がかりを検証。
4. スイング打者視点は実打球方向へ向く。フォロースルー終了後に走者目線へ。走者は自分の実位置・顔高で球を追い、ホームラン公式確定時は進行方向へ向き直す。捕手目線と打者目線のバットは同じ身体/バットの投影。
5. 投手視点は被打球から最大2秒追跡（打球速度で短縮）、次に真に関与する野手の守備目線。投手が直接処理するなら投手目線継続。未来の捕球結果をカメラで事前に知ったふりをしない。
6. 打者名、外野名、走者名は実人物IDで描画。走者名は全視点で赤。通常の選手/グラウンド55ms、投球約22.9ms、打球/バット27.5ms。物理tickは変えない。
7. 見逃し球の追尾はユーザーが承認した浅いゾーン後ろまでのまま。ファウル追尾最大5秒、0〜2秒タップは2秒地点で短縮、2秒以降タップは即短縮。
8. プレー終了後のUI余韻約1秒、ただしアウトが確定した瞬間から本人はベンチへ歩く。第三アウト後2〜4秒で場面切替、1秒以降タップ短縮。ボタンは「試合を進める／一球もどる／一球すすめる」で下部シークバーはなし。

**検証:** 全視点の世界座標一致、PNGマスク/Font hash不変、同一seed/fps差による公式ハッシュ一致、NativeSpinOrientationObserverの800/2200rpm、衝突前後の姿勢、端末画面1200px/390px/実機。

## Phase 8：PC・スマホ単体と同時接続の実証（P1）

- ブラウザ/スマホ版はNode.js/SQLiteネイティブAPIを持ち込まず、共有純粋TS Core＋ブラウザ保存アダプター(IndexedDB/WASM SQLiteは選定と実機検証要)。再プレイの世界を別の近似エンジンで作らない。
- 同じsource id/hash/version、公式イベント、command issued boundary、transactionとreplayをDB分離して保存。クラッシュ後の再読と改ざん拒否を試す。
- PCは高品質、スマホは軽量な描画・タッチ・省発熱設定。画質設定差が物理を変えない。PC/Android/iPhone実機でオフライン9回と保存/再開、100seed replayを比較。
- 同時接続は単一authorityが公式指示/試合イベントを書き、他端末は観測者または権限付き入力者として参加。ブラウザ単独先行がユーザーの確定優先。

## Phase 9：統計監査と現実の野球との照合（全工程の最終PASS）

- 2026-10-14に旧独立ブラウザの400試合・85,254球がPASSした歴史は参考のみ。新Nativeの実証ではない。回帰fixtureは「初回大谷の偽エンタイトル2B/単打/フライ疑惑」「二塁先着セーフ」「捕球後の白球残存」「四球で打者動かず」「一・三塁手がファウル側」「制球97で四球過多」「3アウトなのに走者が走り続ける」等を必ず含む。
- わざとSourceの当時tick、ボール接地/所持、実捕球、送球先・二塁触塁、打者のforce、外部発行済み指示、守備roleを壊すmutationを用意して、監査が必ず検出すること。
- 実野球の公式ルール・打球ファウル方向・制球・球回転・ゴロの反発比較は、確かめられる現実資料/母数/時代に限定。結果が偏っても直接HR確率/フライOUT結果へ補正を足さない。
- LAN01元複合ケース、9回公式TBD/LAD、PC/スマホ、保存リプレイと異常監査が全部PASSしたときだけ「正式試合として接続完成」と宣言する。

| owner | 実装領域 | 重要な禁止 |

各ownerがsourceを単独所有して、一括の実装＋検証へ進む。テストは単体合格と同時にSourceをまたぐ強い受入を増やし、偽のhit/out・公式記録で実行可能に見せない。全工程がP0/P1になり得るが、優先順位は **因果的な物理→身体/走者→9人の判断と発行→裁定/公式閉鎖→PNG表示→保存と実機** とする。
