## 変更方針と接続状況

1. 一つの物理世界の位置・速度・回転・接触・捕球・送球・走者を裁定し、カメラは読み取るだけ。状況別の併殺パッチ、結果の抽選や事後補正、リーグ名buffは使わない。
2. バットはOpenBiomechanicsの実測研究軌道を使用する。MMDへの依存を終了。実測の芯と推定したノブ・先端、未測定の軸回転を区別する。元JSONとSource hashを保持する。
3. 通常HTMLはローカルHostから共有Coreを動かし、自由な次球・9回進行を実装。Native SQLite認証済みの連続世界と同一とは主張しない。
4. 既存v31 UI・間・画像アニメーション・粗い4px/55ms描画を維持。保持球は隠し、ボールは共有Sourceの位置・spinに従う。配球記号は投球中6%、捕手は打球を1〜2秒追って俯瞰へ移り次球で復帰。3アウトはプレー内容を出してからチェンジを表示する。
5. ファウルは実際の `foul_dead_ball` 確定後1500msで次球へ。捕球可能なファウルフライを単に方向だけで停止しない。
6. 全20人に個別の暫定SIを登録。最新メーカーは公開能力11項目を主編集にし、関連するSIを個人の配分を残して調整する。内部40項目は詳細へ。公開対応は明示的な作者用暫定policyであり、旧リーグ0〜100表示から真能力への公式な逆算ではない。
7. 選球眼は独立したコース推定誤差へ接続し、積極性・悪球への制御とは分離。リーグ参考表示は供給された少人数集団だけから算出し、切替だけでSIを変更しない。母集団不足は未算出。
8. 汎用守備の担当重複・空白・backup集中を修正し、速度／加速度による到達時間、走者の脅威、送球レーン、担当継続を使う。身体同士の衝突や全中継の成功は保証していない。

## 再生成

Node依存は既存の `package-lock.json` を使い `npm ci`。設定・依存の追加やlockfile変更は不要です。既存catalogが未生成なら `node tools/catalog/compile-catalog.mjs` を先に実行してください。

```sh
node tools/browser-bridge/build-native.mjs
node tools/browser-bridge/build-v41.mjs dist/rebuilt-game-v41.html
node tools/browser-bridge/build-maker.mjs dist/rebuilt-maker-public.html --public-abilities
node node_modules/typescript/bin/tsc --noEmit
```

v41の承認元HTMLは `docs/demos/assets/approved-v27-baseline.html` に同梱し、個人Downloadsへの参照を除去しました。必要なPNG、元の派生実測JSON、SI名簿、catalog、公開編集referenceもリポジトリに保存します。ブラウザQAのChromeパスと過去のNative実行用パスは現在Windows向けです。環境が異なる場合は実際のruntimeに合わせて検証器を接続し、旧PASSを流用しないでください。

既存の未変更SourceにはGit blobがLF・Windows作業ファイルがCRLFというものがあります。これを無関係なSource変更にしないため、検証時の103入力をZIPへ元byteのまま併記しました。103入力のSHA照合にはZIPを使用し、通常のcheckoutで改行変換が発生した場合は、その環境で再ビルド・再検証してください。公開するHTML自体は検証済みの元byteと完全一致です。
