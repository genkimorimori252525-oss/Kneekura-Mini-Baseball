# V111 — 制球・カウントと被打リスクに基づく自動配球

- Task: `MB-20261024-V111`。日時: 2026-10-24 JST。
- 人間指示: 良い制球を際の攻めに使い、ボール先行では四球の危険を避けて内側へ寄せる。打者が危険なら打たれる危険と四球を比較して際を維持する。公開能力・個人差を変えず合理的な配球を行う。
- 原因: `LivePitchV1.ts`の自動locationは固定配分の抽選であり、`LiveBaseballMatchV1.ts`からballs/strikes/outs/basesが渡っていなかった。既存`BatteryPitchDecision.ts`は合法callの包装で候補選択器ではない。
- 方針: optionalな試合状況contextと軽量な純粋選択器を追加。固定上限の候補に対し、既知の制球分布・打者の打撃能力・63コース選好から期待コストを比較し、12カウントの遷移と四球/被打を評価する。僅差候補にのみ再現可能な選択幅を残す。
- 影響: 通常Hostのautoだけを新方式へ接続。明示手動コースとcontext省略の既存単発APIは保持。投手メーカーでautoとカウントを試せるよう小さな操作欄を追加。公開能力/保存能力値/物理/判定/守備AI/球場/身体モデルは変更しない。
- 63認識: 自動計画では選好重みを候補評価へ統合し、後段で別のコースに二重抽選しない。投手のbias/uncertainty、実際の制球誤差は維持する。
- 限界: 期待コスト/スイング傾向の近似係数は暫定。公式MLB平均へ較正済みと称さず、未来の実球/実打球や乱数誤差を見ない。良い制球でも四球ゼロや際の成功は保証しない。強打者回避を失敗扱いしない。
- 検証: count×制球×打者能力、左右/身体ゾーン/63重み/技巧、手動と旧APIの互換、独立乱数、同seed再現、通常Host接続、実球での判定、軽量性を確認。型・関連回帰・3HTML生成・メーカー/通常/調整室の実ブラウザーを確認。
- 復旧: 凍結V110のHTML/元JSONを残し、V111を別ファイルで出力。今回の限定Source差分だけを戻せる形にする。他のdirty差分は変更しない。
- 判断根拠: 本人の直接依頼と2026-10-23の通常判断記録方針。新しい公開能力/必須保存形式/全体アーキテクチャは導入しないため、追加確認を重ねず範囲内で実装する。変更範囲を拡張する場合は別判断。
- 参考: MLB Walk glossary（2026-10-24閲覧） https://www.mlb.com/glossary/standard-stats/walk 。強打者が打ちやすい球を避けられることを根拠とする。MLB 3–0記事 https://www.mlb.com/news/mlb-hitters-swinging-more-in-3-0-counts は歴史的な2019数値であり、現行の数値較正には使わない。
- 実装分担: 既存Sol1担当は新選択器/その単体試験のみ。主担当は接続/試投UI/実検証/版生成を所有する。重い実行は直列。
