# V106 残存守備失敗とTBD併殺練習

日時: 2026-10-23 JST。Task `MB-20261023-V106`。

直接依頼: V105で残る守備テスト2件の原因調査・修正とメーカー/通常HTML反映。能力・個人差・球場差を維持する。追加指摘は最新版メーカーのTBD「2塁への併殺練習」で併殺が取れないこと。分業は主担当とSolの限定読取1名に絞る。

確認した不整合:

1. 反応60秒の受球者をdirect fallbackとrelease guardが反応0として扱っていた。relay側の到達不能判断を別経路が覆し、実際に捕れない球を投げ、possessionが戻らず未完了になっている。
2. 一塁フォース後のタッグでは、投げて塁を守るまでの時間と、保持者が走者へタッグするまでの時間を同一の比較として扱っていた。受球後のタッグ準備・移動を切り分けて調べる。
3. TBDの実メーカーでは二塁ではなく一塁へ最初に投げており、先行走者へのフォースが消えてから二塁へ届かず1アウトで終わる。単独のアウト余裕だけの選択と併殺の継続機会を調べる。

方針: 現在の能力/球場/得能を変えず、共通の到達・送球・タッグ見積りと実行前検証を修正する。必要な場合だけ有限の継続プレー評価を加える。テストの期待を弱めず、結果だけのアウト/捕球を作らない。API/JSON形式の破壊的な変更や別設計への大改造は行わない。

検証: 失敗2条件を記録した上で回帰検証、極端な反応/能力差とV105身体モデル、実メーカーのTBD second_force、通常HTMLへの接続、PC/スマホ幅、原JSON/旧版保持。必要な関連テストと型検査を直列に実施する。

追加の本人指示: 2アウト未満では慎重守備を除き、よほど間に合わない場合以外は多少際どい併殺も試みる。判断を固定せず揺れを持たせる。この指示に基づき、二つ目のアウトまでの予測が暫定0.65秒遅れ以内なら候補とする。守備判断傾向で幅を変え、同一の保持機会では固定seedの±0.12秒の判断差を使う。物理乱数を消費せず、毎tickの引き直しもしない。慎重守備は既存の独立した緑得能familyの状態として追加し、基礎SI・公開能力値を変えない。各秒数はMLB実測に基づく数値ではなく暫定のAI方針値。

受球の追加原因: 投げる直前のguardは、実速度からの到達時間と静止からの再始動時間の大きい方を使っており、走ってくる受球者の勢いを失っていた。単に最速の領域進入時間へ置き換える案は、ベースへ減速する実際のmotorより早い到達を予測し、送球を取り損ねたため不採用。実motorの加減速profileによる定数回の区分計算で、速度・反応待ち・制動を保持する共通受球ETAを実装する。

二アウト評価: 二塁→一塁だけでなく、一塁フォース→同じ保持者の走行タッグも比較する。実捕球前の継続は仮説に限定し、実捕球後に次の動作を再判断する。実際のグラブ接触・保持・ベース接触・タッグでのみアウトを記録する。

旧テストの期待とは、二塁→一塁を一律に優先する試作案が衝突した。既存の「一塁受球→同じ選手の走行タッグ」の方が早いfixtureを残し、同経路も二アウト評価へ追加した。期待値を緩めずに元の回帰テストが通る方針とした。
