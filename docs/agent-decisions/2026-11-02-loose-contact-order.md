# 漏球時の接触順序と完成基準

2026-11-02、本人は既存機能と品質を落とさず、原作ロビン全球で遊べる版を優先し、過剰な内部検証を目的化せず進めるよう委任。Astraへの一点レビューでは、現Core `LiveFieldPlayV1.ts` のイベント選択は連続時刻の最早を原則とし、同じ整数tickという理由だけの一律HOLDを要求しないと確認。認定時間区間の重複は限定HOLD、対応済みground/actor同時接触には連成応答がある。

採用方針: 追加したbat/body/runnerは実運動と表面速度boundを使い、全候補の時間区間が分離すれば実際の前後順で処理する。真の同時接触は既存応答を使い、区間が分離できない・応答未対応の場合だけHOLD。後続軌道は接触応答後に再計算し、HOLD時はcount/seed/走者/continuationをcommitしない。単なるnumerical t比較だけでは認定区間の重複や挿入順依存を見落とすため不十分。全空間の数学的証明や全same-tick拒否を完成条件にしない。

実装順: 動くbat/runnerと候補区間の最小差分、ground/actor・wall/actor各前後順と真の競合の必要な検証、release→fieldへの同じ契約、原作11球と非opt-in/再開、実V273 UIのType6→次球。続いて四球・未捕第三strike・走者・SWINGを完成。空塁takeだけではユーザー用最新としない。元FAIL/UNKNOWN・一律HOLD版は保管し、source/入力の変更がない既存検証は再実行しない。
