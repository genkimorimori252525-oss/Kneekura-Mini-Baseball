# Non-pitch game repetitions and prospective learning opportunities

Original area 8 authority is the approved foundation doc53,
`53-player-development-trajectory-breakthrough-v1.md` at
`782f6b8ef2406839de5678b00040001111cd8f77`, §§2, 5 and 9. Relevant repetitions
can occur in games or practice. Physical occurrence, personal relevance,
consolidation and actual source adaptation are separate steps.

## Connected bounded production path

`SqliteNonPitchRepetitionStore.prepare` freezes an explicitly accepted learning
intention for one original Player/game/play before its physical pitch starts.
The original current batter actor supplies the game, day, fixture, Player/Person
and defensive membership. The real development owner supplies an exact earlier
HYPOTHESIS/PRACTICING episode revision and domain. Stale current frames, existing
pitch identity claims and reserved same-PA work cannot become prospective
opportunities. One canonical Player/game/play reservation prevents aliases or
multiple exercise labels from multiplying the same admitted repetition.

The supported exercises are:

- `BATTING_CONTACT`: an executed swing's appended actual bat/ball contact.
- `FIELDING_GLOVE_CONTACT`: the original defender's physical glove contact,
  including unsuccessful contact. This does not claim a catch or possession.
- `RUNNING_MOTION`: positive-duration, executed original batter-runner body
  motion with a nonconstant horizontal trajectory. Standing or planned future
  motion is insufficient.

Completion uses the existing ordinary empty-base actual-live closure, its sealed
physical prefix, exact original participant and completed TOTAL role workload.
It currently excludes reserved same-PA roots and occupied-base participants.
No result, movement or effort is inferred from participation alone.

`inspectCompletion` exposes the original proof hash for an independent accepted
assessment. `assess` pins its relevance decision, explicit exposure factors,
health-availability assessment and assessment/calibration provenance. It binds
fatigue to the original workload BEFORE state. Physical contact or a good result
does not produce a default relevance score, stimulus or appraisal.

`adopt` feeds one existing `PRACTICE_RECORDED` learning event through the existing
episode writer and revision CAS. This event denotes a relevant repetition in the
learning pipeline; the physical workload remains its original `MATCH` receipt.
There is no second workload charge. An assessment that declares no relevance
retains its evidence without adding a learning event. Feedback, consolidation and
any source change still need their independent accepted evidence.

The new event has fixed-format dispatch in the existing development reader and
writer, including INSERT/UPDATE, read and exact retry. The real episode owner now
offers a capability-bound, same-connection historical-prefix read, so a repetition
can authenticate its earlier episode without recursively consuming its own later
event. Later pitch-practice/order archive readers also authenticate this new
event format; the existing pitching execution and numerical policies are unchanged.

`readRepetition` returns original assessed factors and historical fatigue.
`assessExposure` supplies these to the existing Core exposure calculation for a
consolidated episode whose repetitions all belong to this owner. It fails on
missing or foreign repetition owners. It does not substitute zero evidence for
mixed-owner episodes or infer consolidation. Exact opportunity/assessment retries
and recorded learning survive later heads and reopening without live intake
callbacks. The initial episode's existing source contracts still apply.

## Remaining implementation versus model inputs

- Standalone non-pitch drill execution remains a production-owner gap: it needs
  prospective accepted body/action inputs, actually consumed physical work,
  completion and workload ownership. This game path does not stand in for it.
- Reserved same-PA and occupied-runner repetitions need their original endpoint,
  action and workload adapters. Existing physical owners can inform that wiring;
  their absence here is not a product-model decision.
- Broader game exercises, mixed pitch/non-pitch exposure assembly and non-pitch
  durable capability adaptation remain code work where their existing original
  facts and source contracts determine the change. No timing formula is reused
  as a batting, fielding or running improvement formula.
- Autonomous exercise selection/prescriptions, numerical relevance/appraisal,
  standardized measurements, physiology and ability calibration still require
  explicit accepted sources or a defined producer. The adapter supplies none of
  those values by attendance, elapsed day or a neutral default.

## Verification boundary

Small Native writer tests substitute the completed physical reader explicitly.
They check prospective reservation, exact historical episode boundaries,
relevance rejection, original MATCH fatigue, exposure, deduplication, stale CAS,
closed-owner reopen and trigger rollback. Separate small admission tests use real
original registration/world/actor owners and a deliberately corrupt late pitch
claim. They execute no pitch or closed game.

The final focused author selection passed 13 cases across three files in 7.61
seconds under a 35-second external wall cap, one worker and a 512 MiB heap. It
used explicit `--no-cache` and an external cache directory and left no surviving
process group. Syntax-only transpilation passed for all nine changed TypeScript
files; the protected 18 blobs and whitespace check were unchanged/clean. An
earlier selection had one assertion-message mismatch after the expected inert
input rejection; that failed report is retained separately.

No full compiler, long Native game, autonomous Career simulation or new physical
fixture regeneration was run by this author. Genuine three-exercise completion
and later mixed-practice integration remain for consolidated verification.
