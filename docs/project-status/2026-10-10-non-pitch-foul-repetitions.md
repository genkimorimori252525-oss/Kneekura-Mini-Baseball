# Non-pitch repetition: completed foul families

Implementation base: `5dd7e48fbde165e6e594ddf0d640aaab26d41398`.

This is an additive area-8 connection to the existing prospective one
Player/game/play repetition owner. An accepted learning intention still precedes
the physical pitch. Relevance and learning factors still require the original
explicit accepted assessment; this connection derives no gain or calibration.

## Connected existing physical owners

- Ordinary foul terminal: the original Native post-play completion must be
  `POST_PLAY_COMPLETED_CONTINUING` or `POST_PLAY_COMPLETED_FINAL`. Its sealed foul
  end, original physical pitch, exact physical history, participant/Person and
  completed TOTAL MATCH workload are independently authenticated on the same
  connection. Actual swing contact and positive-duration batter motion can
  provide the existing exercises.
- Reserved untouched-foul terminal: the original lifecycle outcome, sealed field
  cut, terminal endpoint, official release and TOTAL settlement provide the same
  contact/motion facts. Original occupied runners qualify only when their own
  body actually moved.
- Reserved count terminal after earlier ordinary fouls: the final outcome's
  immutable lifecycle prefix supplies each earlier owned foul reference. Native
  replay checks its original actor, lineage, physical pitch, field history and
  exact physical end. The final released TOTAL remains the one workload for the
  whole play. Missing, foreign or duplicate physical episodes fail closed.

The last path retains qualifying earlier episodes as factual premises of one
existing repetition and learning event. Episode count never multiplies accepted
factors, admissions, workload or source changes. The canonical event identity and
opportunity reservation are unchanged. Existing ordinary-live and reserved
fair-catch evidence encodings are retained.

The existing repetition store, Native historical reader and mixed development
exposure reader already consume this completion owner. Its normal assessment,
apply, exact retry, archive and reopen paths therefore use the new families
without a separate learning or exposure policy.

## Boundaries

- An untouched foul cannot supply glove-contact credit. Defender membership
  alone does not prove contact; offensive membership alone does not prove motion.
- A count terminal with no qualifying earlier physical fact cannot supply a
  batting-contact, glove-contact or running-motion repetition. A nonterminal
  foul alone cannot bypass the final official release and TOTAL settlement.
- Moving occupied non-third-out settlement retains its unresolved production
  choices and missing accepted final owner. This adapter does not create one.
- Standalone batting-contact/catching execution is a separate implementation
  component. No standalone executor, additional exercise, autonomous relevance,
  timing-to-batting conversion or ability formula is introduced here.

## Focused verification

`NonPitchRepetitionPhysicalVariants.test.ts` uses a real small Native database
with explicit lower physical/completion/workload test seams. It checks the new
dispatch, original binding and physical conditions, incomplete settlement,
canonical aliases, prior-prefix membership, zero-motion rejection and repeated
reads. It does not qualify a genuine physical game.

The affected selection also includes `SqliteNonPitchRepetitionStore.test.ts`,
which protects the existing reservation, assessment, writer reauthentication,
rollback, retry and reopen behavior. A first 30-case run passed before the
prior-foul/count-terminal extension. The next 32-case run exposed a test mutation
of an intentionally frozen returned body (31 passed); the test now replaces its
controlled fixture body instead. Both original results are retained locally.
The final selection passed all 32 cases in 7.08 seconds under a 35-second external
cap, with one worker, a 512 MiB heap, disabled Vitest caching and an external
cache directory. It exited successfully with no surviving process group.
Whole-source compiler, independent review and any genuine qualification belong
to the consolidated batch.
