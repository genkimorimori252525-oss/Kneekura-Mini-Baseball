# Accepted batting capability history and Native learning provenance

This area-8 connection follows the [physical repetitions and mixed exposure
batch](2026-10-09-non-pitch-variants-and-mixed-exposure.md). It accepts explicit
replacement capability values through the existing dated batting model owner.
It does not calculate a capability gain from pitch timing, an exercise label or
an exposure score.

## Historical development authority

The new Native readers reconstruct a pinned development episode revision on
the consumer's own SQLite transaction. National exposure uses its existing
original participation/adoption boundary. Practice origins reuse the actual
consumed pitch/discovery boundary. Roster origins reuse the executed original
Manager decision, Player/Person/seed and accepted appraisal/policy contracts.
All saved prior episodes and each required practice event are authenticated at
their original revisions. Same-episode dependencies must move to an earlier
revision; forward dependencies and cycles fail.

The existing pitch-practice decoders now have a read-only entry using Native
Person, timing, release, workload, order and episode readers. It performs no
schema installation or process-lifetime authority registration. Release replay
uses the original accepted revision, independently of a later mutable head.
Postbaseline pitch timing requires the original standardized-practice learning
archive and its earlier timing boundary. A generic stored timing DTO alone is
insufficient for this physical-practice replay path.

The original non-pitch repetition decoder and mixed-exposure decoder share this
historical episode authority. The exposure keeps the exact original event
order, explicit coefficients, physical proof hashes and fatigue/health facts.
Later consumers do not need the writer objects that originally accepted it.

Older roster development rows did not archive their accepted appraisal and
policy inputs. New actual-roster admissions capture those inputs once, use them
for the original resolution and persist them alongside the unchanged legacy
episode bytes. `archiveRosterOrigin` can add that archive to an existing row
only by reacquiring accepted inputs and reproducing its original result against
the Native roster/Person owners. Missing original inputs remain a concrete
data prerequisite. Reconstructing policies from a derived assessment is not an
alternative. Archive reads, retries and post-INSERT validation check the
original Source claims, hashes and result.

## Explicit dated batting replacement

The optional `accepted_batting_capability_development_v1` tag pins:

- The original model Source and complete snapshot hashes.
- One eligible consolidated exposure Source and complete snapshot hashes.
- Explicit accepted capability assessment/calibration references.
- The complete replacement capability hash.

Player, Person and original initiation link must agree. Only the capability may
change; the original body, repertoire, decision model, equipment and perception
calibrations remain pinned. Assessment/calibration references identify supplied
accepted provenance; this connection does not create a measurement producer.

The existing dated selection contract applies. The replacement must follow its
original model's accepted day, and its capability acceptance cannot precede the
exposure's consolidation day. Acceptance on that consolidation day is allowed.
The original model must have been effective by consolidation and must be the
latest strictly earlier dated model. There is no added next-day rule. Existing
same-Player/same-day ambiguity remains rejected.

Generic model reads, exact retries, fresh writes and post-INSERT checks replay
this provenance. Archived physical frames retain their original model reference.
Shared parameter ownership checks validate later rows' frozen parameter claims
without recursively substituting those later models for an earlier frame.
Cross-owner model/exposure cycles fail closed. Untagged Source bytes stay exact.

## Remaining code and model boundaries

- Fielding, runner decision/motion and defender locomotion still need append-only
  adaptation histories and historical selectors. Their one-baseline owners
  cannot be rewritten to simulate an accepted replacement. This is remaining
  ownership/consumer code; no numerical producer is necessary for explicit
  accepted values. Any required change to protected physical consumers needs
  coordinated scope before implementation.
- Standalone non-pitch drills still need prospective physical execution,
  consumed completion and original PRACTICE workload ownership. Existing Match
  repetitions do not supply those standalone facts.
- Moving occupied-runner completion and other reserved outcome families still
  require their compatible original endpoint/workload producers or adapters.
- Autonomous appraisal, relevance, drill selection and numerical ability or
  physiological adaptation require their own accepted measurement/calibration
  models. Pitch timing does not define batting, fielding or running gains.
