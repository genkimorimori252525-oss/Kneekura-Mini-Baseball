# Work描画原則 — 観測座標・B1・名前枠・球場線

更新日: 2026-09-21 JST  
状態: **改訂16。投手目線のB1は原画のバット込み4コマを描く。連続した物理バットの入力は保持し、この表示だけ不可視にする。本体Coreとの接続は未完了。**

本書は2026-09-20の[Work引き継ぎ](2026-09-20-work-handoff-drone-art-broadcast-camera.md)と[Drone-Art表示設計](../game-design/07-drone-art-presentation.md)の具体化である。Coreの物理・判定・結果・Canonical Worldを変更する権限は追加しない。

## 1. 見た目を選び、動きは観測する

B1は「小さい頭・厚い胴体・広い肩・太い手足・顔なし」という描画上の形と配色を定める。動く場所、物理バットの軌道、ボール、接触時刻は観測入力に従う。投手目線のB1の見た目は、後述するバット込み4姿勢を使う。

- Aの光点とB1の人物表示は設定で切り替える。同じ時刻・同じ入力を観測する。
- モデルの大きさは選手の身体寸法に従う。遠近を投影した後、球場と共通の4px固定表示格子に落とす。粒の間隔は固定し、物体の大きさは占める粒数で表す。
- 4pxは表示の粗さであり、世界の座標精度や当たり判定ではない。
- 身体の絵に合わせてバット、球、足元の観測座標を移動させない。

## 2. バットと身体の責任を分ける

Presentationは各観測時刻のバットの握り位置 `grip` と先端位置 `tip` を保持する。通常の連続描画では、その両端を投影し、間の道具形状を4px格子へ描く。改訂16の投手目線B1では、この物理バットの描画だけを省略し、採用原画のバットを身体と一体で表示する。データの削除、軌道の4コマ化、判定の停止は行わない。

物理軌道を「ダウン」「レベル」「アッパー」という名前や打撃結果から作らない。連続描画の視点では中間の軌道もそのまま投影する。投手目線B1の絵は、観測された身体のコマ番号を選び、物理軌道の細かな違いを一対一で表示する役割から外す。これはユーザーが指定した表示方式であり、物理の精度を下げる変更ではない。

B1は原画の身体・腕・脚を保った形状マスクを使い、握り位置へ腕を引き伸ばさない。右打者と左打者は別の原画を選ぶ。改訂15ではユーザーの訂正に従い、投手目線に限り、それぞれの原画の形状全体を左右反転して向きを合わせる。4姿勢すべてに同じ変換を適用し、利き手・打席側・原画IDを交換しない。俯瞰は原画の向きを保つ。身体の4姿勢と、連続した観測バットの座標は別に扱う。

球の描画と、連続表示のバットは観測入力に従う。原画のバットから物理バットや接触点を計算する処理を描画器へ入れない。将来の実関節入力との接続は、採用形状を崩さずに整合することを別途検証する。情報不足を不自然な近似の腕で覆い隠さない。

改訂13は原画を独自の楕円・線分へ描き直し、さらに近似の腕接続を加えていた。この状態を「採用済みの統合」と説明したのは不正確だった。改訂14ではこの近似処理を廃止し、原画の色領域を採取した形状マスクへ置換した。

独立試験版の固定入力には、原画の手と反対側に構えの握り位置が寄る不整合もあった。これは描画器内で修正せず、**試験データの作成器**で握り位置を改訂した。球・回転・判定・得点・走者・イベント時刻は改訂13と同一。CoreやCanonical Worldの値は変更していない。見本データの変更を、実Coreの修正として扱わない。

### B1の4姿勢と6姿勢（改訂14）

| 動作 | 基本姿勢 |
| --- | --- |
| 打撃 | 構え、ため、インパクト、振り抜きの4姿勢。右打者・左打者を区別 |
| 投球 | セット、脚上げ、踏み出し、リリース、振り抜き、守備への戻りの6姿勢 |
| 投法 | オーバー、アンダー、サイド。それぞれ右投げ・左投げ |

ユーザーが採用した小顔・ごつい体格・顔なしのB1を基準に、原画由来の形状マスクとして中継へ組み込む。写真を基準とする旧6コマ打者、旧立体打者へ戻さない。通常の身体マスクにはバットと球を含めない。投手目線B1に限り、同じ原画から採取したバット込みの派生マスクを選ぶ。球はどの表示でも別に観測して描く。原画8点の識別子とSHA-256、および左オーバー原画の未照合状態は[原画台帳](2026-09-21-approved-player-art-manifest.md)で管理する。左オーバーの現表示は右原画を反転した暫定版であり、独立した採用原画ではない。

打者の二つの靴を前後にずらしたシルエットで見せる。左右の打撃途中に利き手が入れ替わる反転を行わない。身体のマスクは描画近似であり、身体の当たり判定ではない。サイズと足元アンカーは観測入力に従う。身体は承認済みの姿勢を維持する。バットの表示方式は改訂16の対応表に従う。

投手目線では打者と捕手が見える。打者/捕手目線では打者の身体を省略する。走者になった打者まで非表示にしない。走る姿勢は観測された移動中に限り、塁へ着いたら待機へ戻る。移動する野手もその経路を観測して姿勢を切り替える。

既存の接続先:

- `src/core/sim/contact/BatBallContact.ts`: `BatPose`、時刻に応じたスイング状態。
- `src/presentation/mini/model.ts`: `CanonicalPresentationSample.batter.bat`。
- `BatterPovRenderState.ts` / `PitcherPovRenderState.ts`: 観測したバット両端の投影。

`CanonicalWorldSnapshot`本体にバットが含まれている、と誤認しない。現行のバット入力はPresentation sample側にある。Coreが提供していない軌道や関節を「正史データ」と称して補完してはならない。

## 3. 時間とカメラ

- 標準表示テンポは55ms。物理の刻みとは独立する。
- 中間位置が必要ならCoreの正式な時刻サンプルを受け取る。描画側の都合で架空の移動を足さない。
- 接触・リリース・フェア確定など必要なイベント境界を正しい時刻で観測できること。現行の `createMiniPresentationSampleSchedule` は標準刻みに加えてイベント時刻を含む。
- 4pxへの丸めにより小さな軌道差が同じ表示になる場合がある。すべての物理差が視認できるという保証はしない。
- 打者目線・捕手目線では自分の打者モデルを省略し、構えたバットが画角外、スイングが画角内に入る構図を使う。バットを結果やスイングフラグで出し入れしない。
- マウンドからホームを見る投手目線では打者と捕手が見える。既存のcatcher-behind `PITCHER_POV`を改名・置換しない。試作では追加視点を `mound` として区別する。
- フェア確定時に俯瞰へ移る。空振りだけで俯瞰に移らない。カメラ操作はCoreへ書き戻さない。

## 4. 選手名

参考画像に合わせ、淡い白の文字を**半透明の黒い長方形**へ入れる。試作の背景は `rgba(0,0,0,0.68)`。文字自体の透明度は下げない。装飾的な輪郭線・角丸・役割別の色分けは加えない。

名前の位置は選手の投影位置に追従する。文字の大きさ、枠の余白、選手との間隔も身体寸法・距離・寄りに従う。試作の余白は文字サイズに対する `em` 単位で指定している。

重なりを避ける調整は選手の近くに限定する。空きがなければ遠い選手の名前を省略する。遠い名前を固定サイズまで膨らませたり、別の選手のそばへ押し出したりしない。

## 5. 球場は共有する座標から描く

本番では、その試合に固定された球場形状と競技規則の寸法定義を読み取る。球場モデル1〜10は外観の種類であり、競技寸法を所有しない。

最低限、左右両方の打席、五角形の本塁、捕手用の区画、投手板、3つの塁、ファウルライン、走路の線を扱う。打者が入っていない側の打席も存在する。

内野を一周する仮の白い菱形を競技上の白線として描かない。一塁―二塁、二塁―三塁の間の土の道と、ファウルラインを区別する。塁の大きさ・向き・配置は採用競技の寸法に従う。

線の片端がカメラの背後や画面外に出ても、見える区間は残す。世界座標の線分を手前の表示限界で切り、画面の範囲でも切ってから4px格子へ描く。線の見やすさのために球場寸法を拡大しない。

### 全面準拠とは扱わない残件

- マウンドの高さ・斜面、地表の立体形状と選手の足元高度は未接続。今回確認したのは平面の寸法と線である。
- 外野100m / 122m / 100m、フェンス、ファウル地域、観客席は独立試作の参照形状。実試合の凍結球場データではない。
- コーチャーボックスは参考図に基づく表示見本。競技プロファイルからの供給は未接続。次打者用サークルは未実装。
- 提供されていないCanonical形状をPresentationから書き戻して埋めない。Ballpark Builderの新規実装はこの作業に含めない。

## 6. 白球・縫い目・ゾーンの優先度（改訂11）

[白球の観測姿勢と表面描画契約](2026-09-21-observed-baseball-surface-contract.md)を適用する。

- 球は白い革＋赤い縫い目。球場と同じ4px格子へ描き、標準55msを維持する。
- ストライクゾーンの線と黒い下地は、重なった球を消さない。球とバット・グラブ・身体の重なりは世界の奥行きで決める。
- 縫い目は球の表面に固定し、各時刻の絶対姿勢へ追従する。球種名や表示コマから回転を作らない。
- 現行Coreは球の回転ベクトルを持つが初期姿勢・絶対姿勢履歴は未提供。正式な姿勢がない場合は白球のみ。改訂11の回転は明示した独立見本であり、正史の回転ではない。
- 遠景では白を優先し、近景で縫い目を表示する。細部の省略は物理や観測姿勢を変更しない。
- 採用済み人物デザインは左右打撃4姿勢、オーバー／アンダー／サイドの左右投球各6姿勢。改訂13の試合形式HTMLにこれらを基準とする描画マスクを組み込んだ。本体の実接続とは区別する。

### 黄色いゾーンと配球図（改訂13）

ゾーンは黄色 `#e0b541`。投球位置に球種・変化方向別の形と番号を表示する。色は結果を表す。一覧は番号選択の補助とする。確定済み投球を1球ずつ追加し、次の打席の開始時に空にする。途中の選手交代や視点変更ではリセットしない。

同じ投球の通知・結果更新は1行へまとめる。過去の記号は現在の白球を隠さず、重なった位置を読むために座標をずらさない。[配球履歴の描画契約](2026-09-21-pitch-history-presentation-contract.md)に入力の境界と未接続事項を記載する。

## 7. 改訂10時点の実装・検証履歴（人物デザインは後に不採用）

更新対象は `mini-baseball-model-1-design-v1.html` の改訂10。ブラウザで開く独立試作であり、Coreの実試合画面へ組み込まれたものではない。GitHubへの今回の変更は、この原則と関連文書の参照導線である。

試作はダウン・レベル・アッパーの3系列、それぞれフェア／空振りの凍結済み観測見本を持つ。3系列の生成は見本データを用意する処理であり、描画処理は系列名による分岐を持たない。試合結果を算出する処理ではない。ボール・バット・イベント・表示時刻を入力として読む境界を本体接続時に置き換える。

検証した内容:

- 前足が投手側、後ろ足が捕手側にあり、構えと踏み込みの投手目線では画面の横方向より奥行き方向へ並ぶ。
- 打撃6姿勢が姿勢見本と投手目線の両方で異なる描画になる。
- 改訂9から観測バット・球・結果・時刻・球場寸法を変更していない。
- バット位置は6種類に限定されず、3系列で実際の描画が異なる。
- 投手目線で手の描画が握り位置へ追従する。
- A/B切替で観測入力・時刻・カメラが変わらない。凍結データは変更されない。
- 打者／捕手目線の待機バットが画角外で、スイング時に映る。
- 本塁拡大で両打席の線を描画し、寸法・ホームの向き・投手板位置を確認。
- 1200 / 390 / 320px幅、4視点で横溢れ・名前同士の重なり・JavaScriptエラーなし。
- フェア時のみの俯瞰切替、停止、時間指定、A/B切替、4px格子の維持。

本体統合時には、同じCore出力を複数の外観・カメラで観測して結果が不変であること、Canonicalのバット・関節・球場を実際に受信できることを追加検証する。試作の合格をCore接続の完了と読み替えない。

## 8. 現在の統合試験版（改訂16）

[試合形式HTMLの実装状態](2026-09-21-integrated-match-preview.md)を参照する。上記の改訂10節は不採用となった試作の履歴であり、現在の身体表現を指示しない。現在の画面は採用B1・白球・配球図・スコア・BSOを一つの時刻で再生する。Coreの物理・Canonical型・試合結果は変更していない。

### 改訂14の再生と打者カメラ

打者カメラの高さは見本の1.62mから1.30mへ下げた。標準倍率で全67打席のゾーン四隅が600×432の画面内へ入る。待機バットは打者・捕手目線の双方で画角外、スイング中は画角内へ入る。

改訂13では `performance.now()` の再生開始時刻と、それ以前の `requestAnimationFrame` 時刻が混ざると、負の1コマへ進み例外停止した。改訂14は55msの表示刻みを維持し、再生を専用タイマーと同じ時計で進める。描画フレーム通知がないプレビュー環境でも再生し、古い開始前時刻で逆行しない。停止時はタイマーを解除する。

### 改訂15：投手目線の向き、記号の遠近、立ち位置

| 投手目線の打者 | 打席側 | 原画と表示方向 |
| --- | --- | --- |
| 右打者 | world x < 0、画面右 | 右原画の4姿勢を一括反転し、画面左へ向ける |
| 左打者 | world x > 0、画面左 | 左原画の4姿勢を一括反転し、画面右へ向ける |

改訂14の「カメラを理由とする反転を一律に禁止」は、この明示的な視点対応へ訂正する。身体の一部だけを反転したり、打撃途中に変換を変えたりしない。原画PNGと形状マスクの採取結果は変更せず、表示時の向きだけを変える。

映像上の配球記号は半径0.065mの注釈として、観測位置の投影倍率 `f / depth` を掛ける。丸・三角、番号、線幅、補助線、選択範囲に同じ縮尺を使う。重なり判定も記号の投影半径に従う。標準の投手目線では旧半径16pxから約5.8pxとなり、ゾーンを占有しない。独立した下部配球図は従来の大きさを保つ。白球が記号より優先する原則も維持する。

立ち位置は見本作成器の打者アンカーのみ `z=0.06m` から `z=0.72m` へ前寄りにする。左右の `x=±0.97m` と両打席の寸法は変えない。向きの修正に対応する構え・移行・振り抜きのバットも見本入力で調整する。スイングの接触コマのバット両端、球・回転、判定、得点、イベント時刻、他の選手の経路、走り出した後の目的地は改訂14と同一。描画器は入力の足元・バット座標を動かさない。原画は平面の姿勢マスクであり、本体の実関節・足裏接地との厳密な接続は残件。

### 改訂16：物理のバットと、原画のバット

ユーザー指定: 物理バットは存在・運動を保ち、投手目線では不可視にする。見た目を身体と同じ原画の4コマへ統一し、滑らかなバットだけが身体から離れる違和感をなくす。

| 表示 | バットの見た目 |
| --- | --- |
| 投手目線 `mound`・B1 | 右・左それぞれの採用原画に含まれるバット。身体と同じ4コマ |
| 打者目線・捕手目線 | 従来の観測軌道。待機時は画角外、スイング時に画角へ入る |
| 俯瞰 | 従来の観測軌道 |
| Aの光点 | 従来の観測軌道 |

- 絵のバットは表示専用で、当たり判定を持たない。Coreの連続したバット・球・接触計算・結果を絵に合わせて変更しない。
- 物理バットを不可視にするのは描画経路だけ。観測入力の両端は保持して投影できる。不可視のバットで球の画素を隠す処理も加えない。
- バット込みの8マスクは、採用原画の左右4枚から採取する。既存の身体画素、足元、身体の基準高、体格、名前位置を維持する。新しいコマや腕の変形を作らない。
- 改訂15の向き対応を身体と原画のバットへ一括して適用し、物理バットの連続描画を重ねない。右打者・左打者の原画と打席側は交換しない。
- 4px格子と標準55msを維持する。同じ身体コマ内では、物理バットが動いても絵のバットは動かない。コマ番号の切替で身体と道具が同時に変わる。
