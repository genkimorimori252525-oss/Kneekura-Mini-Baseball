# 黄色いゾーンと、打席ごとの配球履歴

更新日: 2026-09-21 JST  
状態: **ユーザー指示を改訂12の独立HTML試作へ反映。本体の実試合接続は未完了。**

## 表示の決定

- ストライクゾーンは黄色 `#e0b541`。既存の寸法・位置を変えず、4px格子の点線と四隅で描く。
- 白球＋赤い縫い目を継続する。飛んでいる球はゾーンの線・下地・過去の配球記号より優先する。実物体との前後関係はワールドの奥行きに従う。
- 確定した投球を1球ずつ履歴へ加える。ゾーン周辺に投球番号、一覧に番号・球速・球種・結果を表示する。
- 現在の打席のみを表示する。**次の打席の開始時に空にし、次の投球番号を1から表示する。** 打席終了直後には消さず、最後の球の結果を読めるようにする。
- 途中の選手交代、視点変更、停止・再開、記号表示の切替は、打席が同じならリセット理由にしない。

黄色はゾーンの色。判定はCoreから読む。ゾーン内外の見た目でストライク／ボールを再判定しない。数字記号は過去の観測位置を表す注釈であり、過去の球が空間内に残存している扱いではない。

## 記号と一覧

| 対象 | 表示 |
| --- | --- |
| ボール判定 | 緑系 `#24b698` の番号と結果名 |
| 見逃し・空振り・ファウル等 | 黄系 `#e0b541` の番号と結果名 |
| 打球 | 赤系 `#e5787e` の番号と結果名。色だけでアウトを表さない |
| 未提供・その他 | 灰系 `#c5c5c5`。不足した値は「—」等で明示 |

位置記号も球場と同じ4px格子へ置く。最新の球を選択し、過去の番号を選べばその位置を強調する。同じ場所に重なった投球を読み分けるために、元の座標を散らさない。選択した番号に重なる別の番号は一時的に省き、すべての球は一覧から選べる。投球中は過去の記号を暗くし、現在の白球を優先する。

一覧は投球順。ファウル等で球数が増えても任意の件数で切り捨てない。画面内の高さを超える場合はスクロールする。色だけに依存せず、番号と結果名を併記する。

通常の位置は観測されたプレート通過時の球中心。接触前にプレートを通っていない打球は、正式な接触時の球中心を使い「接触位置」と区別する。通過していない地点へ球筋を延長して履歴を作らない。位置がない場合は一覧のみ。画面外の位置をゾーンの縁へ押し込まない。

## Observerの受け取り口

表示側の入力例は次のとおり。**既存Coreへ追加済みの型ではない。**

| フィールド | 責任 |
| --- | --- |
| `plateAppearanceId` | 試合も識別できる打席ID。同名の打者でも別の打席は別ID |
| `pitchId` / `number` | 打席内で安定した投球IDと投球順。同じ投球の通知を重複計上しない |
| `status` | `confirmed` の記録だけ表示。飛行中・結果未確定の予告記録を表示しない |
| `availableAtMicros` | その結果を観測できた時刻。表示時刻より未来の結果は隠す |
| `revision` | 同じ投球の結果更新。例えば「打球」から「遊ゴロ」へ更新しても1行 |
| `location` | `plate-crossing` または `contact` と、観測された球中心。欠落は `null` |
| `pitchType` / `speedKmh` | 入力元が供給した表示値。未提供なら推測しない |
| `resultLabel` / `category` | Coreの結果に対応する表示。位置から判定を算出しない |
| `count` / `terminal` | 供給されたカウントと打席終了情報。履歴行数から再計算しない |

`observer-pitch-history-v1.js` は、現在の打席ID・観測時刻・読み取り専用記録列から、その時点の確定済み履歴を取り出す。同一IDは最新版1件へまとめ、過去へ戻る際はその時点で観測可能だった版を使う。描画回数や再生開始回数によって球数は増えない。

表示のリセットは抽出対象の打席を変える操作であり、Coreの記録削除ではない。表示側は物理、判定、試合結果、Canonical Worldを変更しない。標準表示間隔は55msを維持する。

## 現行Coreとの接続状態

調査した `CanonicalPlateAppearanceTimeline` は `playId`、`startedAtTick`、`events` を持つ。`TakenPitchPlateCrossed` には通過位置、`PitchAdjudicated` には判定・カウント情報、`BatBallContact` には接触時の球中心がある。

実接続側では、試合IDと打席識別、投球の物理結果と判定イベントの対応付け、球種名・球速の供給を行う必要がある。物理イベントと判定イベントを別々の投球として数えない。球種名・球速やすべての打球結果が、現在の単一イベントから取得できるとは扱わない。

今回のHTMLは2打席の凍結済み観測見本を使う。各打席の表示時刻を0から示し、初期表示は1打席目の3球終了時点。`次の一球を見る`で4球目・5球目を追加し、`次の打席へ`でリセットを確認できる。Coreへの橋渡しは未実装であり、実試合データとは称さない。

## 確認

確定時の追加、飛行中の結果非表示、同一投球の二重計上防止、結果更新、次打席開始直後の0件化、次打席の1球目、時刻を戻した際の履歴復元、別打席・別試合の混入防止、位置欠落、長い打席の記録保持を確認する。

実際に白球が過去の位置記号と重なる場面と、球場試作でゾーン上辺に重なる場面で、注釈の表示切替が白球の画素を変更しないことを確認する。4px格子、55ms、元の球・バット・球場の観測入力、幅1200／390／320pxも確認対象とする。
