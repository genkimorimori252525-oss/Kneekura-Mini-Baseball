# 黄色いゾーンと、打席ごとの配球図

更新日: 2026-09-21 JST  
状態: **改訂15。ゾーン上の球種記号を主とし、映像上の記号・番号・線幅へ遠近を適用。本体Coreとの実接続は未完了。**

## 表示の決定

配球履歴は一覧表のことではない。**過去の投球位置に、球種・変化方向を示す形と投球番号を残す配球図**である。番号一覧は重なった球を選ぶ補助に使う。添付の白い図は意味の説明として受け取り、外観をコピーしない。

- ストライクゾーンは黄色 `#e0b541`。位置・寸法は入力に従う。
- **形＝球種、三角の向き＝変化方向、色＝結果、数字＝その打席で何球目か。**
- 中継映像の投影されたゾーン上と、捕手側で向きを固定した配球図へ表示する。
- 次の打席の開始時に空にし、投球番号を1から表示する。打席終了直後は最後の球を残す。
- 選手交代、視点、外観、停止・再開、表示切替は同じ打席のリセット理由にしない。
- 過去の記号は注釈。飛行中の白球はゾーン・過去の記号・黒い下地より優先する。バットやグラブとの前後関係は実物体の深度に従う。

## 本試作の記号体系

| 球種 | 形 | 向き・補助線 |
| --- | --- | --- |
| 直球 | 丸 | 方向を示さない |
| スライダー | 三角 | 供給された変化方向 |
| カーブ | 三角 | 供給された斜め下方向 |
| フォーク | 三角 | 供給された下方向 |
| チェンジアップ | 丸 | 下に短い線1本 |
| カットボール | 三角 | 変化方向＋短い線1本 |
| ツーシーム | 三角 | 変化方向＋短い線2本 |
| 分類・方向が未提供 | ひし形 | 勝手に方向を推定しない |

丸・三角等と判定色を分ける実例は、[SPAIA運営元の2019年説明](https://www.dreamnews.jp/press/0000198324)および[2020年発表の転載](https://air-next.com/news/spaia%EF%BC%88%E3%82%B9%E3%83%91%E3%82%A4%E3%82%A2%EF%BC%89%EF%BC%9A%E3%83%97%E3%83%AD%E9%87%8E%E7%90%83%E3%83%95%E3%82%A1%E3%83%B3%E5%BF%85%E8%A6%8B-%E4%B8%80%E7%90%83%E9%80%9F%E5%A0%B1%E3%81%AB)で確認した。上表の球種別の細かな線・方向の使い分けはWorkの設計であり、野球界共通の規則や他サービスの完全な再現と称さない。

方向は `breakVector` を投球位置から現在のカメラへ投影した差で求める。同じ入力を捕手側とマウンド側から見れば、画面上の左右は反転する。投手の利き手だけで三角を反転しない。右打者から左打者へ変わっただけでも反転しない。配球図には「捕手側から」を明記する。

結果色はボール緑、ストライク・空振り・ファウル黄、アウト赤、安打青、未確定の打球は別色。**打球になっただけでアウトを先出ししない。** 結果名も併記し色だけに依存しない。

位置アンカーは4px格子に揃える。記号の輪郭と数字は注釈UIとして判読性を確保する。選手・道具・球場・白球の形そのものは4px光点で描く。投球中は過去の記号を薄くする。重なった投球の座標を散らさず、番号選択で読む球を優先する。すべての球を一覧から選べるようにし、任意の球数で切り捨てない。

通常はプレート通過時の球中心。接触が先なら観測された接触時の球中心を使い「接触位置」と区別する。架空のプレート通過位置へ延長しない。位置不明は一覧のみ。画面外の球を端へ押し込まない。

## Observerの受け取り口

| フィールド | 責任 |
| --- | --- |
| `plateAppearanceId` | 試合も識別する打席ID |
| `pitchId` / `number` | 投球の安定IDと打席内の投球順 |
| `status` / `availableAtMicros` | 確定済みで、その時刻に観測できる記録のみ |
| `revision` | 同じ投球の結果更新。重複表示を作らない |
| `location` | `plate-crossing` / `contact` と球中心。欠落はnull |
| `pitchType` / `pitchKind` | 供給された表示名と記号分類 |
| `breakVector` | 供給されたワールド方向。球の運動を制御しない表示メタデータ |
| `speedKmh` | 入力元の表示値。欠落時は推測しない |
| `resultLabel` / `category` | その時刻までに確定した結果 |
| `count` / `terminal` | 供給されたカウント・打席終了情報 |

これはPresentation試作の契約であり、Coreに追加されたCanonical型ではない。純粋なselectorが打席・時刻で抽出し、投球IDごとに観測可能な最新版1件を返す。描画回数で履歴を増やさない。過去へのシークでは未来の版を表示しない。リセットは抽出対象の変更でありCoreの記録削除ではない。

現行Coreの `CanonicalPlateAppearanceTimeline`、`TakenPitchPlateCrossed`、`PitchAdjudicated`、`BatBallContact` を接続する際は、物理イベントと判定イベントの同一投球への対応付け、試合・打席・投球の識別、球種/方向/球速の供給が必要。単一イベントに全情報があるとは扱わない。

## 改訂13の状態と確認

`kneekura-mini-baseball-match-v13.html` は67打席・272球の凍結済み架空試合を一つの時刻で再生する。スコア・BSO・走者・選手名・配球図・中継映像が連動する。Coreの試合計算、速度・軌道の物理検証、Canonicalの完全な再生接続を完了したものではない。

確認: 各打席開始0件、確定前非表示、結果更新でも1件、前後へのシーク、カメラで三角の左右が追従、左右打者で誤反転しない、番号選択後もキーボードフォーカス維持。球が線・記号へ実際に重なる場面で、表示切替によって球の画素が変わらないことを確認した。幅1200／390／320pxに横溢れ・JSエラーなし。

## 改訂15の遠近

中継の記号は画面固定の半径16pxを廃止。観測位置の投影倍率に0.065mを掛けた半径を使い、番号、線幅、下線の間隔、選択範囲も同じ倍率にする。標準の投手目線では半径約5.8px、直径はゾーン幅の約30%。カメラの寄り80〜140%に追従し、名前と同じ距離の規則で拡大・縮小する。

重なりで省略する基準も固定32pxから投影半径の和へ変更し、選択された球を最後に描く。位置は観測座標を4px格子へ丸めるだけで移動しない。下部の「捕手側から」の配球図は従来の半径14pxと番号表示を保ち、遠景で小さい番号はこの図と一覧から確認できる。白球の優先度と1打席ごとのリセットは変更しない。
