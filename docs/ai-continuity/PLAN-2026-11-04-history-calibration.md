## 0. 前提（済み）
- MLB候補2の打撃を既定にした（`lateLookByMeetOnlyV1`、`priorPlacementShareV1 .45`、`impactSpeedLimitV1 1.0`、`battedBallAeroV1 1.2`）。MLBの標準リーグ `work/calibration/cfg-mlbstd.json`（git外）が、能力値84の基準の選手。
- 守備: 守備較正部が、守備位置ごとの体、走り出しの形、塁カバーを進めている（branch `claude/defense-mlb-2026-11-03`）。

## 1. 高速化（最初にやる）
測定（2026-11-04、40球）: 通常167秒、守備を飛ばす（`--skipField=1`）と5.5秒。時間の約97%は守備の計算。1試合のピークメモリは約1.4GB、PCは24コア・32GB。
| 方法 | 見込み | 品質 |
|---|---|---|
| A. 同時本数 3→約10（ヒープ2〜3GB、重い処理は別枠1本） | 約3倍 | 同じ |
| B. 打席の測定を守備抜きで（三振・四球・打球の速さと角度と方向） | 約30倍 | 同じ（守備を通らない数字） |
| C. 打球の結果を表で決める（打球速度×角度×方向×守備水準→結果）。表は本物の守備の計算から作る | 大 | 近似。全試合と比べて誤差を出してから使う |
| D. クラウドのセッションで並列（1つ4コア・16GB） | 1つにつき+4コア | 同じ |
| E. 守備の計算の無駄を削る（複製と固定化で約15%、送球の計画で26%、試合ごとの57MBの複製で6%） | 1.5〜2倍 | ハッシュ一致で同じ |
- 合格の条件: 打者ごとの打率・ISO・三振・四球・本塁打を、全試合と高速版で比べ、差が標本誤差の範囲であること。

## 2. 史料（並行して集める）
- MLB: 成績は Lahman（1871〜）、打球と体は Statcast（2015〜、バット計測は2023〜）、走力の目安 sprint speed、球場の寸法（年ごと）。
- NPB: OOTP_NPB_Historical（成績、database/ に能力の評価があれば使う）、球場（parks.csv）。
- KBO: 入手先を調べる（OOTP の KBO データ、公式記録など）。
- 時代の打ち方: 攻撃角、ダウンスイングの時代、反発係数の変化（飛ぶボール・統一球）、マウンドの高さ、球場の拡張など、リーグ環境の変化。
- 公開 repo に、データ本体・選手名と個人成績を入れない。非公開 repo `Kneekura-eatenBUGsHouse` の data/ に置く。

## 3. 換算（高速化の後）
- 打者: 三振→時間誤差、四球→選球眼、ISO と本塁打→パワー（バット速度）と攻撃角、BABIP→芯の誤差、盗塁と三塁打→走力。速度×時間誤差の相互作用を表にする。
- 投手: 三振・四球・被本塁打・BABIP から、球速・制球・球種・キレ。
- 守備: 守備率・刺殺補殺・UZR/OAA があれば、守備力・肩・捕球。
- 得能: 左右の成績差、得点圏、得意コース（Statcast のゾーン別、なければ推定しない）。
- すべて kbm-maker で書き、能力値は物差し（84＝MLB平均）で表す。

## 4. 再現の確認
リーグ・時代ごとに、全選手のリーグを回して、リーグ平均と選手ごとの成績を現実と比べる。合わない時代は環境（ボール、球場、ルール）を見直す。
