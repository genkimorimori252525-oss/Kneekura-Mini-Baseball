## 測定の決まり

- 測定の道具は非公開 repo の `cloud/tools/`（`bbreplay.mjs`、`bbtrace.mjs`、`bbsum.py`、`poscfg.mjs` ほか。README あり）。`bbreplay` は MLB の打球を、試合の打球の回転を借りて（GAMESPIN）、打者と同じ側の打球だけ（HAND=1）で再生する。`bbtrace` は1球を追う（FRAMES・AIWHO・GLOVEWHO・COVERDEBUG・RELAYDEBUG の書き出しがある。最後の3つは測定用 worktree に一時的なフックを入れたビルドでだけ働く）。
- 測定用の worktree は、作業 branch のローカル版に守備 branch を取り込んだものを使い、push しない。
- 守備の worktree どうしは測定の出力フォルダーを共有している（junction）。ビルド名は作業場所ごとに分ける（`build-m2-…`、`build-def-…`）。走行中の再生が使う bundle を作り直さない（一度これで5本が止まった）。
- node は番人（guard.mjs）の下、守備の枠は `--slot=node-def:6`（打撃は `node-bat`）。1本 `--max-old-space-size=4096` まで。C: の空きが2〜3GBのときはページファイルが伸びず node が落ちるので、再生は同時3本まで。
- `core-playthrough.mjs` の seed と球数は `--seed=301 --pitches=450` と旗で渡す（並べて渡すと無視され、別のハッシュになる）。
- 型検査（tsc、8GB）は測定と同時に回さない。ブラウザと vitest も同時に回さない。
- 連絡板：区切りごとに `claim`、他の担当への依頼は直接送って `note` に「<担当>へ」と写す。
