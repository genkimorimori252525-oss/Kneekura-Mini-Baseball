## 打球角が攻撃角より低く出る原因（2026-11-04、調査の担当、コードは読むだけで測定）
試合の衝突の直前の入力と結果を書き出して（native のコピーに1行足す、K:/kbm-work/investigate/）、上下のずれ D=0 に置き直して解き直した（攻撃角20°で339件、14°で380件）。
| 条件（指定20° / 14°） | 打球角 | バックスピン |
|---|---|---|
| 試合の状態のまま D=0 | 8.3° / −3.2° | −938 / −1,571rpm |
| 軸方向の滑りを除く | 7.3° / −4.2° | −387 / −973 |
| バットを回して攻撃角＝指定（滑りは残す） | 13.8° / 4.5° | −729 / −1,439 |
| 滑りなし・攻撃角＝指定 | 17.7° / 8.9° | +31 / −572 |
- 衝突の解き方（`RigidBatBallContact.ts` の撃力モデル、e=0.52、e_t=0.30、μ=0.15）は正しい。D=0 の手計算（バット31m/s、投球35m/s・降下−7°、q≈0.2）は攻撃角20°で約17.9°、14°で約12.9°（攻撃角−1〜2°）。
- (A) 約−5.5°: 攻撃角を合わせる基準が、動作データの接触時刻の 'outgoing' の速度（`LivePitchV1.ts` の probeVelocity）。実際は表面が約6.8cm手前（約1ms）で触れ、その間に芯の仰角は約1.4°/ms 変わる。振るタイミングの誤差も重なる。強い当たりほど実際の攻撃角が低い（20°指定で全体18.7°、打球速度145km/h以上で14.5°、理由は未特定）。
- (B) 約−3.9°: バットが自分の軸方向（グリップ側）へ滑る成分が元の動作の約2倍。球を押さず摩擦だけを生み、トップスピンと約1,300rpmの横回転を作る。2倍になる理由は未特定（仮説: heightScale がグリップ位置だけに掛かる、照準の平行移動の速度、接触の時刻のずれ）。
- (C) 約−2.3°: 投球の降下と回転。物理として正しい。
- 'outgoing' の芯の速さは 26.5m/s、'incoming' は 31.1m/s（元の動作に実打撃の減速が入る）。そのため速さの比 rate が約1.17倍に膨らみ、impactScale（平均0.89〜0.93）で頭打ちになっている。
- 試しの切り替え `contactLeadAlignV1`（秒、任意、省略時はハッシュ一致）: 攻撃角を接触の少し前の 'incoming' の速度で合わせる。
- `contactLeadAlignV1` を試した（守備抜き12試合×6通り）: 攻撃角14°で打球角 5.6→6.6°、20°で 11.7→13.0°。横回転は 1,718→1,173rpm（14°）と減るが、ライナーのトップスピンは残り、打球速度は約3mph下がる。効き目が小さいので既定にしない。本命は (B) の軸方向の滑りの原因。

## 振り遅れの接触でバットが遅くなる誤り（2026-11-04）
- 2つ目の調査（K:/kbm-work/investigate2）の結論: 軸方向の滑りが約2倍に見えたのは、表面と中心線の差（約−2°、物理として正しい）と接触時刻の散らばりの足し算。接触の53%は動作データの接触時刻より後で起き、そこでは元の動作に記録された実打撃の減速（約5.6msで30.7→17.6m/s）を使っていた。作られた誤り。該当は `LivePitchV1.ts` の selectedFrames（接触後の followThroughSeconds 分をそのまま使う）。

## 空振りの出どころ（2026-11-05、ピッチング部の確かめ、投手20人のリーグ、各10試合）

- 試合の 90〜100mph のゴロの前回転の中央値: −15〜−30° で 4,886rpm、−5〜−15° で 3,130rpm。打ち下ろしのゴロの安打率は −20〜−10° .319、−20° 未満 .333（MLB .168／.086）。90〜100mph のゴロの安打率 .406（MLB .270）、5〜10° の割合 25%（MLB 12%）。
- 低いライナーが前回転になる件（上の「打球角が攻撃角より低く出る原因」）と根は同じで、打球角のわりに前回転が強すぎる、と見る。打撃（衝突の回転）の受け持ちとして引き取った。守備の反応・持ち替えはこれを根拠に動かさない。
- 角度ごとの回転の実測の表は公開されていない。ライナーと同じく、MLB の結果（同じ 150 球のアウト数）に合う回転を、回転の倍率を掃いて逆に解く。地面の跳ね返り（BallSurfaceContact）が原因の一部かも分けて確かめる。
- 守備部が早く着く送球（throwEarliestArrivalV1）を採用し、試合の既定 082 に足した（80d99c26）。一塁走者ありで2アウト未満のゴロ（併殺／封殺のみ／打者だけアウト／全員セーフ）: 今 .39/.34/.10/.17、E .41/.24/.13/.22、MLB .33/.21/.15/.31。MLB とのずれの二乗和 .043→.016。標準一括3に D と一緒に入れると決めた（推奨どおり）。
- 守備の位置ごとの持ち替えの時間を合わせるのは、ゴロの回転を直してからにする。先に合わせると、強すぎる前回転の分まで持ち替えで吸ってしまうため。先に守備部が 150 球で回転の倍率を掃く（×0〜×1）。
- 107 アウトの再生の回転は固定の式だった（逆回転 = 77×打球角+380rpm、±3000 で頭打ち、横回転・ジャイロ 0。−15° で −775rpm、−5° で −5rpm）。94 アウトは試合の打球から近い球の回転を借りた。正しい回転はこの2つの間にあると読む。
- 地面の値（内野の土：反発 .42・滑りの摩擦 .45・回転の減り .18、接線の反発 .17±.03）は、守備部も測定と照らしていない。史料部に、土・芝での跳ね返りとゴロの回転の実測を探すよう頼んだ。地面の値を変えた再生は、根拠がそろってから。
- ピッチング部の途中報告（直した A、23 試合）: 正しく読んだゾーン内の速球の空振り .123（cr4 .088、A+[1,0] .117、A+[1,0.5] .136）。投手の平均からの縦のずれの大きさで <1in .108／1〜2 .131／2〜3 .146 と、上下どちらでも同じように増える。横のずれでは増えない。符号つきの傾きは −0.01 前後で、MLB の +0.019 と性質が違う。
- 見立て（仮説、未測定）: 外れが縦のずれの大きさに比例して対称に出るのは、読んだ球種の「いつもの曲がり」で先を読むなら当然の形。山の傾き（|ずれ| 1in あたり約 .019）は MLB の符号つきの傾きとほぼ同じ大きさ。MLB で傾きが片側だけに出るのは、打者の予想する伸びが実際より一様に低い（揚力を少なく見積もる、「浮き上がる速球」の錯覚の説明と同じ向き）と読めば説明できる。予想が投手の平均より 2〜3in 低ければ、ずれの分布（sd 1.65in）のほとんどが V の右の腕に乗り、符号つきの傾き約 +.019 になる。試す形: 読んだ球種のいつもの縦の曲がり（揚力）を 1 未満の割合で見積もる任意入力。全体の空振りは増える向き（目安 +.02〜.03）なので、他の直しと合わせて見る。
- ピッチング部の追記（直した A、23 試合）: 遅い見直しの後の縦の外れは、どの区分でも 0.2in 以下（ずれ <−1in −0.01/0.06、−1〜+1 +0.01/0.16、>+1 +0.04/0.18、平均/sd）。符号つきの空振りは .161／.108／.132 で、区分の差は約 1.3SE。A だけの組では、遅い見直しが実際の伸びを読み切るので、伸びは空振りを作れない。この組の区分の差は揺らぎと見る。
- したがって伸びと空振りの関係を見る場所は、伸びを球種のいつもの値で読む A+[1,w] の組。48 試合そろったら、その組で同じ区分（遅い見直し後の縦の外れと空振り）を見る。外れはずれ×(1−w) に比例するはず。空振りが V 字（対称）なら、上の「伸びを少なめに見積もる」案を試す。
- 衝突そのものを確かめた（2026-11-07、`resolveRigidBatBallContact` を直接、バット 31m/s・攻撃角 10°、投球 38m/s・降下 −7°、上下のずれ D だけを変える。スクリプトは git 外）: 回転は打球角 1° あたり約 190rpm で、回転 0 になるのは打球角約 +9°（D≈+0.9cm）。D=0 で −1.7°・−2,135rpm、D=−1cm で −12.8°・−4,205rpm、D=−2cm で −24.4°・−6,230rpm。投球の逆回転 ±2,000rpm は出る回転を ∓370rpm しか動かさない（傾き約 −0.18）。
