## 打球角が攻撃角より低く出る原因（2026-11-04、調査の担当、コードは読むだけで測定）
試合の衝突の直前の入力と結果を書き出して（native のコピーに1行足す、K:/kbm-work/investigate/）、上下のずれ D=0 に置き直して解き直した（攻撃角20°で339件、14°で380件）。
| 条件（指定20° / 14°） | 打球角 | バックスピン |
|---|---|---|
| 試合の状態のまま D=0 | 8.3° / −3.2° | −938 / −1,571rpm |
| 軸方向の滑りを除く | 7.3° / −4.2° | −387 / −973 |
| バットを回して攻撃角＝指定（滑りは残す） | 13.8° / 4.5° | −729 / −1,439 |
| 滑りなし・攻撃角＝指定 | 17.7° / 8.9° | +31 / −572 |
- 衝突の解き方（`RigidBatBallContact.ts` の撃力モデル、e=0.52、e_t=0.30、μ=0.15）は正しい。D=0 の手計算（バット31m/s、投球35m/s・降下−7°、q≈0.2）は攻撃角20°で約17.9°、14°で約12.9°（攻撃角−1〜2°）。
- (A) 約−5.5°: 攻撃角を合わせる基準が、動作データの接触時刻の 'outgoing' の速度（`LivePitchV1.ts` の probeVelocity）。実際は表面が約6.8cm手前（約1ms）で触れ、その間に芯の仰角は約1.4°/ms 変わる。振るタイミングの誤差も重なる。強い当たりほど実際の攻撃角が低い（20°指定で全体18.7°、打球速度145km/h以上で14.5°、理由は未特定）。
- (B) 約−3.9°: バットが自分の軸方向（グリップ側）へ滑る成分が元の動作の約2倍。球を押さず摩擦だけを生み、トップスピンと約1,300rpmの横回転を作る。2倍になる理由は未特定（仮説: heightScale がグリップ位置だけに掛かる、照準の平行移動の速度、接触の時刻のずれ）。
- (C) 約−2.3°: 投球の降下と回転。物理として正しい。
- 'outgoing' の芯の速さは 26.5m/s、'incoming' は 31.1m/s（元の動作に実打撃の減速が入る）。そのため速さの比 rate が約1.17倍に膨らみ、impactScale（平均0.89〜0.93）で頭打ちになっている。
- 試しの切り替え `contactLeadAlignV1`（秒、任意、省略時はハッシュ一致）: 攻撃角を接触の少し前の 'incoming' の速度で合わせる。
- `contactLeadAlignV1` を試した（守備抜き12試合×6通り）: 攻撃角14°で打球角 5.6→6.6°、20°で 11.7→13.0°。横回転は 1,718→1,173rpm（14°）と減るが、ライナーのトップスピンは残り、打球速度は約3mph下がる。効き目が小さいので既定にしない。本命は (B) の軸方向の滑りの原因。

## 投手の能力値と成績の関係（2026-11-04）
投手2人だけを乱数で散らしたリーグ60個（最高球速138〜165km/h、制球55〜110）、守備抜き各8試合（480試合中439完走）。当てはめは120人で偶然の範囲（RMS z 0.42〜1.05）。
- 制球は四球に強く効く（球速148km/h で制球60→105 が四球 .181→.038）。
- 球速の効きが弱い: 制球84で 140→162km/h にしても三振 .185→.212（+2.7ポイント）。被本塁打は .013→.017 とむしろ増える。現実の MLB では速球の球速が奪三振に強く効く。速い球への振り遅れと空振りの効きを直す必要がある（仮説）。投手の逆算はその後。
