守備担当（PC）。branch `claude/defense-mlb-2026-11-03`。入口は `HANDOFF-2026-11-03-cloud-defense-mlb.md` の6章 2〜4。
新しい振る舞いはすべて任意入力。省略時は `--hash=1` で旧ビルドと一致（標準リーグ `cfg-std` と、守備位置ごとの体の設定の2つ、seed 301、450球）。

## 測り方
- 同じ打球を2つの設定で打ち直す対比較（非公開 repo `cloud/tools/pairall.mjs`、seed 301〜304、安打以外も全打球）。PC では同じ場所の `gpairs.sh` で、共通の番人の `--slot=node:3` の下で回す。
- 設定は `tools/calibration/defaults.mjs` で試合の既定から作った `cfg-std` を元にする。MLB の体は非公開 repo の `mlbcfg.mjs`（全員 27.3ft/s、守備位置ごとの肩）と `poscfg.mjs`（下の1）。
- Statcast の値は 2025年の Savant の CSV（running splits、sprint speed）を自分で集計した（競技走 50回以上の正選手）。リーグの集計値だけで、選手個人の値は公開 repo に置かない。

## 2. 走り出しの形（`locomotionStartV1`、任意）
- 速度帯の形は 3段のまま、境目と倍率を Statcast に当てはめた: 最高速の 45%・75% で区切り、`accelerationMps2` の 1.393・.348・.209 倍（今は 25%・65%、1・.7・.35）。fieldKinematicsV1 の走者の倍率 1.54 はそのままなので、同じ能力から読む減速と横の加速は変わらない。
- 走者（27.39ft/s）: 5ft .64→.55秒、10ft .94→.86、30ft 1.81→1.81、90ft 4.00→4.03（Statcast .55／.87／1.80／4.03、18点の rms .006秒）。守備位置ごとの平均も同じ形で rms .009秒以内。
- 野手も同じ形を使う。内野の10ヤード 1.74→1.75秒、外野の3秒 34.5→34.5ft で変わらず、速くなるのは最初の1m前後（構えの倍率で最初の0.5秒 1.04→1.39m）。
- 1プレーの間だけ有効な形として、そのプレーで作る全てのプロファイル（野手・走者・到着の見積もり）に同じ形が入る（`withLivePropulsionShapeV84`）。計画と動きが食い違わない。fieldRangeV1 と fieldKinematicsV1 が要る。
- 直したもの: `LiveFielderAvoidanceV1` の止まっている選手の加速の上限が `accelerationMps2` のままで、第1帯が能力を超える形だと全打球で守備が落ちた（安打0、`unresolved` 46本）。第1帯の値を上限にした。今の帯では同じ値なので旧結果は変わらない（ハッシュ一致）。
- 盗塁の競争（`resolveStealV1`）は帯を使わない一定加速の別のモデルなので変えていない。
- 対比較（守備位置ごとの体、fieldKinematicsV1 あり → 走り出しあり、同じ打球 198）: 得点 20→24、アウト 148→150、単打で二塁走者の生還 2/6→4/6、一塁走者ありのゴロの併殺 5/12→6/12、ゴロアウト→安打 5本。結果が変わった打球 33。

## 3. カバー（`fieldCoverV1` を作り直し、任意）
- 塁も打球も守備位置が持たない。各野手が自分の見た状況で、打球を追う者の集合と塁ごとのカバー役を一緒に選ぶ（`assignLiveFieldCoverV1`）。選ぶ基準は期待失点:
  `P(追う誰かが打球を処理する) × (そのカバーで取れる最良のプレーが減らす失点)`。
- 最良のプレーは、保持者が fieldRunValueV1 で選ぶのと同じ形で比べる。1つの塁のアウト、または併殺。塁のアウトは「送球が着く時刻とカバーが着く時刻の遅い方」と走者の競争。送球は、追う中で最も見込みの高い者が打球を取る地点から、持ち替えの後に投げる。併殺は中継役の持ち替えと送球を足す。勝つ見込みは fieldRunValueV1 と同じ競争の式（広がり .15秒）。
- 打球を処理する見込みは、各野手の予測の余裕から出す。間に合う者は、最初に届く点ではなく、その先 .2・.4・.6秒の通り道での最大の余裕を使う（正面の打球ほど確実になる）。飛び込み・伸ばすだけの者は遅れから。
- 期待失点の表は fieldRunValueV1 の NPB 2015-17 の表を、この方針が無いときもデータとして使う。リーグが較正できたら試合で測った値に替える。
- 最初の版（各塁の価値の足し算、期限は走者の到着）は、二塁に3秒かかる者でも一塁走者の封殺には間に合う計算になり、二塁手を打球へ回して併殺を落とした（同じ打球 208 で併殺 7/19→3/19）。遊撃手が遅れる受け手に合わせた弱い送球（11.8m/s）を投げていた。送球とカバーの遅い方と、併殺の転送まで含めた今の形で、その2本は併殺に戻った。
- 旧版（クラウド、間に合う最初の捕球時刻を基準にする規則）の対比較（守備位置ごとの体、同じ打球 198）: 得点 20→20、アウト 148→151、併殺 5/12→7/12、結果が変わった打球 7。seed 304 の249球目は、この設定の試合では中堅フライで、三遊間のゴロは再現しなかった（試合の設定が違うため）。
- 役を変える損: その塁へ向かっていると分かっている者（自分は前回の役、他人は掛け声）がいるとき、ほかの者はその塁に既存の `switchCostSeconds`（.25秒）遅れて着く扱いにした。
- 今の版の対比較（守備位置ごとの体と走り出しあり → さらに fieldCoverV1、同じ打球 208）: 得点 21→22、アウト 155→151、安打 54→54（崩れた打球なし）、併殺 7/19→5/19、安打中のアウト 1→0、結果が変わった打球 8。役を変える損を入れる前と後で、8本とも同じ結果だった。
- 落ちた併殺2本の中身:
  - seed 303 の151球目: 三塁ゴロ。捕球前の .3〜.7秒に、二塁へ入る役が遊撃手と二塁手の間で入れ替わり続け、二塁手が二塁に入りきる前に三塁手が一塁へ投げた。各野手の見え方で二人の二塁までの時間がほぼ同じなため。役を変える損では消えなかった。掛け声が届くまでの遅れの間に起きている、と見ている（仮説、未確認）。
  - seed 304 の40球目: カバーは両方同じ（二塁に二塁手、一塁に一塁手）で、中継も比較側が早い。打者走者が比較側では一塁に 4.30秒で着き、基準では 4.53秒までに着いていない。カバー以外の経路（走者の判断）と見ている（仮説、未確認）。
- 判断: 決め打ちの順は無くなり、安打は崩さなくなったが、併殺が減る。**既定にしない**。

## 5. 打ち切られた試合を続きから（2026-11-04、本人の希望、打撃担当の了解済み）
- `tools/calibration/games.sh`: 番人の上限 1200→2400秒（`MAX`）。番人は枠の待ち時間も上限に数えるため。打ち切られた試合は、25球ごとの続きの状態から `TRIES`（3回）まで自動で再開する。`RESUME=1` で、前の呼び出しが残した状態からも続ける。
- `tools/release/core-playthrough.mjs`: `--checkpoint=<file> [--every=N]` と `--from=<file>`。再開のとき記録ファイルを保存時点の長さへ切り戻すので、通しで打ったのと同じ記録になる。終わりの試合状態の digest を `FINAL` で出す。両方とも省略すれば今までと同じ（`--hash=1` が旧コードと一致、seed 301、150球）。
- `--hash=1` は SHA-256 の途中状態を保存できないので、再開をまたいだ一致は「記録ファイルの完全一致」と `FINAL` の一致で確かめる。
