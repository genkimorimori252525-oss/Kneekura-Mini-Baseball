# Evaluation — Opus単独 vs Opus+Sonnetを公平に測る

## 比較する3構成

A. **Direct Opus:** Opus 5.5 medium/highが計画→実装→テストを一つの文脈で行う。

B. **Hybrid:** Opus 5.5 medium/highが計画・受け入れを担当。独立した通常実装はSonnet 5.5 mediumに限定して委任。難しい仕事はOpusへ戻す。

C. **opusplan:** 公式 `opusplan` でPlanモードはOpus、ExecutionモードはSonnet（個別サブエージェントとは別方式）。

## 手順

- 同じリポジトリ、同じ開始コミット、同じ要求仕様、同じテスト、同じ権限と使用可能ツールで開始する。各構成は別worktree/作業コピー。
- まず12件程度の代表タスクを用意し、(小さい/大きい、独立/密結合、難易度)に偏りがないよう分ける。できれば各条件の反復試行を増やす。
- 課題順序を入れ替え、3構成の試験実施順によるバイアスを軽減。ベンチマークのタスク内容を途中で変えない。
- 改善に必要な手戻りとオーケストレータのレビュー作業も**総コスト**に含める。
- 偽のコストを計算しない。実測した時間と使用量のみ記録する。月額プラン利用時はGitHub/API換算のドル費用とClaudeのプラン使用枠を混同しない。

## 記録項目

| 指標 | 取得方法 | 解釈上の注意 |
|---|---|---|
| 完了率 | 同じ自動テスト+受け入れ基準 | 試験前に固定する |
| 回帰率 | 既存のテスト・再現手順 | 単独では重大度を表さない |
| 手戻り回数 | 修正後の再試行・Opusによる修正 | Sonnetだけのツール実行数では不足 |
| 経過時間 | 実際の計測 | 並列実行は壁時計時間で比較 |
| 総トークン/利用量 | Claude Code提供の観測可能な使用情報 | キャッシュ・副エージェント分を含める。取得不能なら欠測 |
| API換算費用 | 計測値×実際のAPI料金表 | 定額プランの課金額とは別 |
| 品質・保守性 | ブラインドレビューと回帰テスト | 変更ファイル数の多寡だけで判定しない |

## 最終判断の基準

- **Directを残す:** 小規模・順次修正でHybridの手戻りと時間が増える場合。
- **Hybridを増やす:** 独立タスク群でDirectと同程度の合格率・回帰率を保ちつつ、時間や使用量に再現可能な利点がある場合。
- **Opus workerへ切り替える:** 安いモデルの手戻りで総費用が増えた場合。
- **保留する:** サンプルが少ない、環境が変わった、モデルが違っていた、記録が欠損した場合。

この結果を `LESSONS.md` に短く残し、ポリシー変更は承認制にする。性能改善は現在のタスクで測ることが最重要。
