This bounded successor implements one same-half continuing terminal foul-bunt strikeout with empty original and next bases. It requires an explicitly accepted setup Source, the existing deterministic official score and all ten original TOTAL workload effects. It does not establish half-change/final-game handling, autonomous next-batter selection, a second completed-prior chain, a new calibration, or a playable game/UI.

The original physical owners, rule/official journal, terminal Source/proposal, pending official receipt/origin, acknowledgement and official revision remain unchanged. A successful completion updates exactly three existing rows: the shared official writer updates the application result and Match activation; the terminal runner updates its own stage/result. There is no new application INSERT or revision increment.

## Effects and atomicity

A completed read authenticates the original immutable acknowledgement and every exact original scoring/workload effect. Completion references bind the canonical scoring row and frozen workload plan/participant AFTER history, excluding mutable current-head hashes. Missing completed effects are rejected; reads and historical retries never repair them.

Fresh completion captures accepted input and dependency/counter/schema evidence, rechecks it on the writer connection, performs three CAS updates, reauthenticates the resulting mirrors/effects, and checks exact write counts before commit. A narrow durable readback then compares all three owned rows, including row identity, after COMMIT. COMMIT replacement, uncertainty or failed cleanup cannot produce a successful reusable handle. The shared fresh apply/acknowledge paths use the same owned-result readback. Exact completed apply/acknowledge/complete/enqueue retries use archived authority and invoke no acceptance callback.

Contiguous scoring history has an explicit completed-terminal branch. It authenticates completion/effects, the immutable pending scoring input, contiguous revision, the current archived application envelope and the exact seven-column scoring hash. The complete Native history row-selection/proof interval uses the existing read snapshot/traversal bracket. Generic legacy scoring and pitcher-only workload writers remain blocked for terminal mode.

## Readiness integration

Terminal readiness has its own exact versioned reference in the next actor origin, separate from `actualLiveReadiness`. IDs, hashes, game, previous play and consuming next play derive from the authenticated completion. Current admission separately checks Match/world and authenticated allowed workload history. Historical reads do not authorize stale current writes.

The shared prior-scope census resolves each retained original game/play independently to one authenticated terminal completion or existing live closure. Earlier unresolved scopes and dual ownership reject. Ancestry stays within one game, strictly backward, with explicit active-reader re-entry guards. Actor and pitch writers recheck terminal readiness on their own connections at pre/post-write boundaries.
