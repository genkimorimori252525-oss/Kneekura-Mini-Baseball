# Actual-live frame setup routing

## Bounded implementation

`battedWorldFrameBaseCenters` now resolves an actual-live activation through its original authenticated closure and historical readiness. The original physical frame's actor, application, game, play, revision, activation, World and fixture must agree. The setup comes from that closure's accepted Source; neither raw scoring JSON nor the current workload head becomes setup authority.

Initial-world and genuine legacy-scoring routes remain supported. A compatible independent actual-live score can coexist, but matching scoring claims must authenticate through their existing scoring owner. Missing, conflicting, hidden or corrupt claims reject without fallback. Native reads preserve the caller's transaction or own a bounded read snapshot with checked acquisition/completion and cleanup.

Only `SqliteBattedWorldBaseGeometryStore.ts` changes in production. No schema, calibration, persistent cache, physical traversal policy or PR361 v1 participant binding changes.
