# Pitch Arsenal Development System — Planned Design

更新日: 2026-10-07  
対象branch: `jolly/core-foundation-plan-2026-09-17`  
Status: **PLANNED / DESIGN PRINCIPLES FROZEN v1**  
Implementation: **NOT STARTED**  
Calibration / formulas: **NOT FROZEN**

## Purpose

Mini Baseball の投手育成で、球種数そのものを強さにしない。
同時に、「5球種まで」「新球を覚えると既存球が弱くなる」のような人工的制限も置かない。

球種の価値は、習得・習熟・球質・既存球種との差・配球上の意味・実戦での信頼性から生まれる。

---

## Frozen Design Principles

### 1. 球種数の固定上限を設けない

習得可能球種数に原則ハードキャップを置かない。

禁止例:
- 5球種まで
- 6球目は習得不可
- 7球目から既存球種にペナルティ

多球種投手は例外ルールではなく、育成履歴と実戦運用の結果として成立させる。

### 2. 個人ごとの隠し球種レベル上限を設けない

「この投手のチェンジアップ上限は47」のような、ユーザーから観察できない固定上限は採用しない。

Mini Baseball では現実の握り・指・リリース感覚・細かなフォームを直接観察できないため、見えない身体適性を理由に長期練習を失敗扱いにするのは不公平である。

**ユーザーに原因を観察・理解できない失敗を強制しない。**

### 3. 新球種習得で既存球種を直接弱体化させない

新しい変化球を覚えたことだけを理由に、既存球種の球威・制球・完成度を下げない。

能力低下を球種数の帳尻合わせに使わない。

### 4. 制約は有限の育成時間と機会費用に置く

主なコストは能力スロットではなく、時間と練習機会。

同じ期間に、

- 新球種習得
- 既存球種改善
- 制球改善
- 球速向上
- スタミナ強化
- フォーム調整
- その他の投手能力育成

をすべて最大化することはできない。

したがって、新球種追加は可能でも常に最適とは限らない。

### 5. 「覚えた」と「武器になった」を分離する

球種を覚えた瞬間から完成品にはしない。

概念上は、

1. 未習得
2. 試作 / 練習中
3. 投球可能
4. 実戦投入可能
5. 信頼できる持ち球
6. 武器 / 決め球級

のような段階を持てる構造にする。

段階名・閾値は未Freeze。

重要なのは、**所有球種数と実戦 Arsenal を同一視しないこと**。

### 6. 球種数そのものに能力ボーナスを与えない

「7球種だから Overall +5」のような直接補正は採用しない。

新球種の価値は、既存 Arsenal に何を追加するかで決まる。

候補評価軸:
- 球速差
- 横変化差
- 縦変化差
- 軌道差
- 左右打者への対応幅
- カウント別の役割
- ゾーン内外の役割
- 既存球種とのトンネル / コントラスト

似た役割の球を増やしても追加価値は小さくてよい。

### 7. Arsenal Coverage を球種数と分離する

仮称 **Arsenal Coverage**。

「何球種あるか」ではなく、「投球空間をどれだけ異なる方法で攻められるか」を表す分析概念とする。

将来候補:
- velocity separation
- horizontal movement separation
- vertical movement separation
- location role
- batter handedness coverage
- count / situation coverage

算式は未Freeze。

### 8. 多球種の強みは選択肢と予測困難性

多球種投手の主な利点は固定能力値上昇ではなく、

- 同じカウントでも候補球が多い
- 左右打者で Arsenal を変えられる
- 打順が進んだときに見せ方を変えられる
- 一巡目に見せなかった球を後から使える

こと。

一方で、2球種でも両方が圧倒的なら非常に強い投手になれる。

**少数精鋭型と多球種型の両方を成立させる。**

### 9. Arsenal と配球能力を分離する

球種を持っているだけでは最大価値を発揮しない。

価値は概念的に、

**Pitch Quality × Differentiation × Command / Reliability × Tactical Usage**

の組み合わせで生じる。

配球AI / 監督AIは、打者・カウント・左右・巡目・状況から実戦 Arsenal を選択する。

### 10. 基礎能力を維持税にしない

長期間使わなかったことだけを理由に、習得済み球種の基礎能力を恒常的に大きく削らない。

多数球種を維持するだけで練習枠が消える「維持税ゲーム」は避ける。

必要なら、
- 試合勘
- 再現性
- 怪我明けのコマンド不安
- フォーム変更直後の不安定
- オフ後の軽微な錆び

のような **回復可能な一時状態** は許可する。

### 11. 選手の個性は育成履歴から生む

隠し球種適性上限に頼らず、

- 入団時の持ち球
- 練習履歴
- どこへ時間を投資したか
- 実戦で何を使ったか

から投手タイプを形成する。

例:

- Pitcher A: elite Four-seam + elite Slider の少数精鋭型
- Pitcher B: 6球種を高水準で使う多球種型

どちらも成立してよい。

## User Fairness / Explainability Rule

以下は禁止する。

- 非表示の球種別最大レベル
- 非表示の「この選手には絶対無理」判定
- 十分な説明なしに何シーズン練習しても伸びない状態
- 新球種習得による既存能力の自動減点

成長が遅い場合は、UI / レポート / コーチ評価などで理由を説明可能にする。

例:
- 他の育成項目へ時間を割いている
- まだ実戦で再現できない
- フォーム変更中
- 制球が追いついていない

**「テスト結果を返さず赤点扱い」にしない。**

---

## Match / AI Integration Direction

将来のAIは全球種を均等使用しない。

例:
- 1巡目: Four-seam / Slider 中心
- 2巡目: Changeup 追加
- 3巡目: Splitter 初提示
- 左打者: Cutter 増加
- 追い込み: 最も信頼できる put-away pitch を優先

新球種は能力値を増やすものではなく、**意思決定空間を増やすもの**として扱う。

## Deferred / Not Frozen Yet

以下は実装・検証時に決める。

- 練習時間 / ポイントの具体単位
- 習得条件
- 習熟速度
- 各段階の閾値
- command / reliability の詳細式
- Arsenal Coverage の算式
- 球速差・変化量差の価値関数
- pitch tunneling 評価
- times-through-order への具体影響
- AI 球種選択重み
- 一時的 rust の大きさと回復速度
- UI 表示
- CPU育成AIの優先順位

## Future Implementation Acceptance Principles

1. 2球種の超一流投手が成立する。
2. 6〜10球種を意味のある形で使う特殊投手も成立する。
3. 球種を増やすだけでは自動的に最適解にならない。
4. 新球種を覚えても既存球種が理由なく弱くならない。
5. 長期育成が隠し上限で無駄にならない。
6. 球種追加の価値を既存 Arsenal との差から説明できる。
7. AI が球種数ではなく状況と配球価値を見て選択できる。
8. プレイヤーが「なぜ伸びない / なぜ使わない」を理解できる。
9. 育成履歴から現在の投手像を説明できる。
10. 将来数式を変更しても、上記設計原則を壊さない。

---

## One-line Rule

> **球種を増やすことは自由。しかし、増やすことそのものを正解にはしない。**
