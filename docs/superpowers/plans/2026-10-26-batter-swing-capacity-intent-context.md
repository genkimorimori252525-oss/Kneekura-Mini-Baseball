## 0. 結論：この会話で決まったこと

**打者の身体能力・技能は「実行できる運動の範囲」を決め、本人の長期的な打撃方針と一球ごとの判断は「その範囲でどの運動を試みるか」を決め、実際に成立したスイングとバット・ボール接触が結果を決める。**

この原則を以下のように具体化する。

1. 高いパワーは、一般に高いバット速度・加速度や強い打球を実現し得る能力と関連する。ただし**公開パワー数値から接触時のスイング速度を直接算出しない**。
2. 「速く振れる最大能力（能力上限・実行可能領域）」と「その球で実際にどの速度・軌道で振るか」は別。高パワーの打者が毎球全力で振る必然性はない。
3. スイング速度は純粋な筋力だけでなく、身体各部の協調、動作効率、バット特性、選んだ軌道、可動域、準備時間、投球への修正、疲労などの結果として生じる。
4. **強振／ミートを二つの固定アニメーションや固定速度の物理クラスに分けない。** 既存の `POWER_SWING` / `CONTACT_SWING` などのラベル・好みは、候補となる「打撃方針」を表す。内部には連続的な実行目標と実スイングを置く。
5. ミート重視は必ず低速とは限らない。コンパクトにして可動域・タイミング修正・芯への再現性を優先しながら、十分に速く振る打者も成立する。
6. 遅く振ること自体に無条件の命中補正を与えない。遅く振ることで修正余地が増える場合があっても、逆に球速やタイミングによって遅すぎて間に合わない場合もある。
7. 高い身体能力・接触技術を持つ打者は、通常より控えめの速度でも十分な打球初速・角度を生み、ホームランを打ち得る。ただしホームランは**投球と接触の物理から成立したときだけ**認め、保証しない。
8. 非力な打者も全力の強振を選べる。**本人の最大限に近い**という意味であり、別人の平均的なミート速度へ瞬間的に底上げしない。
9. 強い選手のミート打ちが弱い選手の全力強振より速いことがあり得る。`POWER_SWING` は絶対速度カテゴリではない。
10. 同じパワーでも、最大バット速度、加速度、打撃時の再現性、身体とバットの結合、エネルギー伝達が異なる個性を認める。逆に同じバット速度でも打球の強さ・質は一致しない。
11. **同じ打者でも状況に応じて方針を変える。** 「初球に長打を狙い、2ストライクではコンパクト」が可能。ただし全打者・全打席に強制する決定規則ではない。
12. 速いスイングを日常的に好む打者、コンパクトに徹する打者、カウントで大きく使い分ける打者、使い分けない打者など、本人固有の傾向を表す。
13. `強振多用` / `ミート多用` はGreen Traitとして**長期のDefault Preference**を示し、筋力や結果に直接Buffしない。`積極打法` / `慎重打法`（振る／見送る傾向）とは別の軸。
14. 監督のSoft DirectiveやHard Signは既存`49-manager-architecture-v1.md`に従う。指示に応じてその球の意図は変わるが、本人の長期傾向を消去しない。
15. 球種・コースの主観的予測、方向への狙い、振る／見送る判断、目標スイング、実際の運動、接触結果を混同しない。
16. すべての結果は正史物理に従う。パワー・ミート・Trait文字列や結果ラベルによる直接的な打率・長打率・飛距離の後付け補正を禁止する。
17. 描画形式、描画FPS、Mini/Naturalカメラ差によって正史バット速度、接触、結果、公式記録を変えない。

### 0.1 重要な補正：「パワーが高いほど必ず最速」ではない

本会話の「パワーが高いほど、出そうと思えば速いスイングが可能」は、**一般傾向・潜在能力の表現**であり、任意の2名の公開パワー1〜100から最大バット速度の厳密な順位を強制する意味ではない。公開パワーはリーグ文脈での複数の真の技能Sourceから導く要約である。同一リーグ・同条件で真の加速能力Sourceだけを高めた場合には、物理的に実現可能な速度領域が狭まらないようにする。一方、元Sourceの内訳が違う選手間では速度と公開パワー順位の逆転も合法。

### 0.2 何を決定し、何をまだ決めないか

- **会話で合意済み**：能力上限と実際のスイングの分離、選手個人の方針、状況適応、非二分の物理、同じ能力でも打ち方に個性、因果的接触。
- **既存CANONICALに従う**：公開能力は原因のProjection、GreenはDefault Preference、監督の指示権限、既存Trait Family、方向意図と実結果の区別、共通Match Core。
- **本書の実装提案**：後述のデータ契約、候補モーターパラメータ、決定トレース、段階作業、受け入れテスト。これはまだ実装済みを意味しない。
- **未校正／未確定**：最大速度・加速度の分布、スイング努力量から速度への写像、投球状況に応じた方針の重み、可動域と修正量、接触有効質量の人別推定、モデルの実測精度。例示数値を史実選手の真値にしない。

## 2. 物理能力・打撃技術・意思決定の責任分離

### 2.1 身体とバット：実行可能な運動（Capacity / Feasibility）

既存の真の身体・技能Sourceを使い、**条件付きの運動可能領域**を表す。

- バットの接触部位で達成できる速度域（sweet spot/実接触点の速度は別々に測る）。
- 関節・体幹・腕・手首が生み出せる角加速度／トルク、加速と減速の限界。
- 速度へ到達するために必要な時間、始動状態、可動域、姿勢、左右、バット質量・長さ・慣性。
- スイングの途中修正で失う時間、速度、姿勢安定性の制約。
- Condition / 疲労など実際の身体状態に基づく発揮可能量。ただし基礎技能の永久書換えではない。
- 打球への運動量移動は、既存の剛体／有効質量／反発／芯位置／当たり方等で表現する。同じ源技能を「パワー+」「弾道+」として再加算しない。

**最大速度は無条件の定数ではない。** バットや狙う接触位置、準備時間、体勢が違えば同一打者の実行可能上限も違う。「能力上限」を単独1数値の絶対天井ではなく、必要なら状況に条件づけられたenvelopeとして扱う。

### 2.2 技術：その運動をどれだけ正確に実行できるか（Execution Skill）

- ミートの真Source：軌道・面・始動時刻・芯位置の再現性、身体的に可能な範囲の時間／空間修正。
- パワーに関係する真Source：速度・角加速度の発揮、身体からバットへの力の伝達、長打に適した接触運動。
- 方向・球種・高さ・コース・悪球打ち・粘り打ち等は、既存の技能Sourceが対応する実動作で働く。Trait文字列だけで結果を発生させない。
- 高速でも正確な打者、減速しても下手な打者、速度より軌道選択に優れた打者を表す。**高速＝低ミート／低速＝高ミート**の固定式を禁止する。
- 技術が優れていても可動域と反応時間の限界は超えない。

### 2.3 長期の打撃方針（Slow Default Preference）

以下は**本人の好み／戦い方**であって、身体能力ではない。

- いつも速度・強い接触を優先しやすいか、芯への再現性・修正余地を優先しやすいか。
- どれくらいコンパクトに振ることを好むか（スイング速度とは別軸）。
- カウント、球種予測、狙いゾーン、ランナーや点差によって方針をどの程度変えやすいか。
- 狙い球へどれほど事前準備を固定するか（既存 `priorReliance` 等）。
- 自分の好みを貫くか、状況・監督・観測に柔軟に対応するか。ただし既存の心理・人格・判断Sourceを二重に作らない。

Greenの `強振多用 / Balanced / ミート多用` はこのSlow Preferenceを簡潔に表示したもの。新しい公開能力「力加減」「スイング速度」「打撃哲学」などを増設するのではなく、必要な内部設定と深掘りの観測情報で表現する。

**一度の打席で2ストライクになっても本人のGreen Traitをミート多用へ書き換えない。** 長期の好みの変化は練習・経験・戦略学習等、既存Lifecycleに沿って徐々に起こる。

### 2.4 その球の打撃方針（Pitch/Plate-Appearance Intent）

本人のSlow Preferenceに、以下の**その時点で観測・推定可能な情報**を合成する。

- カウント（初球か、2ストライクか等）、得点差、イニング、アウト、走者、必要な得点・進塁。
- 本人が見た球速／球種／軌道／コース／高さと、未確定な主観確率分布 `BatterPitchBelief`。
- その日の調子・身体疲労・直前のスイングから得た学習、投手への慣れ、守備配置の観測。
- 本人の狙う方向 `DirectionIntent`（PULL / CENTER / OPPOSITE / REACTIVE）とその長期方向Preference。
- 監督の既存Game Plan・Soft Directive・Hard Signと伝達・理解・信頼の境界。
- バント、カット、見逃し、ハーフスイングなど、既存の合法アクション。

例：初球で長打を狙う打者が2ストライクではコンパクトに変更する。**これは許容される個別方針であり、`strikeCount=2` なら全員 `CONTACT_SWING` とする決め打ちではない。** 2ストライクでも本来の強振を続ける打者、初球でも球をじっくり見極める打者がいてよい。

### 2.5 実際の運動（Actual Motor State）と結果（Outcome）

方針は目標でしかない。実際の運動は時刻順に、可動域・トルク・姿勢・速度・減速／修正制約を通って生成する。途中で修正、強振から当てる方向への意図変更、見送り／ハーフスイングに移行することは可能。ただし**その時点で物理的に間に合うときのみ**。

実打球は`BatterSwingState(t)`×`PitchWorldState(t)`→一つのContact Solver→`BattedBallInitialState`（打球初速、角度、回転）→球道・守備・ルール・公式結果の順。結果を決めてからバット軌道を合わせ込むことは禁止。

## 3. 「強振」と「ミート打ち」の意味を精密化する

| 論点 | 強振寄りのIntent | ミート寄りのIntent | 絶対に固定しない点 |
| --- | --- | --- | --- |
| 目的 | 強い接触／長打の可能性をより重視 | 接触の再現性／対応・修正余地を重視 | 強振=本塁打、ミート=安打ではない |
| 努力量 | 自分が使える加速能力を大きく引き出そうとする傾向 | 必要な範囲で速度を調整しようとする傾向 | 強振の絶対速度 > 他人のミート速度とは限らない |
| 軌道 | 狙った接触位置・角度へ積極的に振りにいく | コンパクトな経路や修正可能性を重視し得る | コンパクト=必ず遅い、とはしない |
| 時間・修正 | 場合によって早いCommit・小さい修正余地 | 場合によって修正余地を優先 | tradeoffの大きさは運動学から導く |
| 結果 | 成功すれば強い打球、空振りもあり得る | 芯に当たれば強い打球、空振りもあり得る | 安打率や飛距離の直接補正は禁止 |

**UI / 既存Trait用のモード名は残す。正史Motor層を二分しない。** 例えば同じ `CONTACT_SWING` でも、技術的に高速のコンパクトスイングを実行できる打者も、ゆっくり振ろうとする打者も成立する。

モードごとに絶対m/sの表や物理エンジンを新設しない。高い速度を意図していても、差し込まれた／途中で判断変更した／バットの重さに対応できなかった／疲労していた場合、実現速度が下がり得る。逆にコンパクト狙いでも正しい準備で十分速く振れ得る。

### 3.1 スイング強度は連続的な目標、速度は運動結果

以下は**内部契約の概念例**。項目は既存BAT/DIRの型に統合し、重複パラメータを作らない。数値レンジ・公式は未校正。

```ts
// Conceptual contract only. Not a new parallel engine.
type SwingMotorTarget = Readonly<{
  modeLabel: 'POWER_SWING' | 'BALANCED' | 'CONTACT_SWING';
  desiredEffort: number;             // 連続的な「使いたい出力」。実接触速度そのものではない
  desiredCompactness: number;        // 軌道長・経路選択の好み。速度と独立
  contactControlPriority: number;    // タイミング・芯・軌道再調整の優先度（Buffではない）
  targetContactRegion: unknown;      // 既存BAT/DIRの実際の狙い・幾何データを参照
  requestedStartTime: number;        // 観測時刻に合法な意思決定から導出
  sourceIds: readonly string[];      // 真の原因・方針・指示の追跡
}>;

// Actual physical state is still the existing BAT/NATIVE model:
// BatterSwingState(t) with pose, linearVelocity, angularVelocity.
```

※ 上記 `number` は概念記法。0〜1の採否・各項目の独立性・具体的な座標型・時間単位は、既存の型と実測の識別可能性を監査して決める。`desiredEffort`を `maxSpeed * effort` に機械的に置き換えず、時間発展する加速／減速、バット慣性、軌道、可動域から`ActualSwing`を作る。

### 3.2 打席内の時間順

```text
真の身体・技能Source ＋ バット／身体状態（可動域・トルク・慣性・時間）
                     ↓ 実行可能なMotor Envelope
本人のSlow Preference ＋ 本人の主観的な次球予測 ＋ 現在の試合Context
                     ＋ 監督指示／方向狙い
                     ↓
           当該球のSwing/Take/Plan/Commitの意思
                     ↓
  観測された球道に応じた準備／開始／加速／修正／減速／中止
                     ↓
            実際のバットの姿勢・速度の時系列
                     ↓
        空間・時間上のContact / Miss / Take / Check
                     ↓
    実接触時の相対速度・芯位置・有効質量・反発から打球生成
                     ↓
       物理球道→守備・走者・ルール→公式記録
                     ↓
   観測できた事実だけで本人・捕手・監督の将来Beliefを更新
```

時間の向きを逆転させず、未来の正解球道を打者の私的予測へ注入しない。バットが静止状態から最大速度へ瞬間移行する／速度を突然反転する／振り出し後に無制限に姿勢修正することも禁止。

## 4. 個性と状況適応：必要な再現ケース

以下は**設計上成立させるパターン**であり、実在選手の確定査定や必ず発生させる結果ではない。

| 打者像・状況 | 本人の特性／Intent | 期待する因果関係 | 禁止する近道 |
| --- | --- | --- | --- |
| 高パワー・普段は抑えめ | 高い物理上限、低～中の通常努力量、安定した軌道 | 余裕を残して打ち、物理条件が揃えば長打も可能 | 「高パワーなら常時フルスイング」 |
| 高パワー・常時高速好み | 高い上限、強振寄りのDefault | 多くの球で速度を引き出すが、状況・対応で例外あり | 「高パワーだから性格も積極」 |
| 非力・フルスイング | 低い上限、強振寄りのDefault | 自分の限界近くまで加速、別人の平均速度を強制しない | 「弱い打者の強振=他人のミート平均速度」 |
| 高速コンタクト巧者 | 高い運動・制御技能、ミート重視 | コンパクトで正確、なお接触速度は高い場合あり | 「ミートモードの速度は全打者一定」 |
| 同じバット速度・異なる打球 | 同じ局所速度だが接触点、姿勢、回転、慣性、反発などが異なる | 打球初速や角度が異なり得る | 「バット速度が同じなら飛距離も同じ」 |
| 初球に長打、2ストライクでコンパクト | 同一打者のCount別方針 | Count変化で当該球の目標が変わる | Greenの恒久値を書換え、万人に固定ルール |
| 2ストライクでも強振 | 本人の長期好み・局面・指示 | 追い込まれてもあえて長打を狙う | 「追い込まれたら強制ミート」 |
| 初球でも慎重 | 本人の選球判断とSwing Modeは独立 | 見逃す、待つ、狙う等が可能 | 「初球なら全員強振」 |
| 監督がミート重視を指示 | 本人は強振多用、Soft/Hardは既存権限 | 理解・受諾に従って今回のIntentが変化、Slow値は維持 | 監督の指示で打球を安打へ変更 |
| 予想外の変化球 | Pitch Beliefから外れ、残り時間少 | 振り遅れ、修正、見逃し等に分岐 | 未来の球道を読んで必ず合わせる |
| 引っ張り狙いだが流し打ち結果 | 実接触が狙いとズレる | 相対運動で逆方向打球も生じる | DirectionIntentを実打球角度へ強制変換 |
| ミート重視で本塁打 | 十分な実接触速度、芯、打ち出し角、条件 | 物理的に本塁打になる場合のみ発生 | CONTACTなら本塁打禁止／必ず安打 |

### 4.1 デフォルトと当日の可変量を混ぜない

- **Slow**：普段の選好、カウント別対応傾向、練習で変わる技能、長期的なスイング哲学。
- **Game/Plate**：監督Game Plan、投手との対戦学習、状況、Condition、疲労。
- **Pitch**：その球の主観予測、狙い、目標努力量／軌道、振る／見送る意思、実行時刻。
- **In-motion**：既に成立した姿勢・速度と、時間的に可能な加速・減速・修正。
- **Observed**：実際のバット速度、接触、打球、公式結果。観測結果から過去の意図を遡及確定しない。

## 5. 公開能力・既存Traitへのマッピング

| 既存表示・技能 | 本書における役割 | 禁止事項 |
| --- | --- | --- |
| `パワー`（リーグ相対Projection） | 速度・加速度・力の伝達・打球生成技術・身体状態等の真Sourceの要約 | `power / 100`をスイング速度や本塁打率に直接掛けない |
| `ミート`（同上） | タイミング／バット面／軌道／芯への制御技術の要約 | CONTACT選択だけでHit確率加算・全員定速 |
| `選球眼` | 実際のゾーン認識・スイング判断の技能 | 「慎重打法」と同一視、狙い・筋力の上乗せ |
| `強振多用 / ミート多用`（Green） | 本人のSlow Swing Mode Preferenceの表示 | 能力上限の強制変更、2ストライクでGreenを書換え |
| `積極打法 / 慎重打法`（Green） | SWING/TAKEやChaseの方針 | 強振/ミート好みと同一の軸にする |
| `パワーヒッター / アーチスト` | 対応する強振時の技術・Launch/Transfer Sourceの投影 | POWER_SWINGラベルだけの速度・本塁打Buff、真のRaw Powerの再加算 |
| `アベレージヒッター / 安打製造機` | 芯・軌道・打球品質の源技能の投影 | ミートモードで機械的に安打抽選 |
| `プルヒッター / 流し打ち / 広角打法` | 実際の方向別Motor/Contact技能 | Intent割合を0/100に固定、事後打球方向への補正 |
| `粘り打ち / カット打ち / 初球○ / 悪球打ち` | 対応する局面・時間・身体制御が存在するときのみ技能が現れる | 凡打をファウルへ変換、ゾーン外へ無限にリーチ |

新能力を増やさず、真の状態から`0〜100 / G〜S`・Green・ほかのTraitを投影する。**同じSourceを別Traitや隠し能力として二重入力しない。** たとえば公開パワーだけを書き換え、真の身体／技術Sourceを固定した場合、正史試合の結果が変わってはならない。

### 5.1 スカウティング・史実選手の値

現代の測定値や信頼できる動画がある場合と、歴史選手の打撃記録だけがある場合は確度が違う。未知の個人最大バット速度・努力量を史実の確定値として捏造しない。既存Player Reconstructionの `UNKNOWN / HISTORICAL_ESTIMATE / MODEL_CALIBRATED` などのprovenanceを守る。パワー1〜100から最大速度の個人真値を機械的に逆算しない。初期データが公開パワーのみなら、暫定Adapterは暫定値と不確実性を記録し、本当の身体能力の決定値として扱わない。

## 8. 敵対監査（失敗しやすい実装）

1. **公開Power値で速度を決める**：パワー1/100が物理の直接倍率になる。⇒ 内部真Sourceと実行可能領域を必須入力とする。
2. **強振vsミートを二つの固定速度にする**：強振の非力選手がミート平均を下回れなくなる／高能力が常時全力。⇒ Intentは連続動作への目標に留める。
3. **遅いほど命中率が上がるBuff**：動作による理由を失い、速く振る技術の価値も壊す。⇒ 速度変更が実際の修正時間／軌道／タイミングへどう効いたかを評価。
4. **優れたミートが自動的に遅いスイングを選ぶ**：能力と本人の好みを混同。⇒ `Slow Preference`は独立入力。
5. **2ストライクになったら全員コンパクト**：個性が消える。⇒ その打者のCount別PolicyとContext次第。
6. **遅い本塁打を成立させるため打球初速に隠しPower倍率**：接触物理の因果が壊れる。⇒ 有効質量・入射球・接触位置・反発・角度を既存Nativeで評価。
7. **能力上限を1数値だけにする**：重いバット・差し込まれ・不利な姿勢でも最大速度到達。⇒ 時間・動作条件付きEnvelopeを使う。
8. **全選手共通の母集団31m/s profileを無検証で利用**：個人差が運動層で失われる可能性。⇒ 呼出元の個人Source結線を監査し、適切なoverride／Adapterを検討。
9. **NativeのRigidBat物理を別コピーで再実装**：二つの真実の接触結果が生じる。⇒ 一つの正史Contact pathを選定。
10. **GreenやTrait表示ラベルを物理に入力**：表示変更だけで試合結果が変わる。⇒ 真Source→表示の一方通行。
11. **監督命令で本人の好みを上書き保存**：同じ選手の個性が消える。⇒ 一球のIntentとSlow Preferenceを別保存。
12. **捕手が打者の真の一球Intentを参照**：不自然な全知配球になる。⇒ 観測からのBeliefのみ。
13. **バット軌道を完成した本塁打に合わせる**：因果が逆転する。⇒ 必ず運動・接触が先。
14. **安打率だけを校正してOKとする**：物理が不自然なままスコアで隠れる。⇒ 速度／軌道／接触／打球／結果の各階層を別検証。
15. **リポジトリ文書ブランチだけを「最新実装」とする**：先行Nativeを捨ててしまう。⇒ HEAD・worktree・実行経路を着手前に調査。
16. **性能最適化でフレームに依存したスイング**：描画OFFと低FPSで結果が変わる。⇒ Simulation Clockにのみ依存。

## 9. 検証・完成の定義

**設計完了の条件**：本書の会話合意事項（§0）が全て、既存CANONICAL・BAT/DIR・Nativeの所管箇所に対応付けられ、実装しない項目も意図的な非採用／未校正として明記されること。

**実装完了の条件**（設計完了とは別）：

- 個人の能力上限と一球ごとの速度・軌道が分離し、実際の時系列Motor Stateを生成する。
- Count・監督指示・本人の長期方針で、同じ打者が異なるスイングを選択できる。強振多用・ミート多用は恒久能力Buffや強制アクションではない。
- 高速コンタクト、遅い強打、非力な全力振り、カウントで切替、切り替えない打者等の設計ケースが成立する。
- Resultの補正なしに単一Contact Solver・BallFlight・RuleEngineまでつながる。公式イベントとリプレイは同じ正史を参照する。
- SWG、BAT、DIR、CATCHの該当テストの実測PASS、回帰、決定論、セーブと性能の実測結果を報告。未実施は`NOT RUN`、未接続は`NOT CONNECTED`として明示。
- 勝手な`main`統合、ローカル未確認ファイル削除、既存PNGの再設計、別エンジン・新Traitの増設なし。

**完成ではない例**：新しい型を一つ作成、特定fixtureで打球が速くなる、強振UIボタンに倍率追加、文書でチェックを埋める、PNGのアニメ速度だけ変更、9回完走を確認せず「実試合実装」と報告。

## 10. 最終設計判断（一文）

> **パワーは速度・加速度・打球エネルギー伝達を支える真の能力の一部であって、実際のスイング速度を命令するスイッチではない。打者本人の長期方針とその球の状況判断が、身体的に可能な範囲でスイングの努力量・軌道・タイミングを選び、その実運動と既存のバット・ボール物理から結果が生まれる。**

この方式で、打者は「パワー100だから全力で振る機械」でも「ミート打ちなら全員同じ速度の機械」でもなく、**自分の能力を状況ごとにどう使うかという個性を持つ野球選手**になる。
