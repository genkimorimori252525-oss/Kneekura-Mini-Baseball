## 0. ユーザーが求める体験

捕手の配球思考をユーザーが一言で理解できるよう、**「リード性格：狡猾」「リード性格：得意球」「リード性格：ゴリ押し」** のような短いあだ名で表示する。

- 同じ投手・打者・局面でも、捕手の長期的な好みに応じて候補の選び方が変わる。
- 性格は「得意・不得意」や勝率序列ではない。同じ性格でも、観察力・状況判断・投手理解などの能力は違う。
- 相手が適応し、投手の当日の調子が変わり、監督が指示すれば、普段の性格に反する配球をすることもある。
- 連続した配球を打者が読み、捕手もその読みを推定する。ラベルだけを見て結果を抽選しない。
- ユーザーは基本的に**1人につき主たる性格1個**だけを見る。細かい内部重みは通常UIには出さない。

## 1. 初期8タイプ（ユーザー向けラベルは日本語）

| 安定ID | リード性格 | 何を優先しやすいか | 別タイプとの差・注意 |
| --- | --- | --- | --- |
| TRICKSTER | **狡猾** | 打者が待っていそうな球を推測し、予想を外す候補 | 根拠のないランダム配球ではない。「裏をかいた」結果Buffは禁止 |
| PITCHER_STRENGTH | **得意球** | 投手が実際に安定して投げられる武器・コース | 同一球を必ず連投するわけではない。疲労・当日の球質で修正 |
| REPEAT_PRESSURE | **ゴリ押し** | 直近に通用した有効な選択をあえて繰り返す | 「得意球」の投手基準と異なり、反復と継続に寄る。読まれれば逆効果もある |
| BATTER_WEAKNESS | **弱点狙い** | 証拠のある打者の苦手球種・コース | 少ない対戦データを真実扱いしない。投手が投げ切れることが前提 |
| CAUTIOUS | **慎重** | 打たれ方・四球・失投など局面別の大損失を避ける | 「ボール球を増やす性格」ではない。満塁3-0なら押し出しも危険 |
| CHALLENGER | **強気** | 良い球でゾーンに入り、積極的に勝負を進める | 「ゴリ押し」の連投嗜好とは独立。無謀な真ん中固定は禁止 |
| SPEED_VARIATION | **緩急自在** | 実際の持ち球の速度差・軌道差でタイミングを揺さぶる | 物理的な球速・回転を改変しない。既存投手Trait「緩急○」の投球間隔操作とも別 |
| ADAPTIVE_READER | **観察眼** | 打者のスイング、見逃し、反応の新しい証拠を配球選択へ早めに反映する | 観測精度・学習技能そのものが高いという意味ではない。得られた情報の重視傾向 |

**初期セットは8ラベル。** 行動が実質同じなら実測を見て統合し、新タイプは明確に異なる意思決定が立証できた場合のみ追加。旧データで未設定の場合は中立的な既存Preferenceを使い、UIは「標準」または「未設定」と表示してよい（第9の有利な性格にはしない）。

## 2. 既存設計との接続 — 「性格」と「能力」は分離

新たに8種類の配球アルゴリズムを作らず、既存の次のSourceを使う。

- **能力のSource:** CATCHが定める7領域（situationReasoning、batterReading、pitcherUnderstanding、sequenceConstruction、strategicCounterplay、evidenceAdaptation、communicationExecution）。
- **本人の傾向:** CATCH既存のCatcherDecisionPreference（riskAppetite、edgeAttackPreference、noveltyPreference、policyPersistence）と、必要性が検証された最小限の追加Slow Preference。
- **知識のSource:** 信頼度・古さ・出典があるScouting、観測した球と打者反応、投手との実戦経験。
- **能力の表示:** 正本09の「キャッチャー G〜A／球界の頭脳」をそのまま使用。性格は同じ能力の別Gradeでも、新しい青/金Traitでもない。

必要ならSlow Preferenceに追加する軸の候補は、投手の武器重視、打者の弱点重視、成功手の反復、球速差への関心、反応情報への注目度。ただし、既存軸で説明できるものを二重登録しない。「観察眼の情報重視」と「evidenceAdaptationの更新精度」、「狡猾の好み」と「strategicCounterplayの推定能力」は必ず区別する。

**データモデルの原則:** 内部の行動原因は連続したPreferenceとBeliefであり、8個のスタイル名はその読みやすい投影である。選手メーカーで性格を直接選ぶ場合は、選択を初期Slow Preferenceへ変換する。毎球「狡猾だから空振り率+X%」のような分岐を追加しない。公開ラベルは1個、将来の混合個性は内部で表現できるようにする。頻繁な打席結果で性格ラベルを行き来させない。

## 3. 1球の意思決定（既存CATCHへ差し込むだけ）

1. **情報を構築:** 公知のカウント・走者・点差・投球履歴に、捕手が本当に把握した投手状態と打者推定を重ねる。全知・未来情報は禁止。
2. **候補生成:** 実際に投げられる球種 × 合法な照準 × 意図。実行不能・強く劣る候補を先に除外する。
3. **局面・技能で比較:** CATCH既存の合法性、投手の再現性、打者の反応予測、失点や四球などの損失、監督方針・信頼を評価する。独自の巨大な一括Utilityは新設しない。
4. **性格を反映:** 実行可能で競争力の近い候補の比較や情報の優先度に、Slow Preferenceの傾向を使う。固定の球種割合表、カウント別必勝スクリプト、魔法的な成績補正は使わない。
5. **権限を解決:** CATCHER_LEDでは捕手が提案し、投手の受諾を経る。PITCHER_LEDでは捕手は助言のみ。NEGOTIATEDの首振り等は既存契約で扱う。監督の受諾済みHard Signを勝手に破らない。
6. **正史で実行:** Accepted PitchCallを既存Pitch Physicsへ渡す。要求コース、ミット位置、実球道は別。物理的なスピン、球速、制球、打球結果、審判判定をスタイルから直接書き換えない。
7. **試合後に更新:** 観測可能な証拠のみで捕手・打者の各Beliefを更新し、次球へつなぐ。打者に捕手の非公開サインを見せない。

**相互作用の例:** 0-2で投手のフォークがよく決まり、打者が次のフォークを待ち始めた場合、得意球型はフォークを重視し続け得るが、狡猾型は直球で裏をかく可能性を比較する。ゴリ押し型はフォーク継続も選び得る。いずれも投手のコントロール、打者の実際の待ち方、状況により逆転する。常に選択が違うことは要求しない。

## 4. UI・保存の最小仕様

- 捕手の選手カード: 「キャッチャー B」等の既存Gradeの近くに、独立した1行「リード性格：狡猾」。補足説明は選択時／詳細表示のみ。
- 性格ラベルに青・金・赤の特殊能力色を勝手に割り当てない。能力の序列や特効と誤解させない。
- 監督モードで打者に表示するのは対戦履歴から推測可能な傾向だけ。隠し重み、非公開サイン、正解の待ち球を公開しない。
- 選手メーカー/ロスター編集で1タイプ選ぶ場合、テンプレートがSlow Preferenceを初期化する。手動微調整可能にする場合もラベルと実際の傾向が乖離しないProjectionルールを定義。
- セーブはSchema Versionを持ち、未設定の旧選手を読み込んでも破壊しない。ラベル変更とゲーム能力・過去成績を混同しない。
- Seed / Same Input / Same Core Versionで同じ選択・Traceを再現する。UIやFPSを変えてもMatch結果が変わらない。
