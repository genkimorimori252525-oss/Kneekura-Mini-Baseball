## 0. 目的と思想

1936年の職業野球開始期を含むNPB史実、日米野球・日韓野球、WBC・プレミア12・オリンピック／その予選等の**実在した試合**を、日付・大会・両チーム・打席／プレーの事件をキーに調査し、単なる最終スコアではなく「何回の誰の打席で本塁打が出た／誰が失策した／どの方向に、どのような打球が飛んだ」を、**分かるところだけ**細かく復元できる資料基盤を用意する。

- **ゲームの根本原則:** 共有 `Match Core → CanonicalWorldSnapshot / Events → Presentation Adapter → Broadcast`。自然に試合を計算する場合、打球・走塁・判定は因果的に発生する。結果ラベルを先に抽選し、あとから物理運動を捏造することは禁止。参考: [World First](../../architecture/WORLD-FIRST-BROADCAST.md)。
- **ただし「史実そのものを再生する」用途は通常の自由シミュレーションと異なる。** 確定した過去の出来事を閲覧するHistorical Playback層と、新たな選択から未来を計算する自由なMatch Core層を混同しない。史実の3ランという記録から正確な球速・角度を「史実」と称して創作しない。
- 参照資料の出典・権利・観測／推定／不明を保存する。[選手再現部の史料アトラス](../../player-reconstruction/NPB-SOURCE-ATLAS-1936-2026.md)と重複する巨大独立DBや独立した野球Coreは作らない。
- 史実通りに進む試合も、将来の操作UIは監督／選手の両方を念頭に置く。ただし**実操作の内容と史実への影響は未決定**。

## 1. ユーザー希望の３モード（存在方針確定、細部未決定）

| ゲームモード | ユーザーから確定している意図 | 暫定的な設計境界 |
| --- | --- | --- |
| **完全史実**（Exact Historical） | 史実通りに試合が進む | 史実イベント／結果／日時・大会の記録を保持する**再現／閲覧系**。未計測の投球・飛距離は推定表示として区別。未判明の打席を史実確定として埋めない。 |
| **史実モード**（Historical / Alterable） | 史実をベースに、ユーザーの判断などで歴史を変えられる | 史実の初期環境・選手・予定・利用可能なイベントを起点とし、選択後の結果は共有Coreによる因果的実行で変化し得る。**どの時点で史実固定を解除するか、操作しない試合をどう扱うかは未決定**。 |
| **オリジナルモード**（Original） | 能力値による完全オリジナルの試合／シーズン | 実選手でも架空選手でも、共通Coreの技術・能力・心理・物理・監督判断から結果を生成。史実の勝敗・本塁打をゴールとして矯正しない。 |

**監督モード／選手モードは３モードと別軸のプレー視点・操作方式**とする検討方向。両方を搭載したいという希望は確定。ただし操作方法、指示の強さ、反実仮想の発生条件は未確定。

**設計上の衝突を隠さないこと:** 完全史実で選手が自由に投げて打っているのに必ず既知の結果へ誘導するのは「物理が原因で結果が決まる」という既存正本に反する。従って「過去を観測／追体験する」「操作に応じて分岐して史実改変へ移る」「操作を限定する」などは**比較案**に留める。史実からの逸脱をバット物理や審判に隠し補正する案は採らない。

### 1.1 決めていない論点（実装者は勝手に固定しない）

1. 完全史実で許される指示／操作は、カメラ・演出のみ、史実に整合する範囲の参加、史実改変モードへの明示分岐のどれか。
2. 史実改変で史実固定を解除するのは「最初のユーザー介入」「介入が因果的に影響した時」「ゲーム開始時」などのどれか。途中以降の未介入打席・他球場試合をどう処理するか。
3. 全試合の公式結果だけ分かる場合、各打席の完全な配列が不明なら完全史実モードをどう表現するか（無記録区間、可視化用非史実推定、ハイライトのみ等）。
4. 選手モードの入力方法、選手以外の操作、監督指示／自律AIとの役割分担、操作難度。
5. ペナント年の選手能力（実在選手のピーク固定OBカードと現役・独自成長の境界）、球団移籍／ドラフト／年度継続、架空球団、時代変更、試合スキップ、国際大会との日程競合。
6. 史実の誤審・記録訂正があるケースで、公式記録忠実性と現代ルール適用の優先順位。
7. 過去のシーズンを選んだら国際大会まで再現するか、任意参加イベントにするか。既存World Competition設計と合わせる。

## 2. 史実資料→試合イベントの掘り下げ方（重要）

### 2.1 対象と収集順序

1. **試合を特定:** `competitionId / edition / dateLocal / home-away / park / gameNo`。1936年は春秋や複数大会、1945年は通常NPB公式リーグ戦なし。日付だけでは同日のダブルヘッダー等が曖昧になる。
2. **骨格:** イニング別得点、先発・交代、選手別打撃／投手／守備成績、得点、打点、本塁打、失策、併殺など、出典で確認できる記録を保存。
3. **打席・プレー:** 記録があるならイニング、表裏、アウト・走者、打者・投手、結果、守備処理、打球方向（`中本`, `右中間`, `遊失`等）まで確定。ない部分は補完せず unknown。
4. **個別深掘り:** `日付 + 球団 / 対戦国 + 選手名 + 回 / 試合番号 + 出来事` を組み、当時の新聞、公式回顧、当事者談話、写真、試合映像、球場図を探す。著名な特大本塁打、三者連続本塁打、サヨナラ、記録的失策を優先。**全試合の映像を機械的に探し続ける義務は作らない。**
5. **方向・弾道を制約:** 確かな着弾場所・フェンス位置・映像の相対位置などがある場合のみ、方向扇形、弾道の高低、フェンス超過の範囲、推定飛距離の**区間**などを絞る。
6. **検証と採用:** 観測できた値を史実イベントに紐づけ、解釈や逆算モデルは別フィールド。矛盾が発見された箇所だけ記録し局所的に直す。再現可能な物理挙動はLive Coreのチューニングに利用してよいが、「史実の正確な軌跡」に昇格させない。

**強い注意:** `中本`から正確な水平方向角度は決められない。`特大`は飛距離の数値を証明しない。「○○m弾」という新聞記載も計測条件が不明なら**報道値**として扱う。映像単視点だけで真の3D打ち出し角・初速・空気抵抗は確定できない。球種・球速・捕手サイン・打球回転は別々の確からしさを付与する。

### 2.2 具体例：1985年4月17日 阪神—巨人

- 阪神球団公式は、甲子園7回裏2死一・二塁、槙原寛己からバースの逆転3ラン、続く掛布・岡田の**三者連続バックスクリーン方向本塁打**を記述する。球団資料: https://hanshintigers.jp/data/uniform/uniform_1984-1987.html
- 当事者談話等では掛布の打球が**厳密にはバックスクリーン左寄り**だったとされる。二次資料: https://column.sp.baseball.findfriends.jp/?id=078-20150511-01&pid=column_detail
- **保存できる確定粒度:** 日付／球場／対戦／7回裏／打順の連続／投手／本塁打／大まかなセンター方向。異なる証言間で球種が食い違う場合は情報源ごとに保存し未確定扱い。**実測飛距離・打ち出し角・打球速度は、この２資料だけで確定しない。**
- これは「特別有名な一試合だけ丁寧に掘る」モデルケース。すべての試合に同じ探索コストを強制しない。

### 2.3 史実レコードの最小案（スキーマ提案、未実装）

```ts
type HistoricalEventEvidence = Readonly<{
  historicalGameId: string;            // competition/edition/date/teams/gameNoで一意化
  eventSequence?: number;             // 時系列を確認できた場合
  inning?: number;
  half?: "top" | "bottom";
  outsBefore?: 0 | 1 | 2;
  batterId?: string;
  pitcherId?: string;
  eventType: "home_run" | "error" | "hit" | "out" | "run" | "other";
  recordedOutcome: string;            // 公式記録との照合対象
  fieldSector?: string;               // 例 center, left-center, right
  reportedDistanceM?: number;         // 報道にある数値; 実測とは限らない
  estimatedDistanceRangeM?: readonly [number, number];
  inferredLaunchAngleRangeDeg?: readonly [number, number];
  trajectoryDescription?: string;     // 高弾道、ライナー等の言語証拠
  factStatus: "OFFICIAL_OBSERVED" | "SECONDARY_CORROBORATED"
    | "HISTORICAL_ESTIMATE" | "MODEL_CALIBRATED"
    | "UNKNOWN" | "CONFLICTED";
  sourceUrls: readonly string[];
  sourceClaimNotes?: readonly string[]; // 何を支持する資料か
  rightsStatus?: string;
  estimationMethodVersion?: string;

```

実装時は既存の `CanonicalEvent` や公式記録の型と照合して、**新しい二重の公式記録エンジンを作らない**。単一イベント内の情報でも「本塁打=公式／方向=回顧／飛距離=推定」とフィールドごとに根拠を分けられる型が必要。未知の距離を `0` とせず `undefined` とする。

## 4. 実装の接続案（未実装・決定ではない）

```text
[各公開資料/公式記録/新聞・映像/権利台帳]
       → Source Catalog / 試合同定・選手ID同定
       → HistoricalGame Ledger (日程・スコア・打席/プレーの観測記録)
       → Enrichment (史料付きの方向/球種/飛距離レンジ; UNKNOWN維持)
       ├─ Complete Historical Playback [史実イベントの表示・解説、未知を明示]
       └─ Historical Initial-State Builder [当時の条件・名簿・ルール・日程]
                └─ Shared Causal Match Core ← Manager/Player Input
                           └─ Canonical Events / Rules / Score / Replay
       └─ Original Initial-State Builder [独自リーグ/能力/予定]
                └─ 同じ Shared Causal Match Core
```

- **歴史レジャーの「確定イベント」と共有Coreの「新たに発生したCanonical Event」は別の存在。** 完全史実のPlaybackは歴史の事後資料可視化であり、現在の物理シミュレーションの結果を固定したとの証明ではない。非史実軌道を描く場合は「復元イメージ／推定」と明示。
- 史実改変で分岐後は、監督/選手が知覚できない未来の史実展開をAI意思決定に渡さない。確定した分岐以降の試合記録は **save内の新たな正史** として保存。外部ソースの史実記録を上書きしない。
- 史実の勝敗を自由Coreへ**裏補正で強制しない**。未介入試合の扱いは上記未決定論点として留保。
- 既存World Competition、シーズン環境、監督アーキテクチャ、TraitとOB固定能力に接続。例: [Manager 49](../../game-design/49-manager-architecture-v1.md)、[OB Principles](../../player-reconstruction/PRINCIPLES.md)、[Historical Environment](../../player-reconstruction/NPB-HISTORICAL-ENVIRONMENT-MODEL.md)。
- **国内公式ペナント、国代表戦、日米交流戦、五輪予選は大会種別と通算集計を分離**。日程衝突や代表派遣は既存世界大会設計と整合させる。史実/オリジナルで保存データを混ぜない。
- セーブには `mode`、`season/edition`、`dataSnapshotVersion`、`coreVersion`、`seed`、`branchPoint`、`userActions`、`officialRecordVsHypothesisFlags` 等を記録する**提案**。実際のセーブスキーマは現行契約を確認する。
- 各種史料の画像・映像・記事本文はリンク／最小限の非侵害メタデータを優先。権利のない映像の自動ダウンロード・再配信・商用利用はしない。CSVのライセンスと原サイトの規約、再配布の範囲は個別確認。

### 最低限の回帰シナリオ

- 同じ日付に別試合が複数あっても一意に識別できる。
- 1945年のNPB公式ペナントの欠番を架空試合で埋めない。
- 「中越本塁打・着弾位置の記述あり・距離実測なし」を、確定値を捏造せず表示する。
- 同一事件でも方向が公式／当事者回顧／記者推測で異なるとき、根拠ごとに保持する。
- 歴史試合のPlaybackでは史実の勝敗／記録が勝手に上書きされない。
- 史実改変後に旧史実の未来展開がAI意思決定に混入しない。
- Originalは史実に依存せず、同じ初期条件・シード・入力・Core版で結果を再現できる。
- 監督／選手操作の仕様が未決定でも、資料台帳と個別試合Pilotだけは独立して前進できる。

## 6. 非目的・禁止事項

- この計画だけで「全試合の詳細プレー・全投球・飛距離データ収集済み」「3モード実装済み」「一軍史実ペナントが再生可能」と宣言しない。
- 飛距離／打球角／初速の単一点推定を史実の測定事実として登録しない。
- 完全史実を装うため通常Coreの接触・守備・審判結果を後付けするエンジンを組まない。
- 大量の映像／記事／他作者のDBを権利確認なく取り込み・公開しない。
- 史実選手のピーク固定能力（既存方針）を「史実結果の年次固定」という別問題にすり替えない。
- 既存の `main`、並行開発・ローカル未コミット作業を変更・上書きしない。

**この文書は、ユーザーのアイデアと調査入口を後続AIに失わず渡すための計画であり、未確定のモード操作をAIが勝手に決める許可ではない。**
