## 2. 設計原則（変更しないもの）

1. 選手の真の身体・スイング能力（速く振れる素質）と、**現在選択したバットでの実行可能な最大芯速度**と、各球の実際のスイング速度は別。
2. 同一選手・同一長さ・芯位置・身体状態・準備条件なら、**重い／回しにくいバットほど到達可能な最大速度が高くならない**ようにする。別選手同士、異なる長さ・形状では単純な体重／重量順位を強制しない。
3. パワー 1〜100、体重、得能、強振／ミートのラベルをバット速度の直接倍率にしない。既存の真の能力 Source、バットの質量・慣性、姿勢と加速可能な時間から導出する。
4. すでに計算しているバットの質量・慣性・有効質量を使い、接触物理／飛距離／本塁打率への新たなボーナスは**一切追加しない**。遅いスイングでの本塁打は上位計画の接触物理でのみ成立。
5. 元の測定映像／実測軌道の再生、試合 Core、描画 FPS を混同しない。最大値は標準的な準備条件での**推定上限**であり、任意のコース・球で必ず出る速度ではない。

## 3. 最小実装の分岐

**A — 既存重量連動が正史経路にあると実測確認できた場合:** コア変更なし。既存計算済み上限をメーカーへ read-only で公開し、UI とテストのみ変更。枝／版により結果が異なるなら差を証拠付きで記録。

**B — 今回監査したコード同様に未接続の場合:** 新しい打撃エンジンは作らず、既存 `maximumSweetSpotSpeedMps` の真の身体能力と**基準バット条件**から、選択バットの `massKg`・長さ・重心・慣性モーメントに対応する `effectiveMaxSweetSpotSpeedMps` を一箇所で算出。バット重量のために必要な加速負荷を考慮する。実装は既存 Source／Motor 入口に接続し、Maker と実試合は同じ結果を使う。

- 必要なら握り位置まわりの慣性 `I_grip ≈ I_cm + m·d²` を出発点に、基準バットとの比で最大速度の変化を校正する。単純な平方根則などは**未校正の候補**であり、人体の真の運動公式として固定しない。追加の全身筋骨格シミュレータは禁止。
- 基準バット・身体能力・校正版・推定由来を明示する。既存 JSON の一律上書きは禁止し、既存選手の異なる用具設定を誤って「基準バットでの測定値」に読み替えない。未校正なら `未算出` を返し、もっともらしい数字を捏造しない。
- すでに設定された `targetSweetSpotSpeedMps`／`swing.speedMps` が新しい実効上限を超える場合、黙って強制的に速度を下げたり「当たった」ことにしたりしない。既存の検証／自動調整提案へ理由付きで返し、明示的に適用された値だけを保存する。

## 4. メーカー UI（ユーザー必須要件）

**配置:** 既存の「この選手のバット」→ **バットの重さ（kg）** 入力 (`swing-bat-mass`) の**直下**に、余白の少ない小さな read-only 1 行を置く。選手作成タブの試合用 `batMassKg`／研究 draft `bat.massKg` からも、同じ正史値を必要に応じて参照できるようにする。計算ロジックを UI ごとに複製しない。

> **このバットでの推定MAXスイング速度：XX.X m/s（約 YY km/h）**

- 現在の選手の真の身体能力、選択バットの重量と慣性、基準条件から導出。**パワー表示値 × 定数**や、単に現行 `maximumSweetSpotSpeedMps` をラベルだけ変えて表示する偽対応は禁止。
- 重量・長さ・芯位置・選手・真の能力・JSON の採用変更時に即時更新。未確定の入力がある間は古い値を新しい値として見せず、`未算出` または `入力未確定` とする。
- `m/s` を正とし `km/h = m/s × 3.6` は表示変換のみ。速度の「最大」は芯（sweet spot）の速度を意味することを短いヘルプに明記。平均速度・接触時速度・動画再生速度・保証値とは混同しない。
- 既存 UI の重量入力・保存形式・Mobile 390px／PC表示を壊さず、値のための新しい編集スライダー／公開能力／得能を増やさない。

## 5. 実装順と受入

1. 実ワークツリー・複数ブランチ・既存選手メーカー最新版を監査。重量の現在の保存値→物理衝突→モータ Source→UI を追跡し、A/B の判断を検証記録へ残す。
2. B の場合だけ単一の重量依存上限 Source を作り、`WorkbenchPlayer`／`LivePhysicalRoster`／`BattingMotorPlan`／実試合の既存境界で **同じ上限**を使用。実スイング Producer がこの上限を守ることを検証する。
3. `swing-bat-mass` 直下の小さな表示を実装。選手変更・重量増減・能力変更・未確定入力・JSON 保存読込をテスト。
4. 同一選手・同一形状で軽量→重量へ変更したとき最大速度が増えず、別の強い選手では高い値を許容。重量差が接触結果に効く既存テストも維持。最大速度変更のみで接触速度／本塁打を直接書き換えない。
5. 既存の重量による打球差、空振り／見逃し、モータ速度上限、固定 seed 再現、Mini/Natural 同一 Core、実測原軌道不変、fps 非依存の回帰テストを実行。未実行は `NOT RUN`、接続未完は `NOT CONNECTED` と記録。

**完成条件:** 同じ選手でもバットを重くすると（条件を揃えれば）推定 MAX 芯速度が下がり得て、その値を重量欄の直下で確認できる。スイング速度は実試合でも同じ物理制約に従い、衝突物理や既存のスイング意思決定を二重実装しない。

**対象外:** 全身の質量をボール衝突へ加算する別物理、全身筋骨格、全選手再査定、HR 保証調整、強振／ミートの二分固定、新しい公開『スイング速度』能力。
