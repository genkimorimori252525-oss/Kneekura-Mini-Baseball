# Native first-dispatch prerequisite owners

This implements step 2 of the frozen first-dispatch inventory and its Source reference amendment. It enables no physical pitch, consumer action, kernel, consumption or episode admission. The ten `pa_dispatch_v1_` table schemas, accepted Source shapes, original reservation/blocked slot, workload state, and v1 physical/model bytes remain unchanged.

## Owner API and proof sequence

`openSqliteSamePlateAppearanceDispatchStore(path, authority?)` owns its Native connection. Its action, consumer-set, episode and right methods accept an independently accepted Source ID or read an immutable saved record. `acceptCalibrationSet(ids)` and `readCalibrationSet(ids)` require the canonical original-ten, exact-32 route order. The API accepts no connection, actor, cached model, proof context, physical result or exemption.

Action acceptance alone bootstraps the exact ten-table namespace in the owner transaction. Calibration acceptance before that action returns a typed `missing_action_plan` prerequisite, with no invented missing Source ID and no schema installation. Each calibration has its own Source/hash, exact projected member, nominal owner/parameter references and response hash. Pitch timing and response-policy references must equal the canonical action's references. The accepted calibration result is `{kind, source, lineage, role, nominalInputHash, effectiveResponseHash}`; original models and projected execution states remain private to each proof.

Every read-only proof freshly reconstructs the original enrollment/view/actor and nominal owners. A lexical assembly shares these dependencies among the 32 calibrations, and is destroyed at the proof boundary. It is never retained across a DDL, DML, COMMIT, committed verification, or later owner operation. New records require the old fresh view plus the separate dispatch fresh-work predicate. Exact saved reads and retries authenticate the immutable historical view, with no current-frame or future-physical replay.

The exact-32 operation uses one parameter-bound multirow `INSERT`: one atomic DML boundary, precisely 32 affected rows. Whole-operation proofs run before acquisition, after acquisition, after the INSERT and on a fresh committed snapshot. Durable row censuses, schema versions, settings, counters and private savepoint identities must agree at every boundary. Partial existing sets reject instead of being repaired. Actual forced COMMIT or uncertain cleanup retires the owner; committed rows are not erased by compensating writes.

## Nominal endpoint day semantics

Timing references pin a baseline or update Source and the hash of the fully reconstructed `PlayerPitchTimingSource` at that endpoint. Release references do the same for `PlayerReleaseGeometryHistory`. Required rows through that explicit endpoint are authenticated. Historical replay never follows the mutable head or hydrates unrelated payloads after the pin.

The endpoint history and the selected numerical state have different meanings. The normal owners' contract selects the last state applicable at the original game day. A later-day state inside an explicit pinned prefix is authenticated but cannot provide an earlier game's timing or release values. Fresh acceptance and its committed proof independently authenticate normal current history/head and reject an additional applicable revision outside the pin. No stricter endpoint-date rule is added.

TAKE geometry remains explicitly accepted in the action Source. Its original batter/model/Person/body/equipment and clocks are authenticated; the ball radius must match the accepted equipment, and `readyAtUs` cannot precede the actor's world tick. The six delivery fields remain explicit. No v1 stance is substituted and swing remains unsupported.

The timing/release baseline's original Person link is also read on the same private connection and compared with the original pitcher by career, Player, Person and link Source identity. A matching career/Player pair alone cannot substitute a different Person. This introduces no arbitrary equality requirement for Person Source-version labels.

## Orphan and pending behavior

The old global-workload and causal-work guard paths invoke dispatch exclusion before their absent-family returns. Indexed and typed raw identities survive deleted/moved roots and duplicate/escaped raw keys. Prospective dependency links also survive: deleting an action while calibrations or downstream records still claim it cannot authorize recreation. Future execution payloads remain opaque during discovery.

Future claims retain schema-owned pitch/right/episode identities and typed owner/Source references even when copied enrollment/game/first-pitch indexes move. Metadata-only traversal follows these references to their original enrollment claims, including links between future rows, without parsing or replaying their physical payload. A typed reference to a missing prospective owner fails closed.

The existing original-enrollment read branch permits only authenticated prospective prerequisites. A separate predicate rejects dispatch pitch/head, consumer-action, consumption or admission claims for fresh empty-view preparation. It does not enlarge the frozen v1 domain census or change the historical reader.

All consumer adapters remain unsupported in this checkpoint. Consumer sets report exact original player/route missing references, missing accepted calibrations and unsupported adapters. Episodes and rights retain precise pending dependencies. They receive no durable accepted row, completed-work credit or physical authority while any required adapter or input is absent.

## Verification scope

Finite Native tests cover namespace bootstrap, exact-32 acceptance/retry, aliases/missing/foreign inputs, historical retry versus fresh-work gates, deleted prerequisite claims, changed live Source bytes, real forced COMMIT and unexpected adjacent DML. Separate nominal-reader tests cover baseline/update endpoints, later-day selection inside the pin, newly applicable revisions outside the pin, opaque future payloads and raw/TEMP identity faults.

Small dispatch tests explicitly mock original actor/model authentication and use only the already declared fixture calibration values. They verify the new owner's transaction and reference boundary; they do not qualify genuine actor execution or production fatigue values. Genuine TOTAL/view work remains a separately controlled prerequisite. Source-specific supervisor/compiler/review receipts determine checkpoint qualification.
