# 公開能力と得能の分離・得能名・投手調整室 — 確認案

状態：人間が全範囲を明示承認。V77の実装と通常HTML・投手調整室・メーカーの検証、配布凍結が完了。GitHub公開照合待ち。元の全計画の完了は主張しない。

## 人間の目的

- 公開能力は基礎能力。得能の付与・段階・効果倍率で変化させない。
- 得能は基礎値とは別の実行技術・行動特性として保存し、対応する動作へ一度だけ作用させる。
- 人間向けの名前は送球A、ストライク送球、緩急○、牽制○、立ち上がり○などの分かる名前。説明は既存の約1秒hoverの「?」へ。
- 通常試合で使える得能を追加し、ペナント・育成・故障管理等へ範囲を広げない。
- メーカーに独立した「投手調整」を追加。人間向け画面を初期状態とし、メーカー全体にAI用モードを設ける。
- 投手の公開能力から簡単に設定し、必要なら球種別の回転・リリース・投球動作まで詳しく編集。同じ物理と試合描画で試投する。
- 最新のバット軌道・打者カメラ・走塁守備・ボール表示・元の全計画は継承する。

## 調査で確認した差

送球Aの旧setterは得能profileを保存せず、physical.throwDirectionStdRadiansを直接変更する。初期0-b0では.004→.003rad、公開送球精度70→97.95848622191616を再現した。v75の守備職人など追加6技術は、一般physicalと公開能力を変更しないため維持できる。

旧canonical09 §3.3は同じSourceの段階表示と得能を一つの効果として扱う。今回の最新指示は、この送球方式を独立技術へ改める仕様追補として記録する。名称についても旧正本は独自UI名を許していたが、今回は元の分かりやすい得能名を主表示へ採用する。

「意図的な投球間隔操作」「牽制技術」「立ち上がり準備」は、別得能の重複ではなく、同じfamilyの説明的表示名だった。名前だけでなく現在の実行対応を区別する。旧設計の緩急○は投球始動間隔の駆け引きを意味し、単に球速差を増やす処理ではない。未実装の時計・牽制・準備動作を、ラベル変更だけで動作済みとはしない。

## 1. 基礎能力と得能

正本を「選手の基礎physical」「独立した得能profile」「実行時だけの有効設定」に分ける。公開能力・G〜S表示・詳細基礎値は最初の値だけから計算する。得能の付与や削除、効果0〜2倍では基礎値を変更しない。実行用の合成結果を基礎JSONへ書き戻さない。

送球Dは中立。Aやストライク送球は送球を放す際の方向誤差、F/Gはその弱点として別に作用させる。公開送球精度や肩力は不変。効果倍率はメーカーで編集する。実行値が変わることと、基礎能力が変わることを区別する。得能によるアウト率・安打率の直接指定は行わない。

緑特は能力上昇ではなく行動の好みとして独立保存し、明示した監督指示を優先する。v75追加6技術は既存の独立方式を維持。金特と通常段階は同じfamily内で排他、二重に適用しない。

### 旧JSON

旧v1を黙って別解釈にせず、新しい独立方式を版で区別する。旧設定の読込と明示した変換を別にする。

- 旧送球は変更前の基礎値を保存していないため復元不能。既存SIを維持して取り込み、新しい独立送球得能は未設定にする。元70等へ勝手に戻したり、SIから新得能を自動付与しない。
- 旧緑特は保存されたbaselineを使って基礎を復元し、実行時に一回だけ効果を適用する。飽和値から逆算しない。
- 元ファイル・初期20人は変更しない。変換前後の値と対象を確認でき、無効入力は全体を原子的に拒否する。

## 2. 得能画面と追加範囲

人間向けには元の分かる名前、?には効果・適用条件・倍率・対応状況を表示する。内部IDや実行経路の説明はAIモードへ置く。同じfamilyの別名を別項目に増やさない。

先行追加は以下の4系統。いずれも一般能力の変更ではなく、条件が合う動作の技術として接続する。

| 得能 | 作用先 |
|---|---|
| 内角攻め／内角無双 | 打者の左右を考慮し、内角を狙う時の投球実行誤差 |
| ハイボールヒッター／高球必打 | 高い予測打点での打撃実行誤差 |
| ローボールヒッター／低球必打 | 低い予測打点での打撃実行誤差 |
| 打球反応○ | 投手本人が打球を処理する際の初動技術。一般野手や送球受球へ漏らさない |

高低の条件は急な境界にせず、条件外・得能なし・効果0は旧動作へ戻す。具体的な効果係数は試験用の暫定値であり、現実成績へ校正済みとはしない。

通常試合用の実働項目を主一覧とする。未接続の牽制○・緩急○・立ち上がり○を有効スイッチとして出さない。必要な対応状況は元名で説明する。ペナント・育成・回復・故障等は今回の編集画面から外すが、原設計catalogや既存JSONを削除しない。

## 3. 投手調整室

同じメーカーに「投手調整」を追加する。既存の選手作成・バット軌道は保持。明るいデザインと既存のG〜S表示を使う。

### 人間向けの画面

- 上部：投手選択、左右、球速、制球、試投ボタン。
- 左：球種カードと方向図。添付画像を参考に、球種・球速・曲がる方向を一緒に把握できる配置。方向の基準を明示する。
- 中央：同じ試合rendererによる投手目線・捕手目線の試投。補助として横・上からの軌道を表示。
- 右：ストライクゾーン正面の到達点、横変化・縦変化cm、回転数、球速。
- 詳細：球種ごとの回転軸・ジャイロ成分、リリース高・左右幅・本塁方向への伸び、投球時間・頭と身体の移動。

球種別のoptionalなレパートリーを基礎設定へ追加し、LivePhysicalRoster→Host→LivePitchへ通す。現行7球種は共通回転量と固定方向を使うため、表示UIだけで編集したように見せない。新設定省略時は旧7球種と乱数順序を完全に保つ。

矢印や回転数の変更は物理Sourceの回転へ反映し、変化量は空力Coreの計算結果として表示する。後から着弾点を動かさない。制球のために狙いへ向かう初速が逆算されるので、変化量は同じ初期位置・初速度の無回転球との差を同じ本塁平面で測定する。総落下量との違いを?で説明する。

### フォーム

最初はリリースの高さ・幅・伸び、投球時間、身体・頭の移動をまとめて設定できるようにする。フォームpresetから入って個別に調整する。現行1540msの投球動作は作者モデルであり、実測フォーム集とは表示しない。保存済みOpenBiomechanics投球データを使う時は、投球専用の座標校正を行う。打撃用座標を流用しない。新しい全身アニメーション制作は今回の主目的へ含めない。

### 試合画面・保存への反映

調整室の試合画面を見ながら変更し、同じ投球条件ですぐ再試投できる。結果を試合用JSONへ保存する。通常HTMLは既存どおり新しい試合から適用し、進行中の履歴を改変しない。「通常の進行中試合の次球から能力を変更する」Host機能は今回の前提にしない。

## 4. メーカー全体の人間／AIモード

人間モードを初期状態にする。AIモードはJSON一括編集・検証・結果取得・エラー箇所を見やすくし、打者・投手・得能で同じ保存とvalidationを使う。別の物理・別の選手データを持たせない。モード切替だけで能力や乱数・保存JSONが変化しない。

1. `LiveTraitProfilesV1.ts`、`LivePhysicalRosterV1.ts`、`LivePublicAbilitiesV1.ts`と実行resolver：独立方式・旧JSON・公開能力不変を先に検証する。
2. `LivePitchV1.ts`、`LiveBaseballMatchV1.ts`、`LiveFieldPlayV1.ts`：実行時合成と先行4技術。既存6技術は保持する。
3. 球種別設定・回転の観測と試投用共有APIを追加。省略時の互換を確認する。
4. メーカーの得能名・条件説明、人間／AI切替、投手調整UIと通常renderer用adapterを追加する。
5. 通常HTML・調整室・メーカーを同じCoreで生成し、既存Draft PR380へ保存する。mainへマージしない。

新しい依存、設定、lockfile、secretは変更しない。既存の承認された視点・4px表現・55/22ms表示を継承し、試投用の別物理を作らない。
