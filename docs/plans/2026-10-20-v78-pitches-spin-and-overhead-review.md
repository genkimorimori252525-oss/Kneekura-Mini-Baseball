# v78 確認案 — 球種・オリジナル球・回転再現性・俯瞰投影

状態：人間が確認案に対し「ナックルの不規則変化・縫い目の特殊空力も今回に含める」を明示承認。特殊空力を含む範囲を実装・限定検証済み。GitHub保存の結果はv78報告と最新入口に記録する。初期20人の推定一括変更、mainマージはしない。

## 目的と変更前の事実（v77時点）

- 現在の投手調整室は7球種。名前付きオリジナル球の共有保管庫はない。
- 回転は毎球同じvector。既存の「制球」はコース誤差で、回転再現性とは異なる。
- 現俯瞰helper v76は空中の表示直径を掛け算する。今回求められた仮想高度による投影とは違う。
- 世界・ボール物理を先に計算し、粗い中継カメラが観測する設計を維持する。

## 1. 実在球種と名前

基本分類は現Statcastの15種：フォーシーム、シンカー、カットボール、チェンジアップ、スプリット、フォーク、スクリューボール、カーブ、ナックルカーブ、スローカーブ、スライダー、スイーパー、スラーブ、ナックル、イーファス。

ツーシーム、シュート、SFF、サークルチェンジ、スプリットチェンジ、縦スライダー、ジャイロスライダー、高速スライダー、縦カーブ等も、握り・別名・方向の設定例として選べるようにする。同義語を別の未知の力にしない。「世界中の呼称が15個だけ」とは扱わず、資料付きで追加できる分類表にする。

各項目に日本語名・別名・基本分類・設定例・根拠URL・再現範囲を記録する。設定例の球速・回転は特定選手の実測値とは呼ばない。既存7球種の省略時設定とIDは維持し、未知IDをストレート等へ黙って置換しない。

変更前の物理は抗力・重力・Magnus・回転減衰を扱う。ナックルの縫い目による不規則変化、seam-shifted wakeの力は未実装。基本軌道の試投はできても、その特殊現象を再現済みと表示しない。低速球で本塁まで届かない指定は理由付きで拒否し、到達結果を後付けしない。

## 2. オリジナル球の保管庫

投手調整の中に「球種設定」と「オリジナル球の保管庫」の切替を置き、普段は保管庫を閉じておく。球速・回転数・方向・ジャイロ成分を設定し、任意名で保存する。

保存項目は安定ID、名前、基本分類、物理設定、版、作成元。修正保存は新しい版として履歴へ追加する。他の選手へは設定をコピーして付与する。保管庫の後日の編集が、既に割り当てた選手や終了した試合を変更しない。名前をコードとして実行・HTMLとして挿入しない。

個々の球を選ぶIDと「スライダー等の分類」を分け、同じ投手が設定の異なるスライダーを複数持てるようにする。旧選択名fork→splitter、two-seam→sinker等は互換として残し、新しい正式フォークのIDと取り違えない。

保管庫はメーカー保存JSONに含め、ブラウザ内の復元も用意する。移動・バックアップの正本はJSON。試合用JSONには選手へ割り当てた球の完全な設定を含め、通常HTMLが外部保管庫なしで動くようにする。旧JSONの読み込み互換を保ち、新しい保存形式は版付きで厳密に検証する。未保存の入力や不正JSONを黙って破棄しない。

## 3. 投手ごとの回転再現性

主な公開能力・得能とは別に、投手の回転設定の詳細へ「回転の再現性（最低維持率）」を置く。UIでは割合と実際のrpm範囲を併記する。

- 80%：基準1000rpmなら800〜1000rpm。
- 98%：同じ基準なら980〜1000rpm。
- 100%：固定。旧JSONで省略されている場合もこの従来動作。

これは回転数の下振れ幅だけを制御する。回転軸・ジャイロ比・制球・基準回転を書き換えない。既存20人の値を実測したかのように推定・一括変更しない。メーカーで投手ごとに変更できる。

幅のある設定では独立したseed付き乱数列から、毎投球一度だけ係数を取得する。最初は指定範囲の一様分布を作者用モデルとして使用し、実測分布の校正とは区別する。得た初期spinを物理Sourceへ渡すので、変化量・衝突・描画回転は同じ球を参照する。既存の球種選択・制球・打撃の乱数列へdrawを挿入しない。省略・100%ではSourceと乱数順序を旧版と一致させる。

## 4. 俯瞰の仮想高度による遠近サイズ

新設定名は「俯瞰：高さの遠近感」。初期2、1が実高度基準。画面位置は実座標の投影のまま、直径を求めるときだけ地面からの高度を倍率倍として同じカメラで再投影する。地面から2mなら設定2で4m相当、10mなら20m相当の投影サイズになる。直径自体を一律2倍にしない。

座標は球の中心なので、接地時の中心高さ（半径0.0366m）を基準に、浮いた高さだけを倍率倍する。接地した球は基準の小さな白点を維持し、その白点に仮想高度での投影比を適用する。視認用の最小白点によって高さ差が丸ごと消えないようにする。

適用は俯瞰の自由な打球だけ。投球・送球のサイズ、他の視点、画面上の中心位置・影・物理座標・回転・速度・バウンド・守備判断・裁定は変更しない。保持球は非表示のまま。仮想高度がカメラを突き抜ける条件では表示サイズだけ安全上限で止める。

旧設定の「空中直径倍率」を新しい「高度倍率」と同じ意味で読み直さない。版・キーを区別し、旧設定読み込み時には旧方式だと分かる説明と、新方式への明示切替を用意する。通常HTML、カメラ調整室、メーカー内の試合描画は同じhelperを使う。

## 5. 実装順と対象

3. 回転の下限比率をroster → Host / 試投 / 打球比較 → LivePitchへ接続する。基礎値と実行値を分離する。
4. 既存の明るいUIと人間／AIモードを拡張。通常試合の球種選択・配球記号・履歴にも名前を通す。AUTOは所持球だけから選び、持っていない球を勝手に投げない。旧設定のAUTO経路は維持する。
5. V78の通常HTML・調整室・メーカーを作り、既存Draft PR #380へcommit/pushする。mainへはマージしない。

中心となる既存ソースはLivePhysicalRosterV1、LivePitchAuthoringV77、LivePitchV1、LiveBaseballMatchV1、PitcherWorkbenchV77、baseball-maker-pitcher-v77.js、build-maker.mjs、およびball display helper/通常renderer。

実装はこのセッションで主担当が統合し、必要な球種/Coreとメーカーの作業だけ担当を分ける。承認済みの範囲を超える特殊空力は別工程とし、元の計画の未完は消さない。

## 8. 承認された特殊空力の実装

既存の描画と同じ縫い目曲線を、実球のmaterial quaternionで姿勢変換して力を計算する。相対空気速度と縫い目の剥離近傍配置から滑らかな横力を求め、RK4の各段階へ同じ物理として適用する。画面のランダム揺れや、球種名に応じた着弾点補正は使わない。

実験論文で確認した力係数のオーダーと2S/4Sの方向依存を根拠にするが、3Dの近似関数そのものが実験へ校正済みとは表示しない。モデルIDと係数を版付きで保存し、無指定は旧物理の計算と出力形状を完全維持する。持球中は自由球の空力を適用しない。

Sourceの従来orientationは記録起点の相対回転なのでmaterial姿勢と区別する。投球→衝突→打球→捕球→送球でも縫い目位相を連続させる。風との相対速度、姿勢共変性、横力の仕事ゼロ、係数上限、積分刻みの収束を検証する。

無回転でも縫い目の力は残り得る。試投の無回転比較は同じ初期位置・速度・縫い目モデル・姿勢でspinだけを0にし、縫い目横力が必ず0とは説明しない。

回転再現性の下振れと縫い目の実力は、名目spinによる投げ出し計画が終わった後、Sourceの実球へ反映する。投手が同じ投球の回転失敗を先読みして初速度を補償する順序にしない。

根拠追加：[Borg & Morrissey (2014)](https://baseball.physics.illinois.edu/KBall/Borg-AJP-Oct14.pdf)、[縫い目と剥離位置の研究 (2024)](https://link.springer.com/article/10.1007/s00348-023-03751-3)。
