# Mini Baseball — 一般化した守備AIと正史プレーの接続設計

日付: 2026-10-15
状態: **USER-DIRECTED ARCHITECTURE REFINEMENT / IMPLEMENTATION IN PROGRESS**
対象: TBD対LADに限らず、Mini/Natural共通 Match Core 全球場・全チーム

## 1. ユーザー修正の本旨

単一の場面ごとに「一塁走者がいれば二塁へ送球」「二塁でアウトなら一塁へ転送」「満塁なら本塁へ」と結果をハードコードする方法は**禁止**する。

野手AIがプレーを観測・予測・意思決定し、実際の移動／送球／捕球が発生し、その**物理的な観測証拠をもとに**審判が裁定する。三重殺、ホーム併殺、逆方向への併殺、挟殺、カットプレー、送球ミスなどは、AIの戦術と正史の結果として自然に発生すべきであり、「パターン名」で判定を生成しない。

旧v26試作の \`planDefensiveThrow\` に追加された R1-only の \`outcome==='GO' && base===2\` による二塁→一塁の専用分岐は**正本採用禁止／アーカイブ対象**。リリース用設計をその実装へ誘導しない。

## 2. 既存Coreの再利用（重複したAIを作らない）

| 役割 | 既存Source of Truth | 今回の作業 |
| --- | --- | --- |
| 野手が何を認識するか | \`PlayerPerceivedWorldState\`, \`ObservationMemory\`, \`DefensiveDecision\` | 観測時点と信頼度・反応遅延を各判断に渡す。未観測の将来を読ませない |
| 9人の役割・塁カバー | \`TeamCoveragePlan\`, \`TeamCoverageReplan\` | ボール保持者、塁カバー、仲継、バックアップを排他的に割り当てる |
| 失点とアウトの評価 | \`DefenseContext\`, \`ThrowPlan\` | 四塁すべてを候補とし、2回目以降の送球も同一手続きで再評価 |
| 送球の実物理 | \`CoverageThrowExecution\`, \`ThrowLaunch\`, \`BallTransferTiming\`, \`DefenderThrowReceptionContact\` | 出力は実行要求。捕球したかどうかはプレー世界で証明 |
| 走者の意思決定と実走 | \`RunnerDecision\`, \`RunnerLocomotionController\`, \`RunnerBaseTouch\` | フォース進塁は身体動作となり、走者がタッチ前に塁へ着いたか実測 |
| 送球が実際にアウトを作るか | \`ForceObligation\`, \`ForceOutRule\`, \`TagContact\`, \`RuleEngine\` | AIが OUT を書き込まない。守備の予測と最終公式裁定は別の証拠 |

## 3. 1プレーを単一のシミュレーションとして進める

\`\`\`text
打球物理 → 野手・走者の局所観測（情報が遅延する）
  → 守備の役割分担／ボール追跡／塁カバー
  → 各野手の到達可能時間・候補送球先・期待アウト・失点危険を比較
  → 保持者が球を携え、投げる／持ち替える／塁を踏む／走者へタッグする
  → 実球飛翔と受球・確保・ベース接触・走者触塁
  → 行動変化や実際のセーフ・アウトを見た後、観測できた野手だけ再計画
  → Official rulesが正史イベントから判定・得点・次打者を確定
  → Presentationは採用イベントと位置を再生するだけ
\`\`\`

「守備AIが併殺を計画した」ことと「本当に併殺になった」は別。フェンス、送球の逸れ、野手の遅れ、走者のタッチ、観測したのに勘違いした意思決定のいずれも結果を変え得る。

## 4. 候補生成・検索の一般原則

プレー時点の同じ world state から、

1. 塁1〜4と各塁へ物理的に届く全野手（中継も含む）を候補とし、各受け手の移動・グラブ準備・球の移送・送球飛翔・保持時刻を別々に計算する。内野守備位置の既定ロールを固定受球者としない。
2. 走者の次塁到達時刻は \`RunnerLocomotionController\` 等の正史、又は**実行前の観測に基づく予測**から算出。遅い走者を「遅いに違いない」とラベルで処理しない。
3. \`ForceObligation\` を各予想アウトの時刻順に遷移させる。直前のアウト／触塁によってフォースが消えた場合は、次の塁踏みを勝手にフォースアウト扱いしない。タグやアピールが必要なら別の実行行動が必要。
4. 1次送球から2次送球、必要なら3次動作まで**有限の先読み**を行う（各段階で受け手が次の保持者になる）。「二塁→一塁」「本塁→一塁」は探索された行動列であって、コーディングされた専用パターンではない。
5. 評価は役割・点差・イニング・アウト数・時間差・送球失敗リスク・失点阻止を根拠に比較し、無理なアウトを狙わず進塁抑止／中継／保持を選ぶ余地を残す。
6. 守備知能は**認識できる候補の質・先読み深さ・反応時間・再計画能力**に作用する。AIが通常できる正しい送球を全員一律「第1塁へ」と固定することとは無関係。
7. 将来の速度・結果・相手の指示をカンニングしない。観測時刻が未来の情報や受け手不在、未確保の球などは拒否・待機して正史を捏造しない。

## 5. 公式野球ルールの不可侵条件

MLB公式 \`Force Play\`（https://www.mlb.com/glossary/rules/force-play）および Official Baseball Rules 2025 Force Play注記:

- 打者がフェア打球で走者になり、前の塁にとどまれない走者にフォース進塁義務ができる。
- 一塁で先に打者走者をアウトにすると、その後の既存走者のフォースは**解除される**。塁を踏むだけではアウトにならず、タッグなど別の合法手段が必要。
- 満塁の本塁フォースも、三塁走者が本塁へ到着する前に捕球済みの野手が本塁を確保して初めて成立する。本塁→一塁の連携も、2回の合法な別々の動作でのみ併殺が成立し得る。
- 飛球の正規捕球やインフィールドフライは打者走者のフォース状態を変える。帰塁・タッチアップは別の規則と物理時刻で判定し、ゴロのフォース状態で使い回さない。
- 3アウト目のフォースアウトや打者走者の一塁到達前アウトは得点成立との前後関係も規則に従う。アウト表示を先に予約して得点計算を後から合わせない。

## 6. 受入ゲート

- 一塁走者／一二塁／満塁／走者なし、0/1/2アウト、全ての野手が保持者になり得る状況で一つの探索器を使う。条件ごとにカスタム「併殺結果」関数を増設しない。
- 一つの同一入力で「二塁→一塁」「本塁→一塁」「一塁で打者OUT→二塁はタグでなければ不可」等をパラメータの違いから自然に導出できる。
- 複数送球で、実際の移動・持替え・飛翔・保持時刻が単調増加。先の送球完了前に次の送球を撃てず、存在しない野手を瞬間移動させない。
- 守備AIが予想した OUT が未確定の時点では公式 outs は増えず、誤送球・守備機会損失を表現できる。
- 打撃結果、公式得点・塁上走者、球・野手・走者の描画は**同じ正史タイムライン**に帰属。球場が変わっても共有 field world geometry から座標を生成。
- 同じ乱数seedと指示、同じ正史world初期状態なら描画ON/OFF・PC/スマホ・2倍ボール表示で公式結果が一致。
- 既存の \`ForceDoublePlayVerticalSlice.test.ts\`, \`P1RuleAcceptanceMatrix.test.ts\` と連動するテストを強化する。現在未完のLAN01/公式実LIVE全打席を捏造PASSしない。

## 7. 現時点の本番境界

旧v23/v26は独立ブラウザ試作の試合計算であり、正式Native Coreの \`GroundBallProductionOutcomeCoordinator\` にも主として一塁アウトを完結させる境界が残る。今後は一般化した守備**判断だけ**を先に接続し、物理時刻を持つ実際の送受球・走者・審判が揃ってから公式プレー終了を接続する。基礎AIを仮のアウト確率判定へ置き換えて通過させることは禁止。

デザインはv23 PNG原画を保存。ボールの大きさ・回転拡大表示の要求変更は純粋なPresentation問題として別実装し、AI・物理・裁定にフィードバックしない。
