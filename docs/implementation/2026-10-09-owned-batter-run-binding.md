# Owned batter swing-exit and explicit run binding

This batch connects the existing Core swing-exit recovery, runner intent, route,
and analytic motion laws to Native accepted originals and the same-PA physical
field writer. It introduces no physiological parameter values, default intent,
or autonomous decision policy.

## Accepted originals

- `world_player_batter_run_transition_models` accepts the existing Core recovery
  limits and pins an original Player runner decision/motion model. Career,
  Player, Person link, accepted day and clock must agree. These parameters are
  explicit accepted model input; test values are synthetic Core fixtures.
- `world_batter_swing_exit_states` pins an original physical field cut and that
  transition model. Root position and velocity come from the original body
  primitive and accepted static body offset. The retained primitive's fractional
  start offset is preserved. Body forward is separately accepted input: neither
  the bat axis nor velocity direction supplies it. Vertical root motion is
  unsupported by the planar recovery law.
- `world_batter_run_plans` accepts an original issued `advance` intent, original
  provenance, Player/Person, historical view, physical pitch, exit state and
  finite straight route through first base. The issued tick must equal the
  authenticated active view cut. With no issued intent, the pure composition
  returns pending. Bat/ball contact does not create an intent.

Each archive preserves canonical Source and snapshot bytes/hashes and exact
main-table/index identity, discovers raw duplicate-key claims, and rejects an
absent original with a surviving typed child. The established Native producer
transaction brackets each proof with query-only ownership, accounts for exactly
one insertion, rederives after the insertion and verifies after commit. Retry
reuses the original without requesting another accepted input.

The plan is lifecycle work. Its fresh writer checks a current view before
insertion, then the original historical view, reserved state, and the prefix
extended by exactly that new plan after insertion. Lifecycle registration is a
coordinated companion change, required before using this owner end to end.

## Actual motor connection

`batter_run_motion_v1` is an additive physical field action containing only the
owned plan reference. The Native reader authenticates its original actor,
lineage, pitch and plan. The physical helper supports zero-recovery straight
translation with all five original body shapes. Every part must retain its
original static offset, velocity relation, radius and acceleration relation.

The helper checks actual position/velocity against the plan at the exact
physical cut, and adopts only the current constant-acceleration segment through
the existing field checkpoint kernel. It preserves every other actor's current
acceleration and caps coverage by all prior actor horizons, plan end and the
analytic segment boundary. Canonical floating-point reconstruction uses the
existing 32-epsilon arithmetic bound; it is not a motion or contact tolerance.

The real field endpoint is execution evidence. A plan, controller horizon or
accepted future primitive horizon is not execution. A real collision may stop
before the requested checkpoint. Advancing beyond an exhausted actor horizon
requires a separately owned physical continuation; this batch does not renew
unrelated actor commands or manufacture body/foot evidence.

Nonzero recovery remains a calculable plan whose root/facing trajectory still
needs a defined five-part physical pose binding. A later first adoption also
requires a newly matching owned exit cut; no unexecuted plan is treated as prior
body motion. Unsupported recovery, vertical motion and changed part poses fail
explicitly.

## Evidence and limits

Missing model/state/intent/motor APIs produced focused expected REDs. The light
author batch passed 33 cases: 11 real Native model/archive cases, 9 exact-cut
projection cases, 7 existing-law intent composition cases, 5 actual Core
five-part field checkpoint cases, and 1 Native missing-physical-owner boundary.
The Core field cases use explicit structural fixtures and are not claims of a
complete Native same-PA ancestry. Native state/plan acceptance through a genuine
retained field, the companion lifecycle registration and the full compiler
remain for the consolidated batch validation. No new genuine Native physical pitch or flight
was constructed for author validation; Core tests use synthetic flight input. Protected18 and frozen base source
remain unchanged.


## Bounded continuation follow-up

The same issued plan can now adopt successive analytic runner pieces, including
at the exact covered endpoint of the preceding piece. The original finite plan
owns those future runner commands; every new piece still starts at the actual
body state and stops at a real contact or its requested checkpoint.

Runner-only rebases shorten all stored primitive horizons together. The reader
recovers each foreign actor's still-owned horizon from the authenticated field
prefix. Unchanged actor curves retain that horizon; another physical command
replacement resets it. An older cancelled horizon cannot be resurrected.

For genuinely exhausted foreign work, an optional accepted
`stationaryHoldContinuations` item pins the latest original defender decision
and a finite new horizon. Its decision must select `hold`, have no target, and
already be due. All five actual parts must have exactly zero velocity and zero
acceleration at a covered current cut. No moving/braking/accelerating command
is extrapolated beyond its controller boundary. The Native physical action
owner authenticates the original decision through the same field prefix.

The materialized pose is not declared to be a rigid body-local frame:
`AcceptedPoseSource` stores role offsets, and
`composeDefenderPhysicalPrimitiveSegment` adds independently accepted offset
velocities/accelerations to root motion without an orientation input. Shared
Player identity and temporarily static offsets do not authorize rotating the
feet/glove with body-forward. Core recovery supplies root/facing samples, but a
rotating five-part attachment and its collision trajectory are still undefined.
No gait or attachment policy was introduced here.

The continuation author group covers repeated pieces, retained/cancelled foreign
horizons, stationary hold renewal, and rejected moving/accelerating, not-due,
non-hold or missing decisions. One synthetic Core case executes the actual body
past first base in two pieces while retaining the original plan's
`motionExecuted: false`; it makes no official base-touch or safe/out claim.
Full Native ancestry and combined compiler validation remain separate.

This adapter still requires exact integer adoption cuts. A controller boundary
between ticks stops at the preceding covered tick; it is not rounded across or
extrapolated. Core already exposes exact elapsed-time field checkpoints, so a
future additive continuation can connect that defined sub-tick path. The present
16-case continuation author group passed; it is not a full Native/whole-suite
qualification.
