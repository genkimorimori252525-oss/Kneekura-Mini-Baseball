# Piecewise scheduled capture and transfer Core

This additive Core capability changes future actor-acceleration pieces during a scheduled operation while preserving its original physical and timing evidence. Native Source ownership, complete ten-Player composition, independently due work, persistence and end-to-end adoption are connected in the following slice.

## Immutable operations and actual pieces

- Acquisition keeps original contact, retention energy, dissipation power, secure time and confirmation fence. The incoming-to-constrained transition occurs once. The actual secure moment is saved before later pieces and remains unchanged
- Transfer keeps original start/readiness, ratings/calibration and deterministic stream identity. The reached release samples the actual current carrier origin and receiver glove. The raw release cursor remains distinct from the actual free/contact response
- Preparation validates current actor coverage without requiring a fabricated future command through completion. Progress stops at coverage, actual contact, secure/fence or release; unfinished work remains pending
- A retained checkpoint keeps the active piece's original anchor. A real command change validates every original primitive's identity, clock, radius, position and velocity, changing only its supported acceleration
- The constrained glove remains in the complete actor set and real boundary evidence. Only its already validated constraint pair is excluded as an independent competing collider; other roles, Players, ground, walls and bases remain active
- A release removes that constraint and uses the existing zero-duration free-query/departure semantics. Subsequent free motion can still encounter the former carrier glove at the same physical cut

Legacy bridges rederive the original plan/progress and begin the new continuation at the validated current cut. Unexecuted legacy transfer commands are not relabeled adopted truth. Historical legacy roots and snapshots remain unchanged.

## APIs

`BattedWorldPiecewiseFieldAcquisition` and `BattedWorldPiecewiseFieldThrow` each expose preparation, plan validation, an explicit legacy bridge, progress derivation from recorded steps, and full progress validation. Steps select retained actors or a complete internally supplied adopted actor set, and request an exact elapsed endpoint. Native must derive that set from owned contributions; this Core API does not establish database provenance.

`deriveBattedWorldFieldMotionAdoption` adds ordinary zero-time adoption at an exact integer cut. It pins the original origin clock and primitive radii, preserves actual state, and records real immediate contact without epsilon progress.

## Stable contact roots

The new piecewise path uses horizon-independent coefficient-derived dyadic root intervals for non-axial actor and panel/base edge/corner contacts. Requested checkpoints filter the same candidate roots, rather than changing their numerical basis. Exact-sign fallback resolves uncertain floating-point polynomial signs; reversible binary scaling rejects unsupported coefficient precision loss. Existing tolerances and legacy numerical paths are preserved.

This avoids both checkpoint-dependent contact bytes and early contacts at genuinely exact dyadic endpoints. Querying an entire future coverage interval merely to stabilize a short prefix was rejected: an otherwise valid prefix must not fail because an unexecuted tail overflows.
