# 実装ロードマップと検証計画

更新日: 2026-09-17
状態: 設計済み・実装未着手

## 前提

本リポジトリは新規の製作拠点である。先行エンジンを移植する場合も、描画を含む一括コピーはしない。まず、モデル・規則・試合進行・テストを独立したコアとして取り出し、設計文書の契約に合わせて段階的に置き換える。

各フェーズは前フェーズの回帰テストが通ることを開始条件とする。UI は最後に接続するため、表示の都合で規則や物理を変更しない。

## フェーズ

### P0: 移植の境界を確定する

成果物:

- ソース候補のライセンス・依存関係・テスト資産の一覧
- `MatchState`、`RuleEngine`、打球、守備、走塁、表示の依存関係図
- 本リポジトリにおけるコアパッケージの最小構成

完了条件:

- 描画に依存しない試合コアをビルド・テストできる。
- 乱数シードを固定して同じプレーを再現できる。

### P1: NPB規則の核をテストで固定する

成果物:

- `RuleProfile` と初期 `npb-2026` 実装
- アウト、得点、フォース、ファウル、インフィールドフライ、タッグアップのテスト
- 第三アウトの得点取消を含むルール遷移

完了条件:

- `02-rules-ratings-defense.md` の規則テストが通る。
- 得点判定がアニメーションの順番ではなく、規則上のアウト種別と時刻で決まる。

### P2: 明示的なワールド状態へ整理する

成果物:

- ワールド座標・時刻を持つ打球、野手、走者、送球のモデル
- 走者ごとの状態（塁、方向、意思決定、到達予定）
- 時刻付きイベント列と、ルール確定状態の分離

完了条件:

- 同一の入力とシードなら、カメラや再生速度を変えても最終試合状態が変わらない。

### P3: 査定基盤を導入する

成果物:

- 公開査定と隠し査定のスキーマ
- 位置別適性、送球精度、初動、打球判断、走塁判断、捕手能力の最初の実装
- 能力の導入根拠・影響箇所・比較テストの査定台帳

完了条件:

- 能力を一つ変更したときの影響が、重複せずテストで説明できる。
- UI に隠し能力・心理ゲージを漏らさない。

### P4: 守備AIを局面判断へ置き換える

成果物:

- `DefenseContext`、`DefenseIntent`、`CoveragePlan`、`ThrowPlan`
- 動的カバー、中継、バックアップ、捕球後の送球候補比較
- 勝敗条件を含む共通の期待損失評価

完了条件:

- サヨナラ失点を防ぐ選択を、固定的なアウト優先より上位に置く。
- 処理野手・カバー・中継・バックアップの役割が競合しない。

### P5: 個別走塁と特殊プレーを拡張する

成果物:

- タッグアップ、盗塁、牽制、ランダウン、進塁／帰塁の個別判断
- 捕手送球、投手クイック、野手タグの相互作用

完了条件:

- 同じ打球でも走者能力・アウトカウント・得点差で合理的に結果が変わる。

### P6: 一打席采配を接続する

成果物:

- 投手命令・打者命令・詳細指示のデータ定義
- 命令を投球／打撃／走塁の意図へ変換するアダプタ
- 実行不能・不利な命令を説明する検証

完了条件:

- 采配は次打席の意図として一度だけ受理され、球ごとの入力待ちを作らない。

### P7: 監督モード表示を接続する

成果物:

- 縦画面のスコアボード、B/S/O、三塁マーカー、選手カード、横スクロール命令帯
- 打者／投手視点と、打球後の真上カメラ
- ドット／点描の球場レンダラ

完了条件:

- 9回別 `R/H/E`、正しい走者マーク、右赤／左青の表示を持つ。
- 表示切替によって試合のイベント列・最終状態が変化しない。

### P8: 検証用試合と観測を整備する

成果物:

- 代表局面の固定シード試合集
- ルール判定、守備案、走塁案、最終結果のデバッグログ
- 再現性テストと性能テスト

完了条件:

- 不自然な結果を、入力・能力・乱数・規則判定・守備判断まで追跡できる。

## 実装の優先順位

`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8` の順で行う。

先に見栄えを作ると、表示に合わせた結果の作り直しが入りやすい。今回の目的では、P1〜P5 の野球としての正しさを先に保証し、その正史イベントを P7 で可視化する。

## フェーズごとのレビュー観点

| フェーズ | ユーザーが評価する問い |
| --- | --- |
| P1 | NPBの規則として不自然な得点・アウトは残っていないか |
| P3 | 公開能力は分かりやすく、隠し能力は必要十分か |
| P4 | 守備がサヨナラ・同点・追加進塁の危険を正しく優先するか |
| P5 | 走者が状況を読んでいるように見えるか |
| P6 | 一打席単位の采配として納得できるか |
| P7 | 速報風の画面が試合の正しい状態を表示しているか |

## 現時点のリスクと仮定

- `NPB 2026` の大会別運用は、実装直前に公式文書で原文照合する必要がある。
- 打球物理・守備・走塁を詳細化すると、軽量性とのトレードオフがある。P8 でプレー単位の計算予算を測定する。
- 隠し査定を増やしすぎると、プレイヤーが結果を理解できなくなる。公開値への集約とプレー後の因果説明を別途検証する。
- 先行エンジンに既存の不整合があっても、その挙動を互換仕様として移植しない。P1 のルールテストを正とする。
