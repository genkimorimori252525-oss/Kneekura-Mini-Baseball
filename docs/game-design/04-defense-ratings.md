# 守備能力・運動モデル設計

更新日: 2026-09-17
状態: 実装前の仕様。`02-rules-ratings-defense.md` の守備査定を詳細化する。

## 1. 目的

守備能力は「アウト率を直接上下させる補正値」ではなく、正史ワールド上での反応、移動、捕球、送球、役割変更の差として作用させる。

同じ打球、同じ初期配置、同じ乱数シードでも、選手能力が異なれば次の量が変わり得る。

- 動き始める時刻
- 加速と到達時刻
- 打球への入り方
- 捕球成立率と捕球姿勢
- 捕球後の持ち替え時間
- 送球速度と誤差
- 次に取るべき役割を認識する時刻
- タッグ成立時刻

能力値は、結果を後付けで変更するためではなく、この過程を計算する入力としてのみ使う。

## 2. 公開能力と内部能力の境界

プレイヤーに公開する守備系能力は、当面次の三つに集約する。

- `守備力`: 初動、打球判断、追い方、捕球、状況判断などをまとめた分かりやすい総合値
- `肩力`: 実送球速度を主に表す公開値
- `守備位置適性`: その守備位置での経験・技術適合度を表す

`走力` は走塁だけの値にはせず、守備時の最高移動速度にも使う。ただし短距離の到達差を走力だけで決めない。

公開値は内部能力の完全な逆算表にはしない。同じ守備力でも、反応型、安定捕球型、判断型など異なる選手を作れるようにする。

## 3. 初期採用する守備内部能力

```ts
type DefensiveRatings = {
  positionSuitability: PositionSuitabilityMap;
  firstStep: Rating;
  acceleration: Rating;
  battedBallRead: Rating;
  routeEfficiency: Rating;
  catching: Rating;
  transfer: Rating;
  armStrength: Rating;
  throwingAccuracy: Rating;
  situationalAwareness: Rating;
  tagSkill: Rating;
};
```

### 3.1 守備位置別適性 `positionSuitability`

登録守備位置とは別に、各守備位置でどれだけ自然にプレーできるかを持つ。

主な影響:

- 打球判断の補正
- 追い方の安定性
- 塁カバー・中継位置の理解
- 捕球後の姿勢と送球移行

守備位置適性が低い選手でも任意座標へ配置できる。ただし「センター登録だから内野に置けない」のではなく、内野で要求される処理への適性不足が実行差として現れる。

### 3.2 初動 `firstStep`

打球を認識してから身体を動かし始めるまでの反応遅延に使う。

これは最高速度や加速とは分離する。足が速くても反応が遅い選手、足は平均的でも初動が速い選手を表現できるようにする。

### 3.3 加速 `acceleration`

今回追加する能力。

守備では数メートルから十数メートルの短距離競争が多いため、最高速度だけでは到達時間を説明できない。`走力` が主に最高速度を決め、`acceleration` がそこへ到達するまでの時間を決める。

```text
reaction delay
  → acceleration phase
  → capped running speed
  → braking / arrival
```

方向転換能力は初期段階では独立能力にしない。加速、追い方、守備位置適性から派生させ、独立した差が必要だと検証された場合のみ後から分離する。

### 3.4 打球判断 `battedBallRead`

打球速度、角度、回転、バウンド、風、壁との関係から、将来のボール位置をどれだけ正しく予測できるかに使う。

判断が悪い場合は、選手そのものを遅くするのではなく、最初の目標点や予測軌道に誤差を持たせる。

### 3.5 追い方 `routeEfficiency`

予測した捕球点へどれだけ効率よく移動できるかに使う。

- 外野フライの弧を描く追走
- 内野ゴロへの回り込み
- 壁際での進入角度
- 後逸時の追跡

などを同じ能力から扱う。

### 3.6 捕球 `catching`

ボールとの接触位置、速度、姿勢、グラブ方向、バウンド難度などを入力に、捕球成立と処理後の安定性へ作用させる。

単純な `catching = 90 なら 90%成功` にはしない。易しい打球は低能力でも高確率で処理し、難しい打球ほど能力差が拡大する関数にする。

### 3.7 送球移行 `transfer`

捕球後、ボールを握り替え、投げられる姿勢へ移るまでの時間へ使う。

併殺、中継、捕手送球など短時間プレーで特に効く。初期段階では「フットワーク」を独立能力にせず、`transfer + positionSuitability + routeEfficiency` から捕球後の姿勢補正を作る。

### 3.8 肩の強さ `armStrength`

送球の初速と、距離に対して維持できる実効速度へ使う。公開能力の `肩力` はこの内部値を主成分として表示する。

### 3.9 送球精度 `throwingAccuracy`

狙った受け手・中継点・タグ可能位置からの送球誤差へ使う。

肩が強いことと正確であることは分離する。

### 3.10 状況判断 `situationalAwareness`

今回追加する能力。

打球そのものを読む `battedBallRead` と、野球の局面を読む能力を分離する。

主な影響:

- 自分が処理役でないと判断する時刻
- 一塁、二塁、本塁などのカバーへ切り替える時刻
- 中継・バックアップの必要性を認識する時刻
- 走者の動きに応じた再計画の遅延
- 捕球後に候補送球先を認識できる情報量

ただし守備AIの共通目的関数そのものを選手ごとに変えない。低い `situationalAwareness` は「サヨナラなのに一塁を優先したい性格」にするのではなく、正しい局面情報を認識するまでの遅れや候補の見落としとして表現する。

### 3.11 タッグ `tagSkill`

送球を受けてから走者へタグを成立させる時間と、難しい捕球姿勢からのタグ精度へ使う。

## 4. 初期段階では独立させない能力

以下は現時点では専用能力にしない。

| 候補 | 初期の扱い |
| --- | --- |
| 方向転換・俊敏性 | `acceleration + routeEfficiency + positionSuitability` から派生 |
| フットワーク | `transfer + routeEfficiency + positionSuitability` から派生 |
| ジャンプ・ダイビング | 身体条件、走力、加速、捕球から派生。必要性を検証してから追加 |
| 壁際守備 | `battedBallRead + routeEfficiency + positionSuitability` から派生 |
| 中継技術 | `situationalAwareness + throwingAccuracy + positionSuitability` から派生 |
| 併殺技術 | `catching + transfer + situationalAwareness + positionSuitability` から派生 |
| コミュニケーション | 初期は守備計画側の共有情報として扱う。選手差が必要と確認できた場合のみ追加 |

能力値を細分化すること自体を目的にしない。別能力として追加するのは、既存値の組み合わせでは再現できない独立したプレー差が検証できた場合だけとする。

## 5. 移動計算への接続

守備到達時間は概念的に次の要素へ分解する。

```text
recognitionTime
  = contactTime + firstStepDelay

predictedTarget
  = battedBallRead(ballPath, context)

movementPath
  = routeEfficiency(currentPosition, predictedTarget)

arrivalTime
  = movementModel(
      pathLength,
      publicRunSpeed,
      acceleration,
      currentVelocity,
      fatigue,
      surface
    )
```

重要なのは `守備力 → 到達時間を直接 -0.2秒` のような総合補正を作らないこと。各能力は意味のある中間量を変える。

## 6. 守備判断への接続

9人全員の守備計画は、能力によって目的を変えるのではなく、選手が持つ情報と実行可能時刻を変える。

```text
共通の正しい局面価値
        ↓
各選手が認識できている情報
        ↓ situationalAwareness
候補役割と認識時刻
        ↓
移動・捕球・送球の実行能力
        ↓
正史イベント
```

これにより、監督の読み、守備AIの局面評価、個々の選手の実行を別々に検証できる。

## 7. 最初に行う能力分離テスト

実装時には、同じシードと同じ打球を使い、能力を一つだけ変える比較試験を持つ。

- `firstStep` だけを変える → 動き始める時刻だけが主に変わる
- `acceleration` だけを変える → 短距離到達時間が変わるが認識時刻は変わらない
- `battedBallRead` だけを変える → 初期目標点・修正回数が変わる
- `routeEfficiency` だけを変える → 走行距離・進入角が変わる
- `catching` だけを変える → 到達可能性を変えず捕球成立差が出る
- `transfer` だけを変える → 捕球時刻を変えず送球開始時刻が変わる
- `armStrength` だけを変える → 送球開始時刻を変えず送球到達時刻が変わる
- `throwingAccuracy` だけを変える → 送球速度を変えず到達位置誤差が変わる
- `situationalAwareness` だけを変える → 身体能力を変えず役割切替・再計画時刻が変わる
- `tagSkill` だけを変える → 送球到達時刻を変えずタグ成立時刻が変わる

この分離テストを通せない能力は、別査定として持つ意味が薄いと判断する。

## 8. 現時点の結論

現在の守備査定案は大筋で十分である。ただし、連続空間の9人守備をNatural Baseballまで持ち上げるため、初期採用候補へ次の二つを追加する。

1. `acceleration`: 短距離の到達差を最高速度から分離する。
2. `situationalAwareness`: 打球判断と、カバー・中継・送球候補などの局面判断を分離する。

それ以上の細分化は現時点では行わず、シミュレーション結果に独立した不足が見つかったときだけ追加する。
