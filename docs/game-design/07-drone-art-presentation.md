## 1. 目的

Mini Baseball の打球後表示は、滑らかな3Dアニメーションを縮小したものにはしない。

ゲームボーイのように「細かいマスをコマが移動している」と認識できる離散的な見た目を保ちつつ、粗すぎて守備経路・送球・走塁・打球の高さ・バウンドが読めなくならない細密さと速度を持たせる。

この表示は試合結果を作る層ではない。`CanonicalWorldSnapshot` / 正史時間軸を観測する Mini 固有の Presentation Adapter であり、将来 Natural Baseball が3D描画へ置換されても Match Core は共通のままとする。

## 2. 確定した表示方針

### V-001: 連続物理はCore、画面は細密グリッド

Core 内のボール、野手、走者、送球は連続ワールド座標と正史時刻を持つ。

Mini の表示だけが、その時刻の正史座標を細かい表示格子へ量子化する。

```text
Canonical world position
        ↓
Presentation sample
        ↓
Fine-grid quantization
        ↓
Mini overhead display
```

表示格子へ丸めた座標を Core へ戻してはならない。表示上同じマスに見える二つの位置でも、Core 上の実座標・速度・到達時刻は独立して保持する。

### V-002: 4px細密グリッドを基準とする

プロトタイプで採用した最終基準は以下とする。

- 基準 viewBox: `600 x 430`
- 表示グリッド: **4px相当**
- 野手・走者コマ: 約 **10px** を基準に端末スケールへ比例変換
- 地面付近のボール基準半径: 約 **3.3px**。実際の表示半径は後述する正史高度から段階的に変化させる
- 球場線・塁・マウンドも同じ基準座標系上へ描画する

実際の端末で拡大・縮小される場合は全体を比例スケールする。`4px` は物理単位ではなく、基準表示座標における視覚仕様である。

### V-003: ヌルヌルした補間を禁止する

選手やボールを CSS transition、tween、ease、連続補間アニメーションで滑らせない。

表示位置は各 Presentation Sample ごとに更新し、次のサンプルまでそのマスに留まる。

```text
sample n      sample n+1      sample n+2
   ■      →       ■      →       ■
```

「前フレームから次フレームへ滑る」動きではなく、「短い間隔で細かいマスへ移る」動きにする。

### V-004: 滑らかさはサンプル密度で出す

カクつきを減らすために見た目専用補間を入れるのではなく、正史状態をより細かい時刻間隔で観測する。

本番実装では、プロトタイプのように表示側で二つのキーフレームを `lerp` して架空の位置を作ることを禁止する。

必要な中間位置は次のどちらかから得る。

1. Core が保持する十分に細かい `CanonicalWorldSnapshot`
2. Core が定義した決定論的な正史 Motion Segment を、Presentation が指定時刻で読み取った位置

どちらの場合も、表示側が野球結果・移動経路・捕球時刻を新しく決めてはならない。

### V-005: 攻守はチームカラーで識別する

通常プレイでは、守備役割ではなく **チーム所属** を色の主な意味とする。

- 守備側9人は、その時点の守備チームの表示用チームカラーで統一する
- 打者・走者は、その時点の攻撃チームの表示用チームカラーで統一する
- 攻守交代時は、同じ選手でも現在の所属チーム色は変えず、画面上の「守備側 / 攻撃側」の役割だけが入れ替わる
- 両チームの色が近く識別しにくい場合は、縁取り・明度差・コマ形状・短い識別文字などを補助に使う
- 主処理野手、塁カバー、中継、バックアップなどの役割色分けは本番標準には使用しない。デバッグ時のみ許可する

チームカラーはプレー結果や物理へ影響しない Presentation 情報である。

### V-006: ボールの高さを表示サイズへ変換する

真上視点では、平面座標 `(x, z)` だけではゴロ、ライナー、フライ、ポップフライの高さが伝わりにくい。

そのため Mini では、Core が持つ正史3Dボール位置 `(x, y, z)` のうち **`y`（地面からの高さ）を表示上のボールサイズへ写像**して、遠近感・高度感を補助する。

```text
Canonical Ball State
  position.x / position.z → 4px fine-grid position
  position.y              → discrete ball-size tier
```

重要な原則:

- 「フライだから大きくする」「ゴロだから小さくする」という結果ラベル駆動にはしない
- `ball.y` が同じなら、打球分類に関係なく同じ表示サイズ規則を使う
- サイズは連続Tweenで膨張・縮小させず、Presentation Sample ごとに段階的なサイズへ量子化する
- 画面の高さ表現を理由に、Core のボール座標・速度・衝突時刻を変更しない

初期の視認性基準は5段階程度を想定する。

```text
Tier 0: 地面付近 / 低いバウンド
Tier 1: 低い空中軌道
Tier 2: 中程度の飛球
Tier 3: 高いフライ
Tier 4: 非常に高い飛球
```

具体的な高度閾値と各半径は、P2で確定するボール物理スケールとP8の視認性試験から決める。表示半径は地面付近の約3.3pxを基準に単調増加させるが、巨大化しすぎて守備コマや塁を隠さない上限を持たせる。

この方式は厳密な透視投影そのものではなく、**正史高度に根拠を持つ離散的な高度キュー**である。平面 `(x,z)` の正確な読解を優先し、ボール高度のために平面座標を視覚的に歪めない。

### V-007: バウンドも正史物理から見せる

ゴロのバウンドは Presentation が演出として生成しない。

Core 側で、少なくとも以下の正史物理から接地・反発後の運動が決まる。

- 接地直前のボール速度ベクトル
- ボール回転
- 地面との衝突
- 反発係数
- 摩擦
- 芝・土・人工芝などの Surface Profile
- 必要に応じて地面状態

```text
ground collision
    ↓
post-impact vertical / horizontal velocity
    ↓
ball.y rises or stays low
    ↓
Presentation size tier changes automatically
```

したがって、強いゴロ、ボテボテのゴロ、高いバウンド、低い跳ねは「ゴロ用アニメーション」の違いではなく、正史物理の違いとして画面に現れる。

バウンド時に `ball.y` が上がれば表示サイズも一時的に大きくなり、再び落ちれば小さくなる。これによりラベル表示なしでも接地・反発を読み取りやすくする。

### V-008: 地面基準の影 / 高度マーカーを許可する

ボールの高さをさらに読みやすくするため、地面上の位置を示す小さな影または高度マーカーを表示してよい。

- 基準位置は正史 `(x,z)` の地面投影から導出する
- 光源方向を使う場合も、固定された Presentation Profile から決定論的に導出する
- 影の位置や大きさからボール物理を逆算してCoreへ戻さない
- 影はボール本体より目立たせず、ゴロ時には高さゼロに近いことが直感的に分かる表現にする

P8の視認性テストで、ボールサイズだけで十分に高度が伝わる場合は影を弱くするか省略できる。高度を捏造するための自由演出にはしない。

### V-009: 打球分類は表示結果ではなく観測結果

`ground_ball`、`line_drive`、`fly_ball` 等の分類を統計・記録・デバッグ用途で持つことは許可する。

ただし Drone-Art Renderer は分類値を見て「ゴロ用軌道」「フライ用軌道」を選択してはならない。

```text
launch velocity / angle / spin
       ↓
physical trajectory
       ↓
(x, y, z) + collisions
       ↓
Drone-Art display
       ↓
human sees grounder / liner / fly
```

分類は正史物理から派生する情報であり、表示軌道を作る原因にはしない。

### V-010: 監督モードのストライクゾーンは打者ごとのcanonical geometryを投影する

監督モードの投球前表示では、`BATTER_POV` と catcher-behind `PITCHER_POV` の両方にストライクゾーンガイドを出す。

現時点の暫定生成ポリシーは **Height-Ratio V1**:

```text
heightMeters
  ↓
upperY = height × 0.535
lowerY = height × 0.270
width  = 0.4318m
  ↓
StrikeZoneRegion
  ↓
POV camera projection
  ↓
4px表示空間のガイド
```

- 身長が変われば縦寸法と上下位置が変わる。
- 画面中央に固定された同じ長方形を全打者へ使わない。
- 53.5% / 27%は2026 MLB ABSを参考にした暫定値であり、NPB人間球審の規則定義そのものとして扱わない。
- 将来フォームまで正史化する場合、肩 / ズボン / 膝のbody-landmark policyへ交換可能にする。
- policyを交換しても下流の `StrikeZoneRegion` / camera projection契約は不変とする。
- ガイドのcanonical geometryと、人間球審が実際に宣告するeffective called zoneは分離する。
- 人間球審の誤審・count bias・捕手フレーミング等が将来入っても、ガイドの真値をそれに合わせて歪めない。
- ガイド色は黄色 `#e0b541`（2026-09-21ユーザー指示）。4px格子の点線と四隅を使用し、白球の優先表示を維持する。
- ガイド表示・スタイルをCore判定へ逆流させない。

### V-011: 配球履歴は現在の打席の確定済み観測を表示する

投球ごとに番号付きの位置と、球速・球種・結果の一覧を追加する。次の打席が始まった時点で表示をリセットし、番号は1からにする。途中の選手交代や視点変更だけでは消さない。

打席ID・投球ID・観測時刻で管理し、同じ投球の結果更新や再描画で行を増やさない。判定・カウント・位置を表示側で捏造しない。過去の配球記号より飛行中の白球を優先する。具体的な配色、重なり、入力不足と接続境界は[配球履歴の描画契約](../presentation/2026-09-21-pitch-history-presentation-contract.md)を参照する。

## 3. 確定した再生テンポ

最終プロトタイプで採用した基準テンポは **55ms / 表示コマ** とする。

これは約18.18表示更新/秒に相当するが、「18fpsの連続アニメーション」を目指す仕様ではない。各更新時点で4px格子へスナップした離散表示を行うため、見た目には細かなコマ送り感を残す。

重要な原則:

- `55ms` は **Presentation の標準再生テンポ** であり、Simulation Clock の刻み幅ではない。
- Core の物理計算を55ms刻みに固定しない。
- リプレイ速度や高速観戦で Presentation cadence を変更しても、正史イベント・結果は変えない。
- 端末性能が不足した場合は表示サンプルを間引けるが、Core の進行を表示FPSへ従属させない。

## 4. 見た目

### 野手・走者

通常プレイでは守備役割による色分けを行わず、チーム所属を基本色とする。

- 投手、捕手を含む守備9人は守備チームカラー
- 打者・走者は攻撃チームカラー
- コマ内に `P / C / 1B / 2B / 3B / SS / LF / CF / RF` 等の短い識別を置ける
- 登録守備位置は識別情報であり、現在座標を固定するものではない
- チームカラーが近い場合は輪郭線、明度、形状、文字で識別を補う

主処理野手、塁カバー、中継、バックアップなどの役割は内部状態として保持する。

デバッグ表示では役割ごとの色分けを許可する。これは開発・検証用であり、本番の標準表示にはしない。

### ボール

- 野手より小さく、視認しやすい独立した点として描画する
- 白い革＋赤い縫い目を用いる（2026-09-21ユーザー指示。旧黄色指定を置き換える）
- 縫い目は各時刻の球の観測姿勢へ追従し、カメラや球種名で回転を作らない
- ゾーンのガイド線とその下地に重なる部分は球を優先する。実物体との前後関係は奥行きに従う
- 遠景は白を優先し、粒数が足りる距離で縫い目を表示する
- 姿勢入力の不足と実装境界は[白球・縫い目の描画契約](../presentation/2026-09-21-observed-baseball-surface-contract.md)を参照する
- 平面位置は正史 `(x,z)` を4px格子へ量子化する
- 大きさは正史 `y` 高度から離散的に決定する
- 直近の過去位置を **離散点** として短く残し、移動方向を読めるようにする
- 一本の滑らかなベジェ曲線や連続トレイルで軌道を捏造しない
- 接地・反発・落下は Core の正史物理をそのままサンプルする

送球も打球も同じ原則を使用する。ただし送球が高く浮けば、その正史高度に応じて同じ高さ表現が適用される。

### 走者

走者も野手と同様に正史座標から量子化する。

進塁・帰塁・挟殺で滑らかなTweenを使わず、細かいマス移動として表示する。塁到達・タッグ・フォースアウトの成立時刻はCoreの正史判定を使用する。

## 5. 球場とカメラ

打球後は真上に近い固定俯瞰を基本とする。

- 球場全体の関係が読める
- 9人守備、全走者、ボール、送球が同じ座標系に存在する
- カメラ演出のために正史位置を変更しない
- フェンス、塁、マウンド、ファウルラインは視覚的に必要な最小限の線で表す
- 背景装飾よりプレーの読みやすさを優先する
- ボールの高さは主に表示サイズ段階と必要に応じた影で伝え、平面座標を高度に応じて大きく歪めない

必要に応じた軽い拡大・縮小は許すが、移動物体を画面都合で別座標へワープさせない。

## 6. Presentation Adapter 契約

概念上は次のように分離する。

```text
Match Core
  ↓
CanonicalWorldSnapshot / TimedMatchEvent / Motion Segment
  ↓
Mini Presentation Sampler
  ├─ (x,z) → 4px Fine Grid Quantizer
  ├─ y     → Ball Height/Size Quantizer
  └─ team  → Team Color Resolver
  ↓
Drone-Art Renderer
```

Natural Baseball は同じ Core 出力に対して別レンダラを接続する。

```text
Match Core
  ├─ Mini: fine-grid drone-art renderer
  └─ Natural: continuous 3D renderer
```

Mini Renderer が以下を持つことを禁止する。

- 捕球成功を決めるロジック
- 送球先を決める守備AI
- 走者の進塁判断
- ボール軌道の再計算
- ゴロ / ライナー / フライ分類を原因にした別軌道生成
- バウンドの捏造
- アウト・セーフ判定
- 表示を自然に見せるための結果修正

## 7. ライブとリプレイ

ライブもリプレイも同じ表示契約を使う。

```text
Canonical play data
      ↓
Presentation sample time
      ↓
position / height / team-color quantization
      ↓
render
```

リプレイ専用に「それらしい動き」を生成しない。

保存済みの `PlayCapsule` / 正史イベントから再生する場合も、当時のプレー結果・捕球・送球・走塁・ボール高度・接地イベントを維持し、現在の描画コードは見た目だけを生成する。

## 8. デバッグモード

通常画面ではチームカラーを使うが、検証用に以下を切り替え可能にしてよい。

- ball handler
- base cover
- relay
- backup
- deep coverage
- hold / observe
- 正史座標と量子化後座標
- 正史 `ball.y` と表示サイズ tier
- 接地 / bounce event
- Presentation sample time
- Core event time

これにより「AI・物理は正しいのに表示がおかしい」のか、「Coreの守備判断・打球物理そのものがおかしい」のかを切り分ける。

## 9. P8実装時の受け入れ条件

この表示仕様は `P8: Mini のライブ観測表示` の正とする。

最低限、以下をテストする。

1. 基準表示で4px細密グリッドへ量子化される。
2. 通常再生の基準 cadence は55ms/表示コマである。
3. CSS/JS Tween や ease による位置補間を使用しない。
4. 同じ正史状態なら同じ表示マスへ配置される。
5. 表示 cadence を変更しても Core のイベント列と試合結果は変わらない。
6. 描画OFFでも同じ試合結果になる。
7. 野手9人・走者・ボール・送球を正史座標から表示できる。
8. 守備側と攻撃側は各チームカラーで識別でき、守備役割色はデバッグ時のみ使用する。
9. ボールの尾は過去の正史サンプルから作る離散点であり、架空の曲線を生成しない。
10. 極端な守備シフトでも登録守備位置ではなく現在の正史座標へ表示される。
11. 同じ `(x,z)` でも正史 `ball.y` が異なれば、定義された高度 tier に従ってボール表示サイズが異なる。
12. 同じ `ball.y` なら、打球がゴロ・ライナー・フライのどの統計分類であっても同じサイズ規則を使用する。
13. 地面衝突後のバウンド表示は Core の接地時刻・反発後速度に追従し、Presentation 独自のバウンドを生成しない。
14. 高いフライ、低いライナー、ゴロ、高いバウンドをラベルなしでもサイズ変化・移動・離散軌跡から区別しやすい。
15. チームカラー、ボールサイズ、影、トレイルの変更は Core の結果・イベント列へ一切影響しない。

## 10. 確定事項と調整可能事項

### 確定

- ゲームボーイ / ドローンアート系の細密グリッド表現
- 基準4pxグリッド
- 補間なし
- 滑らかさは高頻度の正史サンプルで出す
- 標準55ms/表示コマ
- 守備側・攻撃側は各チームカラーで識別する
- 守備役割色はデバッグ時のみ使用する
- ボール軌跡は離散点
- ボール表示サイズは正史高度 `ball.y` から離散的に決める
- ゴロ / ライナー / フライ分類を表示軌道の原因にしない
- バウンドは正史物理から生じる
- Coreの正史状態と表示を完全分離

### P8実装時に微調整可能

以下は設計思想を変えない範囲で視認性テストにより調整してよい。

- 野手・走者コマの実ピクセル寸法
- 地面付近のボール基準半径
- 高度 tier の閾値・半径上限
- 影 / 高度マーカーの強さ・大きさ
- 球場線の太さ
- 離散トレイルの残存点数・透明度
- 類似チームカラー時の縁取り・明度補正
- 端末サイズに対する全体スケール

これらの調整を理由に4px格子、55ms基準、非補間、正史分離、正史高度由来のボール表示という中核契約を変更しない。
