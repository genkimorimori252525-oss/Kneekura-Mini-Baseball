# 累積負荷・後続動作・通常Canvasの接続

## 所有する実行記録

`SqliteInitialJointRecoveryWorkloadStore` は、実接触前から実回復終端までの完全なTOTALを新しい記録として受け入れる。
元の予約状態から一度だけ再計算し、前の投影状態へ再加算しない。
人物・元状態・coverage・時刻・日付・評価由来を束縛し、TOTALの減少、動いた打者の負荷据置、不完全な参加者を拒否する。
旧・新ownerは共通のTOTAL計算本体を使う。所有者参照の書替えは行わない。

`SqliteJointFieldSuccessorExecutionStore` は、最新の回復記録と再評価後のworkloadを一度だけ消費する。
受理した有限指令から全50形状・保持バット・球を再構築し、疲労からSIの速度・加速度上限を導く。
完全な5形状を持つ参加者に同じ水平加速度を指示する、現在の運動学的proxyの範囲に限る。
動く選手と別選手・保持バットの間は、有限区間全体の連続した非交差を実行前に証明する。
未対応の移動バットやequipment/venueの接続を無視して実行することはしない。

両ownerはschema/index/元行/Source hashを検査する。
親の消費検査と欠落親の修復拒否は、indexだけでなくraw JSONの重複keyに隠された参照も調べる。
実行の終端では新しい負荷評価と次の権利が必要になり、旧権利へ戻って継続しない。
公式結果は、この有限区間だけでは決めない。
