# Same-PA selected-only team dispatch

`SamePlateAppearanceTeamCoverageDispatch.ts` connects nine **already accepted**
individual `defender_decision_v1` selections to `createTeamCoveragePlan`, and then
to the existing original `defender_motion_v1` Native owner. It does not change
`TeamCoverageExecutionGate` or its legacy two-role contract.

The preparation reads original SQLite field and decision proofs, verifies the
same physical launch/root/lineage, original observation references, nine original
registered defenders, and due times. It passes one selected candidate per actor
to the existing global conflict validator. Conflicting handlers or covers fail;
no selected intent is rewritten. Targets come only from the authenticated
individual decision's perception/support geometry. The request has no target or
future-world override.

Preparation has no adoption or movement credit. The caller publishes the
unchanged existing nine-selection motion Source through the original accepted
Source authority. `accept` verifies that publication against the preparation
before invoking the original owner. The owner still validates current views,
latest decisions/calibrations, identity, motor timing, body/primitive coverage,
and field progress. `read` derives an execution receipt only after reading back
the original accepted operation and matching all nine original motors to the
selected intents, targets and common actual field cut. Actual displacement and
executed coverage are reported separately; holds need not move.

The receipt always has `physicalOutsConfirmed: null` and `officialResult: null`.
Movement is not capture, custody, throw success, runner passage or an OUT.
Those remain the existing original owners' responsibilities.

## Missing full tactical selection contract

The legacy individual `DefensiveExecutionCalculation` persists only `selected`, not the
candidate set used in its calculation. Consequently this bridge proves
**selected-only team execution**, not adoption of arbitrary output from
`GeneralTeamTacticalCoordinator`, autonomous tactical prioritization, or a full
official nine-inning simulation. Those claims require three separately owned
contracts before extending this bridge:

1. An accepted individual candidate-set Source retaining original self
   perception, available evidence/cues, known geometry and calculation timing.
2. An accepted team-selection Source binding all nine candidate-set references
   and the actual global selection calculation. It must not consume canonical
   future actor coordinates as perception.
3. Per-actor selection extraction/issuance binding the chosen original candidate
   to that team-selection Source, then the existing motor and field owners.

The old gate's unsupported role results remain valid for its own contract.
They are not converted to successful execution receipts.

## Verification boundaries

`SamePlateAppearanceTeamCoverageDispatch.test.ts` covers singleton selection
preservation, nine-player identity/completeness, conflicting selections, due
times, lineage, and pre-writer Source binding. Its mocked owner tests carry no
Native execution credit.

`SamePlateAppearanceTeamCoverageNative.acceptance.ts` is a separately invoked
unmocked Source-only SQLite scenario using explicit synthetic fixture priorities
and accepted calibration declarations. It checks nine original observations and
decisions, actual grouped motor progress and independent original-store reopen.
The initial scenario exercises handler/relay/backup/deep coverage/hold. Cover
requires a separately visible, actually executed original handler commitment;
it is explicitly unexercised in this initial fixture. Full alternative-candidate
tactical integration and official scoring are unexercised as well. Evidence
can be retained via `BASEBALL_TEAM_DISPATCH_EVIDENCE` without altering earlier
fixture artifacts. A partially completed run is not Native execution proof.
