# 実接触後の時刻を保つ守備入口 V1

## 問題と変更

旧 `SourceBattedFieldMotionV3` は初期 elapsed=0 と旧打球形式を要求する。
実行済みの接触後 Source は originTick=10587305、接触 elapsed=0.46910977857333824 を持つ。
旧形式に合わせるために origin や接触時刻を丸めることはしない。

`SourceBallWorldMotionV1` は既存の `BallWorldResponseInput` を使う独立した入口である。
元の空力・地面 Source、正確な moment、材料回転位相、全 actor と材料、塁、壁、保持バットを受け取る。
既存の検索・衝突応答・反発後の離脱証明を使い、観測ごとに球の初期条件を作り直さない。
実反発が起きた場合だけ、その実衝突から新しい Source と回転位相を引き継ぐ。

守備指令は全 actor を指定し、直前の実位置と速度から開始する。
不完全・重複・未来の指令、未離脱の衝突直後に離脱証明の対象を変える再指令は拒否する。
捕球候補は停止条件であり、保持・アウト・公式記録にはしない。

保持バットは全半径形状を連続検索する。球やバットを押し出したり、接触対象から消したりしない。
V1 は静止保持のみを扱う。手を動かす・放す・落とすには別の実装と有限の実行権が必要である。
純粋な入口で渡された保持者名は保持の認証ではない。

`RecoveredBallFieldRootV1` は元の recovery 入力から物理を再計算し、制御終端への到達と全保持速度=0を確認する。
身体・手・実バットを同じ計算結果から復元し、保持者と球の caller frame を受け取らない。
旧 actor の制御期限を延長する処理ではなく、新しい有限静止指令を条件付きで用意する。
旧 `BattedWorldMotion` の共通 actor 準備処理を、旧 flight を要求せず再利用できる型に分離した。

## 実検証と限界

関連8ファイル54テスト PASS。全 src TypeScript と Native 検証ツールの strict 型検査 PASS。
実行記録の Native 読取は、通常 owner により元の依存関係を再構築する。
実回復終端 elapsed=0.546911 から1.546911まで、50 actor と実バットを保持し、地面接触を含む継続を確認した。
全78テーブルの schema/全行と main/WAL の内容は変更していない。
実記録は `outputs/verification-authored-with-bat-recovered-field-root-v1` ～ `v3` に保存する。

この検証で追加した接触材料は明示された synthetic fixture である。
範囲は元の actor・実保持バット・地面で、正式球場の壁・塁との接続は未検証である。
9人への連続指令は純粋計算の synthetic テストであり、9人の知覚・判断・捕球・送球の Native 完走ではない。
新入口は Native 授権を与えず、`motionIssued=false` の条件付き計算にとどまる。

次の実行には、接触前から recovery までの新しい累積 TOTAL を元の reserved state から再評価し、
最新 recovery に結び付く後続実行権、正式材料・球場、知覚遅延を持つ守備指令を接続する必要がある。
前の累積負荷を再利用して追加動作を認めることはしない。
通常 HTML、選手の実態 SI、混合9回、100試合以上、実機スマホの未検証状態は変わらない。

## 原失敗を保持

最初の新テストは previousContacts の欠落により、反発直後を同時刻の新規衝突として検出して失敗した。
直前の接触を引き継ぐ修正を行い、閾値・時計・位置は変更していない。
型検査では actor 型の推論と glove リテラルの拡大を修正した。全 FAIL receipt を保存する。
v1/v2 の Native helper は実データ上1秒先へ到達したが、途中停止を明示的に拒否する条件が不足していた。
v3 では指定時刻・tick の一致、非停止、終端 world、実地面接触を合格条件に追加した。
