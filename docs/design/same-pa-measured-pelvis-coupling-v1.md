# 実測バットと腰位置の連動

2026-10-16。OpenBiomechanicsのみを使用する。身体の表示・フォーム描画は追加しない。

## 元の干渉の確認

前工程の全区間検査は、実測バットと固定した胴体球との干渉で拒否された。同じ打撃試行・同じ原時刻の左右股関節中心を公開データから取り出すと、12軌道の原標本すべてで、腰の中点とバットの最大半径カプセルの隙間は正だった。固定された汎用姿勢と実測軌道との位置関係が一致していなかった。

腰の中点は重心の測定値ではない。今回の処理は、既存の粗い身体球を配置するための明示的な参照であり、筋力、姿勢の力学的安定、床反力や身体の実行能力を証明しない。

## 原データの選抜

`tools/browser-bridge/import-openbiomechanics-pelvis.py` が、保存済みの `hitting_landmarks.zip` から `session_swing`, `time`, `left_hip_*`, `right_hip_*` だけを選ぶ。

- 既存の12打撃軌道と原文字列の時刻で完全一致して結合する。近傍時刻への付け替えはしない。
- 同じ行の手元・芯を含む原バット観測も照合する。欠損、重複、非有限座標は拒否する。
- 1644個の原キーを保持し、既存と同じ正則な世界座標変換 `(元Y,元Z,元X)` を適用する。左右反転や長さ調整はしない。
- zip、内部CSV、元のバットデータのSHAと、原股関節の文字列を記録する。

生成データは `docs/demos/measured-batter-pelvis-v1.json`。本データの登録だけでNativeの人物・制御への採用権は発生しない。

## Coreの接続

`MeasuredPelvisControlV1` は、元の股関節中点を、バットと同じ開始時刻・再生倍率・水平剛体変換で読む。待機から最初の原位置・速度へはC1で接続する。原標本間の線形補間と速度の不連続は、未測定の補間として明記する。期限外へ外挿せず、終端の静止を創作しない。

`createCoupledHeldMeasuredBatBodyControlV1` は、既存の胴体球1個を同じ半径のままこの連続位置へ置き換える。初期位置と選択した元の胴体球が一致し、バットと原キー・試行・変換・時計が一致することを要求する。他の障害物は残し、元の足の制御も保持する。

速度の上界を使い、バット対全障害物、動く胴体対全障害物・地面・保持手、手の到達範囲、両足への最大脚到達範囲を連続区間で証明する。標本点だけが通ることを合格理由にしない。初期保持、元の半径、到達上限、バットの原キーを緩めない。返却した速度を外部で変更しても将来のサンプルは変わらない。

## 現在の証拠と限界

`verification-authored-with-bat-coupled-pelvis-v4` は、元のNative ownerで現在のSWING判断、バット準備、人物の身体を再認証してから、新しい連動計算を行った研究用生成物である。元DB本体と永続WAL内容は不変。

元の固定胴体での全区間拒否を再確認し、同じ137バットキーと同じ49障害物を保った連動計算ではtick11134216まで通った。これは待機→実測区間の終端直前まで約0.487秒。手の到達範囲上界1.088528mは元の1.1m以内、芯速度上界25.934829m/sは元の50m/s以内。腰位置の速度上界は3.532615m/s。

身体速度の上限5m/sは明示した研究用の合成値で、本人の実測能力評価や地上走力からの換算ではない。身体参照はまだNativeの所有データとして登録していない。`bodyReferenceOwned:false`, `physicalExecutionAdmitted:false`, `motionIssued:false` を保持する。

関連Core75件、全src型検査、検証ツールstrict型検査を実行した。最初のテストは全clipへ同じ終了時刻を当てて拒否されたため、原キーごとの実際の終了時刻へ修正した。最初の研究helperは保存archiveとownerの返す身体receiptを取り違えたhash照合で失敗し、元ownerから読む形へ修正した。型検査の `scale:number` 対 `scale:1` の失敗も保持する。
