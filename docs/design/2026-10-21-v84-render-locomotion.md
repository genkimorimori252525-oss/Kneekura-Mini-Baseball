# v84 描画と接地移動

承認範囲は全体の目標描画頻度2倍、空間サンプル密度の縦横1.2倍、live試合の加速・制動・切返し置換。通常試合、カメラ調整室、選手メーカーに同じPresentation設定を渡す。v83のHR後1750ms見送りとv82のメーカー復帰操作を継承する。

## 描画

| 状況 | 通常周期 | 目標頻度 |
| --- | --- | --- |
| 通常シーン | `55 / 6 ms` | 約109.1 Hz |
| 自由な投球 | 通常周期の`1 / 2.5` | 約272.7 Hz |
| 自由な打球 | 通常周期の`1 / 2` | 約218.2 Hz |

単一RAFでシーン全体を描く。ボールだけ別時刻の画像を重ねない。投球・打球の倍率は重ね掛けせず、保持球・送球・準備は通常周期。実際の提出頻度は画面、RAF、CPU、画面合成に制約され、上の値を実測FPSと呼ばない。保存されたCore frameの間を物理外挿して新しい接触や保持を作らない。表示時計の更新回数と異なる保存tickの観測回数も分けて計測する。

`KneekuraPresentationControlsV84.configure({frequencyScale:2,qualityScale:1.2})` と `inspect()` を3成果物で共通利用する。調整室のA/Bも同じ試合時計を使う。メーカーは設定を子rendererへ渡し、試投・打球のSourceを変更しない。

画質は論理600×432・backing1200×864・構図を維持し、4px格子を`4 / qualityScale`へ細分化する。整数セル番号から座標を求め、地面・壁・PNG・バット・球・深度・遮蔽を同じ格子で扱う。原画・色・SI寸法・球表示倍率は変えない。格子範囲は最大256件のimmutable cacheを使い、品質変更で失効する。品質1.0は旧描画を再現する。これは人間承認によるv81の4px固定規約への明示的な例外であり、以後の性能改善が勝手に細部を減らす許可ではない。

既存の走行2画像を、観測したactor位置の累積距離で切り替える。現在1recordだけをcacheし、停止時や逆seekで未観測の未来位置を使わない。1.4m/poseは表示用の未校正係数で、全身骨格の実測再現を意味しない。

## live移動

`LiveLocomotionV84.ts` の少数速度帯の解析を共有する。推進は既存能力`a`を上限に、最高速度の0–25%は`a`、25–65%は`.7a`、65–100%は`.35a`。既定制動は`1.8a`、野手の横踏ん張りは`a`。明示された走者制動・横加速度・旋回半径・技術補正は保持する。新しい公開能力を増やさない。

野手は大きな方向転換で先に踏ん張って減速し、推進・制動・横方向が一つの加速度budgetを共有する。区間内停止は`stopAfter`で表し、位置や速度をリセットしない。回避とフェンス停止も同じ制動距離を使う。旧Native/hostの `DefenderMotion` と証拠契約は変更しない。

走者は既存の塁を回る経路と触塁diskを保持し、経路上の速度計画だけを置換する。直線legの予測と実触塁時間は同じ解析計画から求める。野手ETAは同速度帯・制動を使う軽量な戦術近似であり、回避込みの実軌道や到着証明ではない。到達予測からOUT/SAFEを作らず、実接触・保持・触塁のみを裁定へ渡す。

係数は左右支持を平均化したゲーム制御であり、実測校正済みの生体力学モデルではない。研究の方向性と旧実装の問題は先行AMENDMENTに記載した。
