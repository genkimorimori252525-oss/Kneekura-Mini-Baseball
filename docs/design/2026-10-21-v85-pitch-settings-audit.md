# 投球設定の監査とメーカー解説 v85

2026-10-21。基準はv84のauthoring Core `89c78290…` と通常renderer `b68c9541…`。v85はメーカーの説明・表示操作のみを変更し、Core、実数値、保存形式、通常試合を保持する。

## 設定の十分性

一般的な球種を設計する入口は概ね揃っている。項目を増やす前に、回転数・回り方・縫い目・比較基準の意味を区別できる説明が必要だった。

| 要素 | 現行で扱うもの | 限界 |
| --- | --- | --- |
| 球速 | 初速、公開最高球速、既存の98〜100%の球速ばらつき | 個別の球速ばらつき幅の設定はない |
| 回転 | rpm、回転による押す向き、符号付きジャイロ成分 | 回転効率は独立した自由入力にせず回転から導く。実進行方向と設定基準は区別する |
| 再現性 | 回転数の最低維持率、制球、seed | 回転軸・縫い目姿勢・放す位置の個別ばらつきと誤差間の相関は未対応 |
| リリース | 高さ、腕側の幅、本塁への伸び、投球動作の設定例 | 球種別のリリース差は未対応。フォームは作者モデル |
| 縫い目 | 有効化、作用倍率、初期姿勢3角、姿勢の時間変化 | 48点の縫い目を使う作者近似。実在SSWの定量校正は未完 |

未対応要素は今後の設計候補として記録する。今回、新たな公開能力や空力設定は追加しない。「現実の投球を完全再現できる」とは扱わない。

## 回転の説明で守る区別

回転数は回る速さ、回転軸は回り方。バックスピンは比較球より落ちにくくし、トップスピンや横回転もマグヌス力に寄与する。「回転効率＝バックスピンだけの割合」「効率が高ければ全ての球種で強い」は不正確である。[Young・Nathanの回転比率の説明](https://baseball.physics.illinois.edu/ActiveSpin-v3.pdf)、[MLB用語集](https://www.mlb.com/glossary/statcast/active-spin)を参照した。

`LivePitchAuthoringV77.ts` の `gyroFraction` は固定world z成分を全回転で割った設定値で、横成分の設定目安は `sqrt(1-g²)`。g=.6なら目安80%、2400rpm中1920rpmとなる。±はねじれの向きで、左右の変化の指定ではない。

実投球は斜めに進み、Core空力は相対風速へ再分解する。そのためUIで算出する比率は「設定時の目安」であり、実測Active Spin率や実投球の厳密な効率と表示しない。既存trial metricsに正確な比率は公開されていない。v85の `spinGuide()` は表示専用でCoreに値を戻さない。

縫い目による後流の偏りは実験でも研究されているが、実験の測定値とゲームの作者係数は別物。[Utah State Universityの実験資料](https://digitalcommons.usu.edu/all_datasets/191/)を参照。作用1倍はこのゲームの基準で、実測SSWと一致する保証ではない。2倍の係数も、最終変化量が必ず2倍という意味ではない。

## 比較線

灰の比較球は実球と同じ位置・初速度・初期縫い目設定で、spinだけを0へ置き換える。縫い目ONなら比較球にもその空力が残る。実球の縫い目は回転し、灰球は回転しないので、両者の縫い目力の履歴は異なる。この差を純粋なマグヌス効果だけの差と説明しない。

v85は1つのOFF/ONで、6方向の軌道図の灰線・灰端点、本塁図の灰点を切り替える。初期OFF。domain/scaleは比較球を常に含めたまま保持し、ON/OFFで緑の実投球の見え方が拡大・縮小しない。Core trial、比較に基づく数値、roster、保存JSONは不変。

OFFでも変化量の数値に比較球を使用するため、比較球の物理計算を省略する変更ではない。

## 小数点を切り捨てない理由

JavaScriptの `Number` はbinary64で、表示上の小数桁数によって保存サイズが変わるものではない。[MDN Number仕様の説明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number#number_encoding)を確認した。切捨ててもRK4の段数、空力評価や衝突探索の回数は減らず、切捨て処理が追加される。

位置をm単位の小数1桁へ切り捨てると10cm刻みになる。球の直径約7.32cmより粗く、短い積分での移動・回転・接触を損なう。rpm、角度、時間など異なる単位へ同じ桁数規則を当てることも適切でない。

今回、解説の目安だけを小数1桁で整形する。入力・確定値・JSON・物理計算には戻さない。縫い目有効時の積分や複数試投は負荷候補だが、この監査で性能の主因を実測したわけではない。v84で残った描画のCPU負荷とも区別する。

## 解説UIと検証

既存の明るい配色・主操作・バット軌道画面を継承。投手のプレビュー下の余白と、選手能力の横へ説明を配置。バットの現行タブと保管庫にも説明を置く。見出し切替、キーボード、フォーカスによる関連説明、スマホ表示を扱う。既存の1秒hover/?の説明も維持する。

最終Source/hash、ブラウザーでのOFF/ON/復帰、未保存入力・小数精度・JSON・既存削除復帰の検証は `docs/verification/releases/v85/README.md` を参照。旧v82/v84、元CharterHOLD、旧FAIL/UNKNOWN、Native認証・100試合・実機、v84全場面実FPS2倍未達を保持する。
