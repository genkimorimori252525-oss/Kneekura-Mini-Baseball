# 球場設計室 v2 — 赤・青・金の開閉式ドーム

2026-10-24 JST / `MB-20261024-BALLPARK-STUDIO-2`。

根拠: 本人の直接指示「このイメージを球場設計室でデザインして再現」「既存の描画法と内野の配置は維持」「赤・青・金の観客席と開閉式の屋根、ライト105m・センター128m、低いフェンス」。直前に承認された生成画像2枚を意匠の手渡しとする。定員120,000人は前turnの本人指定。外観/意匠実装はこの明示指示の範囲であり、別のart directionへ変更しない。

## 判断・影響・復旧

- 球場設計室だけをv2へ拡張。凍結V114、設計室v1、通常試合、メーカー、他chatのV115 src/dist/CURRENTを変更しない。
- 既存rendererの投影・4px格子・dot・深度bufferを利用。生成画像の貼付や別WebGL rendererへの変更はしない。立体観客席・金の通路/トラス・狼の幾何意匠・銀色の可動屋根を座標データとして生成する。
- 右翼105m・中堅128m。未指定の左翼は暫定105m、低いフェンスは暫定1.3m。左中間/右中間と追加点はこの寸法をつなぐ滑らかな外周の初期案。数値は編集可能。
- 内野の固定データは一切変更しない。定員120,000は設計上の定員であり、12万個のactorを生成しない。階層席の光点が観客群を代表する。
- v2 schemaに任意の建築設定を追加し、旧v1設計JSONも読み込む。旧v1保存領域を上書きしない。現在の基準円形へ戻す、preset再適用、取消/やり直し、JSON入出力を維持。
- 屋根開度0〜100%。観客席を含む全景カメラを追加し、既存5視点は保持。断面表示は表示だけの省略であり屋根自体の開度・球場寸法を変えない。
- 円形Coreへの非対称形状接続は今回も未実装。壁高1.3mだけでHRキャッチ成立を保証する処理は足さない。
- 検査中、既存park cacheのkeyに独自外周が含まれていないことを確認。同じ視点で編集を続けても表示が古くならないよう、コピー内のcache keyへ外周と建築のidentityを追加する。
- 復旧はv1または元V114を開く。新規v2成果物とJSONは別名。ソース変更は専用tools/docs内に限定。

## 検証

1. geometry/建築schema・旧JSON互換・内野保護・不正値拒否をunitで確認。
2. 屋根開閉の実座標、観客席の外野侵入なし、座標有限、上限・プリミティブ数・キャッシュの条件を確認。
3. v2 buildで元V114/内包Core不変・コピーrendererだけの変更と入力SHAを確認。
4. 実Chromeで寸法/固定内野、色/開閉/断面、同じcameraで複数回編集、保存/取消/旧JSON読込、PC/スマホ幅・全視点・idleなしを確認。元rendererの基準画素比較も継続。
5. 実際の画像を見て構図・遮蔽・色を確認。結果を専用CURRENT/証拠へ記録し、既存PRへ判断記録を追記する。
