# ロゴ・観客の表示調整

ロゴの設定は維持。観客は本人の最新指示により [群衆タイル方式](README-crowd-tiles.md) へ変更した。以下の「観客を間引く」「身体サイズ」「4,321群」は旧方式の履歴であり現在の表示ではない。現在の密度はLEDの量で、満員の群衆背景は消さない。

2026-10-24 / MB-20261024-BALLPARK-VISUAL-TUNING。

現在の `outputs/球場設計室_v3_局所密度版.html` を再読み込みする。「芝生のオオカミと描画密度」に細かさ2〜8倍、明るさ0.5〜3倍、光り方0〜100%を追加。初期値は6倍/明るさ1.7倍/光り方30%。輪郭近傍だけ芝生と同じ点格子で描き、発光も元のdot primitiveに適用する。広い矩形patchやロゴの線overlayは使わない。

「観客の見え方」で表示密度5〜100%、描き込み（光だけ/簡素/詳しく）、身体の大きさ50〜180%、LED明るさ20〜150%を変更できる。初期密度25%では代表観客群4,321（以前17,280）。定員12万人は変えない。間引き対象は固定seedで選び、動作の各コマで観客が増減しない。

LEDの棒は手元から先端まで常に0.07m。手は身体近くの弧で動き、棒だけが人より長くならない。身体サイズを変えても棒は7cm。遠景ではnative格子の光点で発光を示すため、物理サイズ以下を画像上で正確に測れるわけではないが、長い棒へ引き伸ばす処理はない。「簡素」は身体1点とLED1点、「詳しく」は頭と実寸の短い棒を追加、「光だけ」はLEDのみ。

通常の動作は2コマ動作2周→3コマ動作1周で7コマ。左右→左右→左中右（pose 0,2,0,2,0,1,2）を繰り返す。動作ループ選択で従来の2コマのみ/3コマのみも利用可能。安打等の反応速度、停止、背景停止、reduced-motion、最大3枚の画像再利用は維持する。

明るさ/発光はoptionalな `architecture.logo.brightness/glow`、観客設定はoptionalな `architecture.crowd` に保存。JSON保存・ブラウザ保存・取消/やり直しに対応。旧JSONにない値は表示時の既定値を使い、勝手に追記しない。旧JSONの細分倍率や明るさ設定を強制変更しないため、新しい初期例を見るには「赤・青・金のドームに戻す」を使う。既存の設計は先にJSON保存できる。

新しい初期JSONは `examples/russian-dome-v3-tuned.json`、持出し用 `outputs/球場構想_v1/球場設計_ドーム_v3_応援調整.json`。変更前HTMLは `outputs/球場設計室_v3_観客ロゴ調整前.html`。通常試合への新球場/イベント連動は依然未接続。

屋根の検査はカメラ位置に注意。俯瞰はy=100mで屋根y=105.88mの下にあるので、閉じた屋根でも内部が見える。屋根外側からの遮蔽は球場全景（eye.y=260m）で検証する。最大発光での遮蔽検査と独立ray-triangle検査はこの条件でPASS。内側でロゴが見えることを光漏れと誤認しない。
