# 観客とLEDペンライト

履歴仕様。現在の見え方・7cm LED・7コマの動作は [README-visual-tuning.md](README-visual-tuning.md) を優先する。以下の初期17,280群/旧3コマループは現在の初期設定ではない。

2026-10-24 / MB-20261024-BALLPARK-CROWD。

`outputs/球場設計室_v3_局所密度版.html` を開く。プレビュー下の「観客」「動かす」「コマ数」で表示/停止/2〜3コマを選択し、安打・本塁打・アウト・失策のボタンで反応を確認する。初期値は3コマで常時再生。端末で動きを減らす設定が有効な場合は初期停止し、本人が「動かす」で再開できる。

タンボフは球場テーマの赤・青をLED色として使用。観客群ごとに振り方の位相をずらす。色を変えた場合は応援色も更新。定員12万人をactorとして動かさず、既存の17,280個の代表点に身体・頭・ペンライトを同じ投影/光点/深度で描く。実在する12万人の個別挙動や群衆シミュレーションではない。

| 反応 | コマ間隔 | 継続時間 |
|---|---:|---:|
| 通常 | 400ms | 常時 |
| 安打 | 95ms | 2.4秒 |
| 本塁打 | 80ms | 4.5秒 |
| アウト | 140ms | 1.4秒 |
| 失策 | 120ms | 1.8秒 |

これは初期の演出値で、物理/公式判定の時刻ではない。同じコマを速く切り替える。反応終了後は通常へ戻る。本塁打反応は低優先のアウト等で上書きしない。停止/背景では反応時計も停止し、復帰時に再開する。

## 開発と試合接続の境界

`crowd.mjs` の `createCrowdPlayback()` は単調時計と観測イベントのみを使う。`crowdSymbol()` は任意のチーム色配列でworld-spaceの身体/ペン先を作り、stadium-meshがnative格子と深度で描画する。球場/設計のJSON形式は変更していない。コマ数・再生状態・反応は一時的なプレビュー設定であり、設計JSONには保存しない。

```js
BallparkStudio.setCrowdPlayback({paused:false,frames:3,visible:true});
BallparkStudio.reactCrowd({type:'hit',id:'game-42-play-18-hit'});
BallparkStudio.inspect().crowd;
```

IDは直近64件を重複抑止する。実際の試合では公式に安打/失策/アウトが確定した観測イベントから送る。バット接触だけで安打とみなさない。新球場自体は通常試合へ未導入のため、今回は通常試合の結果からの自動反応も未接続。相手側応援区画や攻守での歓声/落胆の出し分けも未接続。

静止した設計室ではカメラ/設計/コマ数の変更時だけ最大3枚のsceneを生成する。通常再生/反応はその画像を切替えるだけ。1200×864 RGBA換算で3枚12,441,600 bytes、2枚8,294,400 bytes（canvas内部の追加領域は含まない）。旧cacheは置換して解放対象にする。非表示/停止/旧球場でtimerを停止。**通常試合へこの静止scene cacheをコピーして球や選手を凍結させない。試合は動的worldを描画しつつ、crowd clock/symbolを再利用する。**

再現コマンド: `node --test tools/ballpark-studio/crowd.test.mjs`、`node tools/ballpark-studio/check-crowd.mjs <unique-label>`。詳細receiptはCURRENT-crowd。端末別のFPS向上は計測していない。
