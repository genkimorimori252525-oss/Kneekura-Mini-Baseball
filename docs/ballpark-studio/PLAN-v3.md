# 局所密度と地面素材の共通描画

2026-10-24 JST / MB-20261024-BALLPARK-STUDIO-3。

本人の直接指示: 点が集まる画面へロゴだけ線で上書きする方式を修正し、ロゴの周囲の点も細かくする。今後も同じ方式を利用しやすい開発環境を残す。

対象は球場設計室のコピーrendererだけ。v2 HTMLは比較用に保存し、別名v3を生成する。右翼105m・中堅128m、低い壁、内野席張出し、加工した金色狼、元の内野/PNG、屋根開閉を維持する。

## 接続

1. 芝生と狼画像を先に同じ地面素材へ合成する。矩形pixel/線のロゴ専用overlayは撤去。
2. 最新指示に従い、密度領域は画像の可視alphaマスクからの距離＋最小余白で定義する。外接矩形をそのまま細分化しない。初期値は3倍密度、輪郭余白0.6m、移行0.8m。密度・余白・移行幅を編集可能にする。
3. 通常領域は元の光点と格子をそのまま使用。局所領域では同じdot primitiveを細分格子と比例半径で使い、芝生も狼も同じ光点で描く。マーク/選手/屋根は従来の順序・遮蔽を維持。
4. 素材値・密度設定をpark cache keyへ含める。APIから領域・倍率・光点数・素材の状態を確認できるようにする。
5. 共通surface-layer moduleと専用AGENTS/利用資料・実Chrome計測/比較画像を残す。通常試合Coreへの接続は今回も未実装。

## 検証/復旧

密度の連続性と範囲、通常領域同値、芝生/ロゴの同一sample、細分光点の半径と格子をunitで確認。実Chromeでは境界、素材/密度変更のcache更新、屋根による遮蔽、内野不変、旧JSON/保存/履歴/PCスマホ幅、基準画素一致を確認。実画像も目視する。v1/v2/元V114はSHA読戻し。復旧は元ファイルを開く。原FAIL/不採用案と未接続境界は保持する。
