# 球場設計室 v1

2026-10-24 JST / MB-20261024-BALLPARK-STUDIO-1。

本人の依頼は、現在の描画を維持して球場を長期間設計できる環境の作成。塁や白線の配置は固定し、現実の規則に照らして変更できる球場差を編集する。2026-09-20の将来計画は参考で、今回の直接指示が環境作成の根拠。通常の判断は本人の共通委任に従い、この文書へ記録する。

## 対象と境界

- 専用HTML「球場設計室_v1」。最新の確認済みV114から通常試合の既存描画エンジン・原画・4px表現・色・カメラを再利用する。
- 変更前の球場を初期値とし、基準表示は元rendererと同一画素で比較する。既存の通常HTMLを変更しない。
- 左翼/左中間/中堅/右中間/右翼の距離・各位置の壁高、追加の壁頂点、外周/バックネット位置、外野の土の幅を設計。塁・本塁・投手板・打席・固定白線は編集不可。外野のファウル線は固定方向を維持し、終点だけ外周に追従する。
- 人間向けの図/入力、取消/やり直し/初期値/保存、JSON入出力、AI向けの検証結果/CLI/APIを設ける。未確定のエラーがある間は最後の有効プレビューを保持し、保存成功を偽装しない。
- 設計モデルはバージョン付きの独立データ。円形だけの現行Match Coreへ非対称の壁を無理に変換しない。通常試合への反映/壁衝突/守備経路/HR裁定の接続は別の共有契約変更として明示し、今回の設計プレビューを「試合実装済み」と呼ばない。
- 通常試合で守備・走塁を実装中の別chatがあるため、src、メーカー、既存renderer helper、dist、V115生成物、CURRENTの進行中taskを変更しない。専用tools/ballpark-studio と docs/ballpark-studio が所有範囲。共通CCGには固有task-IDの検証receiptだけを追記し、専用CURRENTで継続状態を保存する。

## 規則と設計判断

根拠: [MLB 2026 Official Baseball Rules](https://mktg.mlbstatic.com/mlb/official-information/2026-official-baseball-rules.pdf) Rule2.01–2.04と付図。MLB公式Rulesページからリンク確認済み。

- 固定寸法: 90ftの正方形、投手板前縁まで60ft6in、本塁の形、打席/コーチ箱等。2026の18inベースの置き方も既存rendererの共通固定形状を保持する。
- 一般基準のfair領域内の障害物距離250ft以上と、推奨値を区別する。新設MLB球場の両翼325ft/中堅400ftという追加条件は別の検証モード。既存球場の例外を一律に禁止しない。
- フェンス高に、この条項由来の一律固定値は置かない。作業環境の数値上限は描画/計算上の安全限界としてルール上限と区別する。
- 芝と土の形は自由部分もあるが、MLB内野土の外周などには追加制約がある。今回はその内野部分を固定し、外野土幅のみ表示設計対象とする。
- 距離は点だけでなく、点間の直線壁の最短距離も検査する。回転による内野移動、塁間変更、ファウル線の角度変更をJSONからも受け付けない。
- 円形基準は元の暫定球場そのものとして保存し、新設MLB基準に満たない場合は表示する。現行の見た目を、ルール値へ勝手に変えて隠さない。

## 実装と検証

1. 純粋なgeometry/modelと検証、固定部分を保護するtests、AI用CLI。
2. 元HTMLをSHA固定し、設計室に内包するコピーだけへ外周queryを追加。元の円形表示経路は維持。立体壁と地面の端は同じgeometryを参照する。
3. 編集UI/設計図/既存rendererプレビュー/人間AIモード/履歴/保存。静止プレビューは操作時だけ再描画する。
4. 寸法/違法入力/線分/高さ/履歴/JSON復帰、PC/スマホ実Chrome、基準画素一致、固定部分不変、元V114ファイル不変を検証。

復旧: 新設計室を閉じて元のV114を開く。元入力/成果物/過去FAIL/BLOCKED/UNKNOWNを保持。新依存・他agent・本番移行・既存データmigrationは不要。
